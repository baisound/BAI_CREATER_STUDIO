# v0.12.9 Critic 3回・Judge 1回（機能優先開発レビュー）

## 判定対象と前提
v0.12.8からの変更を対象とする。ユーザーの「機能とUI優先」に従い、既存のセキュリティ検証を後続へ回すが、元ファイルや素材の保全・登録経路の最低限の安全性は保持する。製品の全機能が完成したと推定しない。

## Critic 1 — 発見性・導線
**修正した点**：統合素材タブ最上部に「①ファイルを追加 → ②素材選択 → 3D表示・再生・停止」を集約。GLB/VRMの未実装だった新規登録入口を追加。登録成功後に素材選択まで自動更新。
**課題**：FBX/PMX/VMDとGLB/VRMを含む全形式の共通素材管理はまだ完了していない。タブ全体の抜本統合は未了。

## Critic 2 — 操作到達性・スクロール
**修正した点**：主要パネルの高さを管理し、右側のアクション一覧と詳細をスクロール可能にする明示的なルールを追加。狭い幅では縦配置へ切替。GLB/VRMプレビューを一覧より先に表示。
**課題**：CSSの古い互換指定が多数残る。実ブラウザでの1366x768/1920x1080/小型ウィンドウの到達性テストは未実施。

## Critic 3 — 機能連携と既存データ
**確認した点**：ローカルHTTPでカタログ取得、GLB登録、登録後のカタログ件数増加、ファイル再取得を確認。Python/JavaScript構文検査成功。GLB/VRMと元の37件FBX、既存VRM、PMXなどの素材を保持。
**課題**：転写とPMX/VMD再生は実ブラウザで未検証。WebMCP/標準MCPに新アップロード専用ツールはまだない（ブラウザ標準のローカルファイル選択操作は動作）。保存・復元の実UIシナリオは未検証。

## 最終Judge
**判定：機能開発プレビューとして条件付き受け入れ、製品リリースは不合格**。
理由：GLB/VRM素材の登録入口ができ、最低限の登録API実動作を確認した。しかし全形式の一元管理、画面実機テスト、編集・保存のE2E、全ツールのWebMCP/標準MCP整合を未達とする。ソースの静的検査だけでUXを合格にしない。

## 次の完了条件
1. 素材管理をFBX/GLB/VRM/PMX/VMDの単一データ体系とタブへ再編。
2. 実ブラウザで登録→モデル選択→全身表示→再生・停止→自動保存→再起動→復元を検証。
3. 1366×768、1920×1080、狭いウィンドウで操作不能箇所ゼロ。
4. GLB/VRM登録と再生をWebMCP・標準MCP経路から呼び出す機能テストを追加。
5. これまで正常確認済みの接地・コンビネーション・お気に入りの回帰テスト。
