# v0.14.0 実装／Critic×3／Judge

## 実装1 → Critic1：機能発見性
- 中央ワークスペース冒頭に、FBX/GLB/VRM/PMX ZIP/VMD共通のファイル追加UIを追加。
- 形式に応じて既存の登録処理を呼び出す。PMX ZIPはA/B登録先を指定。
- Critic1：既存UI間の遷移負担が改善。一方、保存APIのデータモデル統一は未達。新UIはアダプター方式。

## 実装2 → Critic2：スクロール／操作
- 過去の競合する追加CSSレイアウト指定を整理、レイアウトを単一スタイル定義で管理。
- コンビネーション上部操作バー、中央のスクロール一覧、折りたたみ詳細設定を独立。
- Critic2：静的レイアウトコードは整理。1366x768/1920x1080のブラウザ実画像テストは管理ポリシーでブラウザナビゲーションがブロックされ未完了。

## 実装3 → Critic3：登録結果／保存
- 共通ファイル欄の選択状態・形式を説明し、登録中／失敗／既存画面への受け渡しを表示。
- 元のFBX/GLB/VRM/PMX ZIP/VMD保存処理は削除せず利用。既存素材とGit履歴を保持。
- Critic3：UIアダプター部分は追加済み、完全な登録成功・3D描画・自動復元はE2E未検証。GLB/VRM登録後の成功表示は既存結果UIに依存。

## Judge
判定：**開発用の改修として受理／製品合格は保留（実機検証が必要）**。

理由：入口統合とCSSの整理は前進したが、バックエンドの素材登録は形式別であり、WebMCP・標準MCPの新共通入口は未実装。Chromiumの `ERR_BLOCKED_BY_ADMINISTRATOR` により実画面テストが実施できない。登録→再生→停止→再起動後復元のE2E確認も完了していないため、最終的な使いやすさや機能の正常性は未保証。

### 次回必須項目
1. サーバーに統一素材APIと型付き素材台帳を実装し、UI/WebMCP/標準MCPの3経路で共通化。
2. 実Windows/Linuxブラウザでアップロード、再生、停止、保存・復元を検証。
3. レスポンシブ画面で全操作ボタンに到達できるかをスクリーンショット・自動テストで確認。
4. 登録中から登録完了までを画面内で一貫したステータスとして表示。
