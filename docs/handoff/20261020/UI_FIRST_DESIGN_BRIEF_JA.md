# P1 UI先行 — デザイン・挙動仕様

## UX原則
1. **制作デスクトップアプリのワークスペース**に見えること。一般的なSaaSウェブ管理ダッシュボードやカード大量羅列にしない。
2. 3Dビュー/タイムライン/インスペクタ/アセットパネルは必要なとき適切な密度。パネルのタブ切り替え・内部スクロール・固定操作領域・ツールチップ。
3. **画像は構成・情報のリファレンスのみ**。青紫グラデーション、ネオン光彩、ギラギラしたAI風UIは採用しない。
4. 配色提案は：温かみのあるグレー/チャコール・穏やかなオフホワイト・抑えた墨色・必要最小限の深緑またはブラス系アクセント。色は意味ある状態表示のみ。
5. 市販の編集ソフトの使い勝手を研究する：Blender、DaVinci Resolve、Unreal Editor、Adobe系、Figma等の良い点（画面の密度/ナビ/階層）。**外観の丸写し不可**。まず2種類の小規模デザイン比較をして一つ採用。
6. 色の対比・キーボード移動・フォーカスリング・文字サイズ・スクロール・小画面対応を必ず設計。

## 25画面モックのインタラクション契約
- 25独立ルート（`/workspace/01`〜`/workspace/25`等）、画面IDを固定、直接URLアクセス・再読み込みでも同じ画面が開く。
- サイドバーの押下で該当ページへ遷移、現在位置をハイライト、パンくず/戻る/進むが動作。
- タブ、ドロップダウン、モーダル、検索、フィルター、ソート、数値コントロール、フォームのバリデーション、閉じる・取り消し、保存の反応がある。
- **モック動作**なら `サンプル表示` を明示し、設定をUIローカル状態で切替。外部処理・実GPU処理が未実装なら押下して `◇ 未実装：説明` とする。偽の成功を出さない。
- 既存機能が接続できた場合は `実機能` と区分し、既存APIサービスを通す。
- P1はフル機能の再実装ではない。全25画面の導線確認をゴールとする。
- HMRでコード変更を再読込、Python側も監視起動。ただし再読込時に未保存編集が失われる点を注意書きする。

## 技術実装の選択基準
- `package.json`を**必ず先に読む**。TypeScriptが既にあるなら採用。なければVite+TSを無理に巨大移行せず、独立したUIシェルから段階導入。
- 具体候補：Vue 3 + TypeScript + Vite、または既存React採用済みならReact + TypeScript。ルーティング、アイコン、アクセシブルなヘッドレスコンポーネント、ドッキング/分割パネルを用途で選定。Tailwind等も**既存スタックと衝突しない場合のみ**。
- `tsc --noEmit`/ビルド/Playwright等のブラウザ遷移テストを検討し実際に実行。既存のPython・JSテストも維持。

## 画面操作受け入れテスト
25メニュー全遷移、各画面の戻る/進む/直URL、代表タブ、代表ダイアログ、未実装表示、画面崩れ、HMR、既存Python起動・API応答、MCP非回帰をチェックする。スクリーンショットの合否を外観の一致のみで判断しない。
