# リップシンク・表情・BGM配置 要求仕様（A1・草案）

状態: 仕様草案。実装・動作確認の証拠ではない。対象は `LIP-001`〜`004`、`LIP-009` と、2026-10-20 に同段階での実装が承認された歌音声の配置。BGM の管理 ID は未決 `O-LIP-01`。`LIP-005`〜`008`・`010`・`011` と EQ／ミキサー／効果音編集（新UIの候補表示）は含めない。

## 目的・依存

VRM/PMX の歌唱映像で、歌音声を映像時刻へ配置し、字幕または歌声から口形を作り、表情・既存 VMD のモーフと矛盾なく再生する。音声解析が使えなくても手でキーを打って完成できる。`DATA-008`〜`010` の保存・復元、`MOTION-002/003/006` のモデル・VMD 読込、P2 ⑤の VMD 表情再生、Phase E のカメラ時間軸が前提。音声付き動画は Phase F の `RENDER-001/006` に渡す。

## 利用者の流れ（歌ってみた）

1. VRM またはテクスチャ同梱 ZIP の PMX、ステージ、カメラ、VMD/FBX モーションを読み込む。`SCR-10` で歌音声を素材として取り込み、波形を見て共通タイムラインの開始位置を決める。
2. 音声の頭出しを試聴し、カメラ／身体／VMD 表情と同じフレームで再生する。SRT を読込み、読みと母音候補を修正する。`SCR-27` で歌詞に使う場合は同じ素材IDの確定SRTを明示的に参照し、口形キーを別トラックへ生成する。歌詞側の編集で確定済み口形キーを自動上書きしない。SRT がなくても手入力で口形キーを作る。
3. 歌声ステムがある場合だけ音素境界の推定を実行し、確信度と未確定箇所を確認する。推定は既存の手修正を上書きしない。無音・長音・「っ」「ん」「ま／ぱ／ば」の閉口は個別に調整する。
4. `SCR-12` で対象モデルの実在モーフを確認し、中立口形 `A/I/U/E/O/Closed/Rest` を PMX モーフ／VRM expression へ明示的に対応付ける。未対応は警告し、勝手に別モーフへ変換しない。
5. `SCR-13` の表情・リップ区画で眉・目・瞬き・視線・感情キーを編集し、VMD 由来の表情との合成結果をプレビューする。変更前後を切り替えて確認し、保存後に再読込する。`SCR-05` は編集先への入口に限る。

## 画面と操作

| 画面 | この範囲で必要な操作 | 状態の表示 |
|---|---|---|

| `SCR-13` `/workspace/13` | 既存 VMD モーフとリップ・表情レイヤーの比較、キー編集。右「表情・リップ」と下部表情トラックを追加 | 本機能の接続前は `◇ 未実装` |

## データ・時刻・保存／復元

- 原本音声、SRT、VMD、モデルは変更しない。プロジェクトは素材 ID・ハッシュ・相対参照、音声ストリーム情報（サンプルレート／チャンネル／長さ）、タイムライン開始フレームとサンプル単位の頭出しオフセットを保存する。移動後に参照が切れた場合は欠損として表示し、黙って無音にしない。
- 共通の有理数 `project_fps` と整数フレームを編集基準とする。音声サンプル位置との換算は有理数で計算し、区間ごとの丸めを積算しない。波形・再生ヘッド・VMD／口形／表情キーは同じプロジェクト時刻を参照する。
- `LipTrack` は `sourceAssetId`、SRT 由来の読み候補、音素／口形キー、由来（手動・SRT・推定）、確信度、修正履歴を持つ。`MorphMap` はモデル資産 ID／ハッシュと実在モーフ名に結び、別モデルへ暗黙に使い回さない。
- `LIP-002` の歌声ステム同期は SRT の時刻と音声の音素境界を照合する強制アラインメント候補として扱う。解析環境・入力品質・推定不能区間を表示し、人手で境界を確定できる。
- `LIP-004` は PMX の口モーフについて、実際の頂点変位範囲とモーフ間の重なりを解析し、母音別の強度候補をモデル単位で示す。形状差の数値だけで自然さを断定せず、実プレビューで調整・確定する。VRM expression は利用可能な定義と重み範囲を検査する。
- `ExpressionTrack` は眉・目・瞬き・視線・感情のキーと、VMD 基底・リップ・表情・手動上書きの順序設定を持つ。各モーフの最終重みはモデルが許す範囲へ制限し、競合・欠落を診断する。合成規則の既定案は `O-LIP-02`。
- 変更は Undo/Redo とプロジェクト revision の対象。保存→アプリ再起動→復元で音声位置、モーフ対応、キー、レイヤー有効状態、未解決警告が一致する。

## 手動 UI・WebMCP・標準 MCP

三経路は同じサービスで `importAudioAsset`、`placeAudioClip`、`setAudioOffset`、`importSrt`、`proposePhonemeKeys`、`setLipKey`、`mapMouthMorphs`、`setExpressionKey`、`previewAvSync`、`getMorphDiagnostics` を呼ぶ。名称は契約案で、既存 API の実在を主張しない。操作には対象 ID、プロジェクト revision、範囲・単位、結果／警告を返す。競合・不正 SRT・非対応モーフ・音声欠損は構造化エラーにする。音声取込はユーザーが選んだファイルだけを扱い、MCP に任意パス読取権を与えない。ログには歌詞全文・音声・個人パスを残さない。

## 受け入れ条件・テスト方針

| ID | 合格条件 | 試験 |
|---|---|---|
| `LIP-001` | 日本語 SRT の時刻を保った口形候補を編集でき、VMD に存在するモーフのみ出力し、欠落をレポートする | SRT→手修正→VMD書出→再読込。原本ハッシュ不変 |
| `LIP-002` | 歌声ステムの推定結果と確信度を示し、推定不可でも手動編集できる | 無音、ノイズ、長音、境界ずれ、解析エンジン不在 |
| `LIP-003` | 閉口・促音・長音と子音先行をキー単位で調整できる | 「ま／ぱ／ば」「っ」「ん」入り基準音声をフレーム比較 |
| `LIP-004` | PMX と VRM の実モーフ名・対応不足を表示し、モデル別に保存する。PMX は頂点変位・モーフ重なりから母音強度候補を算出し、手動調整できる | 既知の頂点変位と重なりを持つ PMX で候補値と適用前後を比較・保存。別の実 PMX／VRM 各1体以上、無モーフモデル、別モデルへの誤適用防止 |
| `LIP-009` | 口形と眉・目・瞬き・視線・感情の独立編集、VMD 表情との競合表示、身体キー不変 | 同一フレーム競合、Undo/Redo、保存復元、実モデル再生 |
| BGM配置 | 歌音声の取込・波形・頭出し・フレーム同期が機能し、欠損を通知する | 先頭無音、途中シーク、異なるサンプルレート、再起動、UI／両MCP同値 |

音声と画面の既知同期点を少なくとも先頭・中間・末尾で測り、ずれが各点で1映像フレーム以内か記録する。フレーム内の音声サンプル位置は保存値と一致させる。Windows/Linux、手動 UI／WebMCP／標準 MCP、音声なし・AI停止時を分けて検証する。実ブラウザー・実モデル試験を実施するまで「動作確認済み」にしない。

## 価値

- 使う側: 歌と口・表情のずれを波形と同じ時刻で直せ、元の VMD と音声を失わずに投稿用映像へ進める。
- 売る側: PMX/VRM 両方を扱う歌唱制作の中核導線を提供でき、手動編集と AI 補助を同じ品質基準で説明できる。

## 未決事項（所有者が選べる既定案）

- `O-LIP-01` BGM 配置の管理 ID: **既定案** 新規の承認済み BGM 専用 ID を台帳取込時に発番する。`LIP-001/002` へ音声配置を隠して重複管理するより、音声取込・同期・復元の進捗を独立に追えるため。番号は開発側の台帳更新時に重複検査して決める。
- `O-LIP-02` 同じモーフへ VMD・生成リップ・手動キーが重なる場合: **既定案** 同じ口モーフは手動キー > 確定済み生成キー > VMD 基底の優先置換、別表情チャンネルは合成後に範囲制限。意図しない二重開口を防ぎ、基底を失わないため。
- `O-LIP-03` SRT の読みが曖昧な場合: **既定案** 候補を未確定表示し手で直してから VMD 出力する。誤読を確定結果として書き出さないため。
