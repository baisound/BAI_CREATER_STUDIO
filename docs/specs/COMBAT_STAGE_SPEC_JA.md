# 格闘・接触・ステージギミック 要求仕様（B4・草案）

状態: 要求仕様。対象 `DANCE-008`〜`011`、`LYRIC-010`、`MOTION-021`。`O-COMBAT-01/02/03` は所有者がすべて推奨案Aを承認した。決定と境界は [B4所有者判断資料](B4_COMBAT_STAGE_DECISIONS_JA.md)、実装者が使う具体的なスキーマ・計算順・API・失敗系・試験は [B4実装設計](B4_COMBAT_IMPLEMENTATION_DESIGN_JA.md) と [共通契約](IMPLEMENTATION_COMMON_CONTRACT_JA.md) を参照。`DANCE-012` の手指・小道具接続は B1、基本ステージ配置とギミックのデータは B3 に従う。格闘演出は見た目と時刻の編集機能であり、実際の衝突物理や人物への安全性を判定する機能ではない。台帳の `MOTION-021` は要検証、現行新UIの物理ベイクは未実装表示で、今回の仕様判断では状態を変更しない。

## 目的・依存

2体の攻防、掴み、ノックダウンから Kip Up、3〜4連続技、扉等のギミック、MMD 物理ベイクを、元モーションを保持したまま制作・検査する。B1 の複数ダンサー・手指／小道具、B3 のステージと `LYRIC-010` 基礎データ、`MOTION-003`〜`009`、`DATA-008`〜`010`、Phase E カメラ、Phase F 出力に依存する。B の未完成項目が Phase E/F を止める条件にはしない。

## 利用者の流れ（歌ってみた／演出）

歌唱 MV の間奏で2人の演技区間を作り、`SCR-13` の2体トラックへ攻撃と反応の VMD/FBX を置く。攻撃開始・接点・反応・回復をタイムラインのイベントで合わせ、`SCR-06` の床や扉との位置を確認する。掴みや武器は B1 の実骨／小道具接続を選び、接点のずれをフレームごとに診断する。衣装や髪の物理を新規ベイクレイヤーへ出し、原演技と比較する。カメラの見切れと音声との時刻を確認して動画を書き出す。

## 画面・データ・保存／復元

- `SCR-13` `/workspace/13`: 攻撃／反応の2体トラック、接触イベント、掴み拘束、ノックダウン／Kip Up／連続技の区間、差分プレビュー。未完成機能は `◇ 未実装` と示す。
- `SCR-06` `/workspace/06`: 床、扉、可動ピボット、モデルとギミックの接点、物理ベイクの表示／非表示。`SCR-12` は髪・衣装・アクセサリの対象部位、`SCR-16/17` はショットと出力、`SCR-24` は貫通・ピクつき診断を扱う。
- `InteractionPair`: 攻撃者／被弾者のインスタンス ID、攻撃・反応クリップ ID、接触イベント（フレーム、骨／小道具接点、ローカル座標、期待ワールド位置）、root 補正、見た目上の間合い警告。`O-COMBAT-01=A` により、同じフレームの接点距離・方向・時刻差と映像オーバーレイを併記し、自動合否や物理安全を断定しない。接点は時間評価でワールド座標へ変換し、元の骨キーを変更しない。
- `GrabConstraint`: 接続元／先の実骨または小道具 ID、開始／終了、オフセット、重み、解除条件。参照骨欠損や循環は確定前に拒否する。
- `StageGimmickEvent`: B3 で登録したステージ資産／実在可動ピボット ID、可動範囲、適用区間、開閉等の状態キー、トリガーとなる時刻付きイベント ID。`O-COMBAT-03=A` により扉等の登録済み可動物を対象とし、未承認のゲームロジックは追加しない。ステージ原本を直接編集しない。
- `PhysicsBake`: 元モデル／モーション／物理設定、対象部位・区間の hash、シミュレータ版、seed、時間刻み、環境識別、生成レイヤーと診断を保持する。`O-COMBAT-02=A` により入力・計算条件の一致と対象環境の代表再計算による出力一致を確認した場合だけ再利用可能とする。再計算は対象部位・範囲に限定し、入力条件が変われば旧ベイクを無効と表示する。異なるOS/GPUの結果一致は別に検証する。

保存→再起動→復元で2体の ID・時刻・接点・拘束・扉状態・ベイクの有効性警告が一致する。変更は Undo/Redo でき、元 VMD・PMX・ステージ素材は不変。完成映像／VMD の書出時は適用レイヤー、未対応拘束、ベイク条件をレポートする。

## 手動 UI・WebMCP・標準 MCP とテスト方針

共通操作案: `createCombatPair`、`setContactEvent`、`previewContactAlignment`、`setGrabConstraint`、`setComboBranch`、`setStageGimmickEvent`、`bakePhysicsLayer`、`detectIntersections`。三経路で対象 ID、revision、dry-run、失敗理由、警告を一致させる。MCP から任意の外部シミュレーションコマンドを渡さず、許可済み処理だけを起動する。障害時の診断ログは素材本体を含めない。

実 PMX/VRM と2体モーション、接続骨がある／ない小道具、床と扉を含むステージで、接触前後・掴み解除・Kip Up・分岐チェイン・扉開閉・ベイクの再現性をフレーム比較する。意図的な貫通と警告の誤検出も記録する。シミュレータ版／seed／時間刻みを変えた試験、ベイク途中の取消、保存復元、Windows/Linux、UI／両 MCP 同値、動画と VMD の再読込を行う。見た目の接触警告を精密物理判定済みと表示しない。

## 価値

- 使う側: 間奏や舞台演出で複数人とステージを同期させ、試行錯誤しても原モーションと物理設定を残せる。
- 売る側: ダンス MV の演出幅を広げつつ、MMD 物理と接触の制限を明示した編集機能を提供できる。

## 所有者決定

- `O-COMBAT-01=A`: 骨／小道具接点の差と同一フレームの映像を併記し、合否を自動断定しない。
- `O-COMBAT-02=A`: 入力・計算条件が一致し、対象環境の再現性を確認できた場合だけ物理ベイクを再利用する。
- `O-COMBAT-03=A`: 登録済み可動ピボットと時刻付きイベントの連動を初期範囲とし、未承認のゲームロジックは含めない。
