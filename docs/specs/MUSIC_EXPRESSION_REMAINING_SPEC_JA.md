# 音楽・リップ・表情の後段 要求仕様（B2・草案）

状態: 仕様草案。A1 以降の後段。対象 `LIP-005`〜`008`、`LIP-010`、`LIP-011`、`LYRIC-006`。BGM の読込・配置、基本口形・表情キーは A1 の仕様を参照する。音声 EQ／ミキサー等の `NF-002` は未承認で対象外。

## 目的・依存

複数の既存 VMD から制作者の口形編集傾向を分析し、修正候補を比較・評価し、モデル別の版を管理する。身体と表情の演技を合わせ、明示許可した顔映像から表情候補を作る。歌音声から BPM／ビート／イベントマーカーを取得して、ダンス・カメラ・発光と同じ時間軸へ置く。`LIP-001`〜`004/009`、BGM 配置、`DATA-008`〜`010`、`MOTION-006`、`CAM-015`、`RENDER-001` に依存する。

## 利用者の流れ（歌ってみた）

歌音声と基本リップを完成した後、`SCR-10` で BPM とビートを確認し、手動で誤った拍を直す。手元の許諾済み VMD を複数読み込み、口形の開始・持続・閉口傾向を分析する。提案を `SCR-05` の別レイヤーで元演技と A/B 比較し、必要なキーだけ採用する。歌の感情に合わせて `SCR-13` の身体区間と表情キーの連動候補を確認する。顔動画を使う場合は対象・保存範囲を選び、`SCR-12` の実モデルに対応する表情キーだけを取り込む。モデル別 VMD 版を新規保存し、`SCR-17` で映像を確認する。

## 画面・データ・保存／復元

- `SCR-10` `/workspace/10`: 音声波形上の拍・イベント、手動 BPM と自動推定候補、基準オフセット。推定値と確定値を区別する。音声解析なしでも手でマーカーを置ける。
- `SCR-05/13`: 元 VMD／推定口形／人手修正／身体演技／表情を独立トラックで表示。比較は同じモデル・フレーム・カメラで行い、片方を採用しても元レイヤーを保持する。
- `SCR-12`: モデル別版、モーフ対応、顔映像から生成した候補と対応不能箇所を表示する。顔映像未登録時はカメラ権限を要求しない。
- `StyleProfile` は入力 VMD ID/hash、モデル・作者の申告メタデータ、算出した時刻・強度・閉口の特徴量、分析条件を保持する。作者の推定・同一性認定は行わない。
- `LipProposal` は元キー参照、提案キー、理由、信頼度または根拠、利用者の判定（表現できている／許容／修正必要）を保持する。元 VMD は不変。
- `LipVersion` はモデル ID/hash、楽曲 ID、親版 ID、VMD 出力 hash、モーフ対応版、変更要約を持つ。保存／再起動／復元で親子関係と比較結果を復元する。
- `BeatMap` は音声 ID/hash、推定または手動 BPM、拍時刻、イベント時刻、基準オフセット、拍ごとの確定状態を持つ。全時刻は音声サンプル位置を源とし、編集画面では共通有理数 FPS のフレームへ変換する。
- 顔入力は同意したローカルカメラ／動画だけを使い、元映像の保存有無を事前に選ばせる。保存しない場合は抽出済みキーだけを残し、診断ログに顔画像を含めない。

## 手動 UI・WebMCP・標準 MCP

同じ操作サービスの契約案: `analyzeLipStyle`、`proposeLipCorrections`、`compareLipVersions`、`rateLipProposal`、`saveLipVersion`、`linkBodyExpression`、`captureFacialCandidate`、`analyzeBeat`、`setBeatMarker`。すべて対象 ID・revision・由来・診断を返す。推定機能がなくても手動マーカー／キー／版管理は使える。標準 MCP にカメラを自動起動する権限を与えず、明示的に選択した動画または UI で許可した収録セッションだけを使う。外部変更時は UI へ競合を示す。

## ID 別の受け入れ条件・テスト方針

| ID | 合格条件と試験 |
|---|---|
| `LIP-005` | 複数 VMD の傾向を入力・算出条件付きで比較し、元ファイルは不変。モデル／楽曲の違いを分析結果に示す |
| `LIP-006` | 修正提案の理由と判定区分を表示し、利用者が未採用／部分採用／採用を選べる。確定キーを自動上書きしない |
| `LIP-007` | 同一フレームの元／提案／採用後を切替再生し、差分キーを確認。保存復元後も比較できる |
| `LIP-008` | モデル別の親版・出力 hash・変更要約を管理し、旧版へ戻しても新しい版が消えない。VMD 往復で欠落を記録 |
| `LIP-010` | 身体区間と感情表情の連動候補を編集でき、身体・口形・表情の元キーは不変。競合レイヤーを警告 |
| `LIP-011` | 明示許可した顔動画／カメラから実在モーフ向け候補を生成し、権限拒否・顔未検出・モーフ欠損時は手動編集へ戻れる |
| `LYRIC-006` | BPM／拍／イベントを波形上で手動編集でき、ダンス・カメラ・発光の同一時刻を参照。テンポ変化・無音・拍ずれを試す |

実音声と許諾済み VMD／顔サンプルで、先頭・中間・末尾の同期、保存再読込、Undo/Redo、UI／両 MCP 同値、Windows/Linux を確認する。自動推定の精度は曲種・モデル別に誤差を記録し、単一の成功例から一般化しない。

## 価値

- 使う側: 手元の VMD を基準に口形を改善し、別モデルや曲ごとの版を失わずに管理できる。
- 売る側: 制作傾向・拍・表情を共通タイムラインへ接続し、継続制作での再利用価値を高められる。

## 未決事項（既定案）

- `O-MUSIC-01` 作者傾向の表示単位: **既定案** 入力 VMD 集合ごとの統計とし、実在作者の識別・評価はしない。申告メタデータだけでは本人性を保証できないため。
- `O-MUSIC-02` 顔映像の保存: **既定案** 元映像は既定で保存せず、許可時だけプロジェクト外の明示した素材として参照する。顔情報を必要以上に残さないため。
- `O-MUSIC-03` テンポ変化曲: **既定案** 単一 BPM 値だけでなく時間付き拍マーカーを正本にする。途中でテンポが変わっても同期を維持できるため。
