# 音楽・リップ・表情の後段 要求仕様（B2）

状態: 所有者決定済みの要求仕様。実装する際は [B2実装設計](B2_MUSIC_EXPRESSION_IMPLEMENTATION_DESIGN_JA.md) と [共通契約](IMPLEMENTATION_COMMON_CONTRACT_JA.md) を読む。A1 以降の後段。対象 `LIP-005`〜`008`、`LIP-010`、`LIP-011`、`LYRIC-006`。`O-MUSIC-01/02/03` は所有者がすべて推奨案Aを承認した。決定と境界は [B2所有者判断資料](B2_MUSIC_EXPRESSION_DECISIONS_JA.md) に記録する。BGM の読込・配置、基本口形・表情キーは A1 の仕様を参照する。音声 EQ／ミキサー等の `NF-002` は未承認で対象外。機能は未実装・未検証。

## 目的・依存

複数の既存 VMD から制作者の口形編集傾向を分析し、修正候補を比較・評価し、モデル別の版を管理する。身体と表情の演技を合わせ、明示許可した顔映像から表情候補を作る。歌音声から BPM／ビート／イベントマーカーを取得して、ダンス・カメラ・発光と同じ時間軸へ置く。`LIP-001`〜`004/009`、BGM 配置、`DATA-008`〜`010`、`MOTION-006`、`CAM-015`、`RENDER-001` に依存する。

## 利用者の流れ（歌ってみた）

歌音声と基本リップを完成した後、`SCR-10` で BPM とビートを確認し、手動で誤った拍を直す。手元の許諾済み VMD を複数読み込み、口形の開始・持続・閉口傾向を分析する。提案を `SCR-13` の別レイヤーで元演技と A/B 比較し、必要なキーだけ採用する。歌の感情に合わせて同画面の身体区間と表情キーの連動候補を確認する。`SCR-05` は編集先への導線と参照表示だけにする。顔動画を使う場合は対象・保存範囲を選び、`SCR-12` の実モデルに対応する表情キーだけを取り込む。モデル別 VMD 版を新規保存し、`SCR-17` で映像を確認する。

## 画面・データ・保存／復元

- `SCR-10` `/workspace/10`: 音声波形上の拍・イベント、手動 BPM と自動推定候補、基準オフセット。推定値と確定値を区別する。音声解析なしでも手でマーカーを置ける。
- `SCR-13`: 元 VMD／推定口形／人手修正／身体演技／表情を独立トラックで表示し、右「比較・版」と「表情・リップ」で編集する。比較は同じモデル・フレーム・カメラで行い、片方を採用しても元レイヤーを保持する。`SCR-05` はここへ移動する導線のみ。
- `SCR-12`: モデル別版、モーフ対応、顔映像から生成した候補と対応不能箇所を表示する。顔映像未登録時はカメラ権限を要求しない。
- `StyleProfile` は選択した入力 VMD 集合のソート済みID/hash、モデル・楽曲、作者の申告メタデータ、分析器版・条件、算出した時刻・強度・閉口の特徴量を保持する。結果は集合の傾向として表示し、作者の推定・同一性認定は行わない。
- `LipProposal` は元キー参照、提案キー、理由、信頼度または根拠を保持する。利用者の**品質評価**（表現できている／許容／修正必要）と**採用操作**（未採用／部分採用／採用）は別の値にする。部分採用では採用したキーIDを明示し、残りを元レイヤーに維持する。元 VMD は不変。
- `LipVersion` はモデル ID/hash、楽曲 ID、親版 ID、VMD 出力 hash、モーフ対応版、変更要約を持つ。保存／再起動／復元で親子関係と比較結果を復元する。
- `BeatMap` は音声 ID/hash、サンプルレート、音声サンプル位置の昇順拍マーカー列と推定／手動／確定の由来、イベント時刻、表示用BPM区間を持つ。時刻付き拍マーカー列を同期の正本とし、単一BPMは正本にしない。編集画面では共通有理数 FPS のフレームへ変換し、丸め差を表示する。音声差替え時に旧マーカーを黙って再利用しない。
- 顔入力は同意したローカルカメラ／動画だけを使い、元映像は既定で保存しない。候補キー・処理版・同意記録だけを残す。利用者が明示選択した場合だけ指定場所の素材参照として保持し、未選択時は診断ZIP・ログ・MCP応答にも顔画像や絶対パスを含めない。

## 手動 UI・WebMCP・標準 MCP

同じ操作サービスの契約案: `analyzeLipStyle`、`proposeLipCorrections`、`compareLipVersions`、`rateLipProposal`、`saveLipVersion`、`linkBodyExpression`、`captureFacialCandidate`、`analyzeBeat`、`setBeatMarker`。すべて対象 ID・revision・由来・診断を返す。推定機能がなくても手動マーカー／キー／版管理は使える。標準 MCP にカメラを自動起動する権限を与えず、明示的に選択した動画または UI で許可した収録セッションだけを使う。外部変更時は UI へ競合を示す。

## ID 別の受け入れ条件・テスト方針

| ID | 合格条件と試験 |
|---|---|
| `LIP-005` | 選択VMD集合のID/hashと算出条件を固定し、その集合の傾向として比較する。作者欄の本人性・技量は推定せず、モデル／楽曲の違いを分析結果に示す。元ファイルは不変 |
| `LIP-006` | 修正提案の理由と品質評価を表示し、採用操作として未採用／部分採用／採用を別に選べる。確定キーを自動上書きしない |
| `LIP-007` | 同一フレームの元／提案／採用後を切替再生し、差分キーを確認。保存復元後も比較できる |
| `LIP-008` | モデル別の親版・出力 hash・変更要約を管理し、旧版へ戻しても新しい版が消えない。VMD 往復で欠落を記録 |
| `LIP-010` | 身体区間と感情表情の連動候補を編集でき、身体・口形・表情の元キーは不変。競合レイヤーを警告 |
| `LIP-011` | 明示許可した顔動画／カメラから実在モーフ向け候補を生成する。元映像は既定で保存せず、明示選択時だけ素材参照を保持する。権限拒否・顔未検出・モーフ欠損時は手動編集へ戻れる |
| `LYRIC-006` | 音声サンプル位置の拍マーカー列を時刻正本としてBPM／拍／イベントを波形上で手動編集でき、ダンス・カメラ・発光が同じマーカー時刻を参照。テンポ変化・無音・FPS変更・拍ずれを試す |

実音声と許諾済み VMD／顔サンプルで、先頭・中間・末尾の同期、保存再読込、Undo/Redo、UI／両 MCP 同値、Windows/Linux を確認する。自動推定の精度は曲種・モデル別に誤差を記録し、単一の成功例から一般化しない。

`LIP-006` では品質評価と採用操作を別々に保存復元し、「修正必要だが未採用」「許容だが部分採用」を試す。採用結果はA1で決定した `O-LIP-02` の手動キー→確定生成キー→元VMDの優先置換に従い、既存の手動0キーと確定口形キーを黙って上書きしない。

## 価値

- 使う側: 手元の VMD を基準に口形を改善し、別モデルや曲ごとの版を失わずに管理できる。
- 売る側: 制作傾向・拍・表情を共通タイムラインへ接続し、継続制作での再利用価値を高められる。

## 所有者決定

- `O-MUSIC-01=A`: 入力 VMD 集合ごとの統計とし、実在作者の識別・評価はしない。
- `O-MUSIC-02=A`: 元映像は既定で保存せず、明示選択時だけ素材参照として保持する。
- `O-MUSIC-03=A`: 音声サンプル位置の時刻付き拍マーカー列を正本にし、BPMは表示・推定値とする。
