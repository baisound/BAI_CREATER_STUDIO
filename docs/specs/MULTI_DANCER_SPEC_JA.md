# 複数ダンサー・フォーメーション 要求仕様（B1・草案）

状態: 仕様草案。A1〜A3 の後に扱う。対象 `DANCE-001`〜`007`、`DANCE-012`。`O-DANCE-01/02/03` は [B1所有者判断資料](B1_MULTI_DANCER_DECISIONS_JA.md) の推奨案Aをすべて承認済み。格闘・掴み・Kip Up・連続技（`DANCE-008`〜`011`）は別仕様。P2 ④の単体モデル／ステージ配置と P2 ⑤の VMD 再生を前提にし、開発中の P2 移植へ割り込まない。

## 目的・依存

複数の PMX/VRM ダンサーに別々のモーションと開始時刻を与え、歌ってみた動画で位置交換、隊形、カノン、ミラー、主役交代、手指・マイク等の操作を非破壊で編集する。`DATA-008`〜`010` の保存／復元、`MOTION-003`〜`009` の実モデル／モーション、`CAM-004` の画角確認、`RENDER-001` の同時描画に依存する。`DANCE-006` の「衝突回避」は接近警告に加え、経路・間合いの改善候補を提示し、手動修正と適用後の再評価を行う。精密な物理衝突保証ではない。

## 利用者の流れ（歌ってみた）

1. `SCR-12` の登録済みモデルを `SCR-06` のシーンに2体以上置き、各インスタンスに固有 ID とトラックを持たせる。ステージ・カメラ・BGM は既存の共通時刻へ配置する。
2. `SCR-13` で各人へ VMD/FBX 由来クリップを割当て、開始位置と速度を調整する。ダンサー A/B を指定区間で交換し、足運びと経路のプレビューを確認する。
3. V字／円／列／千鳥の隊形、カノン開始差、ミラー軸、主役交代を設定する。手指やマイクの保持／持ち替えは `DANCE-012` として別キーにする。
4. `SCR-02/16` で全員の見切れ、`SCR-17` で動画を確認し、必要ならダンサー別 VMD を別ファイルで出力する。元モーションは残す。

## 画面

`SCR-06` はシーンツリーと複数選択、配置ギズモ、隊形・経路プレビュー、右「ダンサー配置」で位置交換と回避候補の提案・手動修正・適用・再評価を行う。`SCR-13` はダンサー別トラック、クリップ開始、ミラー、部位マスクを扱う。`SCR-12` は各モデルの骨格・小道具接続点を確認する。`SCR-16` は主役交代とカメラ割りを確認する。未接続区画は現行の `◇ 未実装` 表示を維持する。長いダンサー一覧は内部スクロール、再生・保存・Undo は固定領域に置く。選択中の人・クリップ・時間を常に示す。

## データ・保存／復元

- `DancerInstance`: インスタンス ID、モデル資産 ID/hash、骨格プロファイル、root transform、可視状態、ロック、トラック ID。モデル資産自体とインスタンスを区別する。
- `DancerMotionTrack`: ダンサー ID、クリップ元 ID/hash、入力／出力フレーム、開始オフセット、時間倍率、部位マスク、ミラー設定、ブレンド、キーの由来。全員で同一の有理数 FPS とフレーム時刻を使う。
- `Formation`: ID、参加インスタンス ID、pivot、隊形タイプ、各アンカー／オフセット、適用区間。位置交換は元位置・目標位置・通過経路と試算警告を別レイヤーで持ち、確定前に dry-run できる。
- `PropBinding`: 小道具資産 ID、保持者、手指／骨接続点、切替フレーム、オフセット。モデルに該当骨がない場合は未対応とする。
- 保存→再起動→復元で人数、各人の位置／トラック／開始時刻、隊形、手指接続、警告が一致する。削除や位置交換は Undo/Redo 可能。ダンサー別 VMD は新規ファイルへ出し、未対応骨・補間欠落を一覧にする。

## 共通時刻と非破壊評価の境界

- シーン上の各ダンサーをモデル素材とは別の安定したインスタンスIDで参照する。複数体が同じ素材を使っても、root位置、モーション、部位マスク、小道具、選択状態を混ぜない。隊形や主役交代に含まれるIDが欠けた場合は削除済み対象として警告し、別の人物へ黙って付け替えない。
- クリップの素材内区間、プロジェクト上の開始フレーム、時間倍率、カノンの開始差を分けて保存する。全員を共通の有理数FPSと整数フレームで評価し、途中シークやループで少しずつずれないよう絶対フレームから計算する。ミラーは左右骨の対応表と軸を明示し、対応のない骨を勝手に反対側へ割り当てない。
- 隊形・位置交換は適用区間 `[startFrame,endFrame)`、参加者、元位置、目標位置、候補経路を持つ非破壊レイヤーとする。dry-runでは元キーを変更せず、変更前後の経路、最小距離、足滑り候補を同じ時間軸で比較する。適用後にも再評価し、新たな接近が生じた区間を示す。
- 小道具の持ち替えは保持者と接続骨の切替をフレーム単位で評価する。前後の境界フレームで二重保持や消失を検査し、骨・小道具素材が欠けていれば完成表示にしない。元の小道具資産は不変更とする。
- VMD一括出力ではダンサーIDと素材・モーションの出典を結果マニフェストに残し、出力名の衝突を事前に検出する。成功したファイルと失敗・未完成ファイルを分け、原モーションや既存完成物を黙って上書きしない。

## 手動 UI・WebMCP・標準 MCP

共通操作案: `createDancer`、`setDancerTransform`、`assignDancerClip`、`previewSwap`、`commitSwap`、`applyFormation`、`offsetDancerClip`、`setMotionMirror`、`setBodyPartBlend`、`bindProp`、`exportDancerVmdBatch`。三経路とも対象 ID・区間・revision・dry-run 結果を同一サービスで扱う。接触警告は計算方法と閾値を返し、警告なしを「物理的に安全」と言い換えない。MCP に任意の原本削除を公開しない。

## ID 別の受け入れ条件・テスト方針

| ID | 合格条件と試験 |
|---|---|
| `DANCE-001` | 実モデル2体以上に別 VMD と異なる開始フレームを割当て、同時再生・保存復元で維持する |
| `DANCE-002` | A/B 交換の dry-run で経路と足滑り候補を示し、確定後も元キーと Undo が使える。交差／障害物のケースを試す |
| `DANCE-003` | V字・円・列・千鳥を区間適用し、人数不足・重複アンカーを警告する。カメラ画角で全員を確認する |
| `DANCE-004` | カノンの開始差、ミラー左右ボーン表、主役交代区間を独立編集し、カメラと共通時刻で再生する |
| `DANCE-005` | 身体部位マスクと強度を各人別に変更でき、未指定部位・他ダンサーのキーを変えない |
| `DANCE-006` | ダンサー間距離と移動経路に基づく接近候補を時間・場所付きで示す。回避経路・間合いの改善候補を dry-run し、手動修正して適用後に再評価できる。警告のみは部分実装として残す。交差経路・狭い舞台・回避不能例で、適用前後の最小距離と新たな接近を試験する |
| `DANCE-007` | 各人の VMD を別名で一括出力し、モデル名・フレーム数・欠落ボーンを報告。再読込し原本 hash 不変を確認する |
| `DANCE-012` | マイク等の小道具を実骨に接続し、持ち替え区間の位置を再生確認。骨欠損・素材欠損を通知する |

実モデル・実 VMD で結果を確認し、単体と複数体の性能差、Windows/Linux、UI／両 MCP の同値、音声とカメラとの時刻同期を記録する。概算の接触警告と実物理挙動は別判定にする。

追加の失敗系: 同一素材から2体作る、途中シークでカノンを再開する、未対応の左右骨をミラーする、隊形の参加者を削除する、持ち替え境界で保持骨が欠ける、VMD出力名が既存ファイルと衝突する場合を試す。どれも他のダンサーのキーと原素材を変更しない。

## 価値

- 使う側: 複数人の歌唱・ダンス演出を1つのタイムラインで調整し、各人の VMD を安全に取り出せる。
- 売る側: 単体モーション閲覧から複数人のMV制作へ利用範囲を広げ、再利用できる隊形・振付ワークフローを提供できる。

## 所有者決定

- `O-DANCE-01` 位置交換の回避候補: **所有者決定A** 床・他ダンサーとの距離を使う候補経路を提示し、人が選択・修正したものだけ適用する。警告だけでは `DANCE-006` を完了扱いせず、実モデルでの前後比較を必須にする。精密な物理保証を約束しない。
- `O-DANCE-02` `DANCE-012` の小道具範囲: **所有者決定A** 既存の登録済み小道具を骨へ接続・持ち替えする範囲。小道具生成・形状編集は扱わない。
- `O-DANCE-03` VMD 一括出力の失敗: **所有者決定A** 各ダンサーを個別成功／失敗で報告し、成功分を保持する。1件でも失敗ならバッチ全体を「一部成功」と表示し、失敗ファイルを完成物に混ぜない。先行成功と原本を保護する。
