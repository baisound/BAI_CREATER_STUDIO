# MMD エフェクト互換・適用・出力 要求仕様（A3・草案）

状態: 所有者のA3判断と後続の優先効果指示を反映した仕様。実装・GPU実測の証拠ではない。対象 `RENDER-011`〜`015`。Phase F の後、Phase C の前に扱う。Ray-MMD/MME の `.fx` をブラウザーでそのまま実行できるという意味ではない。`SCR-09` のノード編集 `NF-001` は未承認で対象外。決定理由は [A3所有者決定記録](A3_MMD_EFFECTS_DECISIONS_JA.md)、優先効果は [効果別候補](A3_VISUAL_EFFECT_PRIORITY_JA.md) を参照する。

## 目的・依存

MMD「歌ってみた」制作で、ステージ・キャラクター・カメラ・BGM・モーションに発光や DOF 等を付け、ブラウザープレビューと動画出力で何が再現できるかを明示する。`RENDER-001`〜`010` の描画・検品、Phase E のカメラ／DOF 評価、`DATA-008`〜`010` の保存に依存する。MMD 向け設定出力は MMD 上での適用成功を保証しない。

## 互換境界

| レベル | 意味 | 利用者への表示 |
|---|---|---|
| `native` | アプリ自身の効果として実装・実描画試験済み。原MMEの同一実行を意味しない | ブラウザー／動画双方の試験結果を別々に表示 |
| `approximated` | 原効果の見た目を別実装で近似 | 原 `.fx` と同一の結果とは表示しない。差分画像と制限を示す |
| `export-only` | 原素材・パラメータ参照と MMD 用手順だけ出力 | ブラウザーでは適用済みと表示しない |
| `unsupported` | 解析・近似・設定出力のいずれも未対応 | 理由と素材保持状態を示す |

各アセット・効果ごとに `previewStatus` と `renderStatus` を別に管理し、試験前は未検証とする。Ray-MMD は独立したシェーダー体系として個別検証し、汎用 MME 効果との互換を推測しない。未知の `.fx` を WebGL シェーダーや任意コードとして実行しない。

## 利用者の流れ（歌ってみた）・画面

VRM/PMX・ステージ・カメラ・BGM・VMD/FBX を配置した後、`SCR-08` でエフェクト素材を登録し、出典と利用許諾を確認する。効果スタック、対象モデル・材質・ショットへの割当、パラメータキーは専用の `SCR-26` が編集を所有する。`SCR-06` は対象選択と効果表示、`SCR-02/03` は焦点と被写界深度の確認、`SCR-17` は短区間の実レンダーとの差分確認を担う。外部 MMD へ渡す必要がある `export-only` 効果は設定書と素材参照を出す。`SCR-09` は材質確認に使えるが、未承認のノード編集をこの仕様で有効化しない。

`SCR-26` では左の登録済み効果を選び、右「効果スタック」で適用先（シーン／モデル／材質／ショット）と描画順を決める。右「パラメータ」で効果の ON/OFF と共通強度、選択した内蔵効果に対応する固有項目を調整する。現在フレームへキーを追加すると下の強度キートラックに置かれ、中央プレビューで前後を比較する。編集前後は Undo/Redo できる。`export-only` の原 `.fx` パラメータはブラウザー近似値と区別して参照し、ブラウザーで描画済みと示さない。現モックの入力は説明用で、効果適用・保存・キー記録は未実装と表示する。

## データと保存／復元

`EffectAsset` は ID、元ファイル hash、出典・作者・ライセンス・許可用途、依存ファイル、対応エンジン、互換レベル、検証環境、代替方法を持つ。ライセンス不明なら再配布パックには含めない。`EffectInstance` は対象（シーン／モデル／材質／ショット）、効果 ID、ON/OFF、パラメータ、強度キー、品質段階、描画順、原効果との対応を持つ。原素材を変更せず、効果の追加・削除・順序変更は Undo/Redo できる。保存後の復元では参照 hash、描画順、警告、互換レベルが一致し、素材欠損時に効果を黙って代替しない。

描画順の既定は `stage → opaque → alpha → emission → postprocessing → overlay`。DOF と Bloom、透明物・発光の順序依存を明示し、循環は設定保存前に拒否する。カメラごとの焦点値とレンダラーの実ぼけを別の値として提示する。

## 適用・描画・出力の実装境界

- 登録した素材の状態は `registered`、アプリの効果インスタンスへ結びつけた状態は `attached` として分ける。互換レベルに加え、`previewStatus`、`renderStatus`、`mmdExportStatus` をそれぞれ `未検証／対応／近似／参照のみ／非対応` の根拠付きで記録する。素材の登録だけでは映像への効果適用を示さない。
- 効果ごとに、必要な入力（深度、色、速度、透過など）、対応するパラメータ名・単位・範囲、描画パスの前後関係を定義する。必要な入力やGPU能力が欠けた場合はその効果を選択不可または未対応と表示し、別の効果へ黙って置き換えない。スタックの順序変更は依存グラフを再検証する。
- 固定フレームの評価関数は、シーンrevision、効果スタック、対象ID、ショット、キー、イベントを入力にする。`RENDER-013`の粒子・煙等はイベントIDとフレームから再現できる状態を持ち、同じジョブスナップショットのプレビューと動画出力で開始・終了・対象が一致する。入力が欠けたイベントは描画成功にしない。
- `RENDER-012` のDOFはカメラ側の焦点値と、描画に使ったぼけ設定を別に残す。Bloom、MotionBlur、透明物と重ねたときの出力差を代表フレームで比較する。効果ごとにGPU／ブラウザー／レンダラー／品質設定と画像のhashを記録し、試験していない環境へ対応表記を広げない。
- `RENDER-015` のMMD向けマニフェストは、出典・素材hash・必要ファイル、適用対象、順序、元`.fx`の値、アプリ内蔵効果の値、未対応項目を分ける。元素材の同梱は素材別の許諾が確認できた場合に限る。参照のみの素材は受け側に必要ファイルと未同梱理由を示す。MMD上での実適用成功は独立した実機試験で判定する。

## ID 別の契約

| ID | 必須要求 |
|---|---|
| `RENDER-011` | Ray-MMD/MME 素材の登録・依存ファイル・ライセンス・互換レベル表示。登録は適用や互換を意味しない |
| `RENDER-012` | AutoLuminous風発光、Bloom、DOF、MotionBlurに加え、所有者が優先する影の強調を効果別に評価。原効果との差分を表示し、対応不能な環境では無効と表示 |
| `RENDER-013` | 発光・火花・煙・衝撃波に、所有者が優先する霧、塵、舞う桜の花びら、きらめきを統合。ヒットイベントまたは持続区間へ結び、開始・終了と対象を記録。素材がない場合は生成成功と偽らない |
| `RENDER-014` | シーン／対象／材質／ショット別のスタック、順序、テンプレート、強度キーを非破壊で保存。霧の濃度、粒子量、影の強さ、DOFの焦点などは効果ごとの単位と範囲を持つ |
| `RENDER-015` | MMD 側で再構成する設定書・素材参照・適用順・未対応項目を出力。ブラウザー近似パラメータと原 `.fx` のパラメータを混同しない |

## 手動 UI・WebMCP・標準 MCP

共通サービスの契約案は `registerEffectAsset`、`listCompatibility`、`attachEffect`、`setEffectParamKey`、`reorderEffectStack`、`compareFxRender`、`exportMmdEffectManifest`。三経路で対象 ID、revision、許可、検証結果、未対応警告を同じ形で扱う。素材登録は選択したファイルと依存ファイルだけを許し、MCP に任意ファイル実行を公開しない。素材パスや歌詞を診断ログへ記録しない。

## 受け入れ条件・テスト方針

- 実際の利用許諾が確認できる効果素材を1件以上、ライセンス不明素材を1件、欠損依存素材を1件登録し、登録・再配布可否・保存復元を確認する。原ファイル hash は不変。
- `native/approximated/export-only/unsupported` の各表示を UI／両 MCP で同じ結果にし、未検証効果を再現済みと表示しない。
- 同じ素材を「登録だけ」「対象へ適用」「ブラウザープレビュー成功」「動画出力成功」「MMD向け設定書作成」の順に進め、各段階で未完了の状態を完了表示しない。依存テクスチャ欠損、描画入力不足、GPU能力不足、スタック循環を投入前または実行時の明確な失敗として記録する。
- Bloom、DOF、MotionBlur、透明物を重ねた代表フレームを実ブラウザーと動画出力で比較し、差分画像、描画順、GPU／ブラウザ／レンダラー情報を記録する。計算上の焦点範囲と実描画のぼけを別々に判定する。
- 霧、塵、桜の花びら、きらめき、影の強調、ボケの各OFF/ONを同じカメラ・実モデル・フレームで比較し、見た目の変化とアルファ境界、前後関係、GPU負荷、動画出力との差を記録する。簡易な奥行き霧を局所的な体積霧と同じ機能として報告しない。影は単なる画面暗化ではなく実モデル・ステージの陰影変化を確認する。
- ヒットイベント時刻を変えた場合に `RENDER-013` の効果開始フレームが追随する。対象のないイベント・範囲外イベントは警告する。
- 同じイベントID・入力スナップショット・フレームを二度評価し、粒子や煙などの開始・終了・代表フレームが一致する。スクラブ、保存復元、レンダー再試行後にも結果が一致するか測る。
- MMD 用設定書に必要素材・適用順・互換外項目が列挙され、原 `.fx` 自動適用成功の文言がない。実 MMD への適用は別の実機検証として記録する。
- 効果 ON/OFF、順序変更、Undo/Redo、保存復元、素材欠損、GPU 能力不足、Windows/Linux、音声付き出力を検証する。
- `SCR-26` で効果選択→対象割当→強度・効果固有パラメータ変更→現在フレームへのキー追加→再読込を試験し、UI／両MCPで同じ対象・単位・値を返す。`export-only` はブラウザー描画値と混同しない。

## 価値

- 使う側: 見た目を調整しながら、プレビューと書き出しの差、MMD でしか再現できない箇所を把握できる。
- 売る側: MME 素材管理と現実的な互換表示を提供し、互換性の過大な約束による失敗を減らせる。

## 所有者決定

- `O-MMD-01` 初期内蔵効果の範囲: **所有者決定A** Bloom、DOF、MotionBlur、AutoLuminous風発光を個別に実装・試験する。Ray-MMDは素材登録・MMD向け設定出力から始め、ブラウザー近似は効果別の証拠が揃ったときに追加する。`RENDER-013` のイベント効果は承認済み要件として別に扱う。
- `O-MMD-02` 差分の合否: **所有者決定A** 効果別の測定項目と代表フレームの目視確認を併用する。閾値・許容差は実素材と参照レンダーで決め、比較できない場合は未検証とする。
- `O-MMD-03` ライセンス不明素材: **所有者決定A** ローカル参照のみ保持し、配布用出力には含めない。許諾状態を素材単位で保持する。
