# 動画・連番書き出し 要求仕様（A2・草案）

状態: 所有者のA2判断を反映した仕様。実装・動作確認の証拠ではない。対象 `RENDER-001`〜`010`。`RENDER-011`〜`015` は別仕様。新 UI の AOV 等の未承認候補 `NF-016`〜`018` は対象外。決定理由は [A2所有者決定記録](A2_RENDER_DECISIONS_JA.md) を参照する。

## 目的・依存

MMD アプリを介さず、制作中のシーンをカメラ通りに固定時刻で描画し、歌音声付き投稿動画または透過中間素材として確実に保存する。`CORE-004`（共通操作）、`DATA-008`〜`010`（保存・履歴）、Phase E のカメラと共通タイムライン、A1 の音声配置を参照する。音声素材がない作品では無音出力も選べる。MMD エフェクトの採否は A3 の対応レベルに従う。

## 利用者の流れ（歌ってみた）

VRM/PMX、ステージ、カメラ、BGM、VMD/FBX、対応済みエフェクトをプレビューし、`SCR-17` で投稿プリセットを選ぶ。1080×1920 の縦動画、または 1920×1080・60 fps の MP4 と歌音声を選び、範囲・容量・互換警告を確認してジョブを開始する。進捗と失敗理由を見て、中止または可能な形式だけ再開する。完成後に再読込検査結果を確認してから公開用ファイルとする。透過が必要なら PNG/EXR 連番へ切り替える。

## 画面と状態

- `SCR-17` `/workspace/17`: 出力プリセット、解像度／縦横比／FPS／範囲／背景／音声、実カメラでの短区間プレビュー、キュー、進捗、履歴、検品結果。予測容量・残容量・FFmpeg 能力を明示する。現在のモックや既存部分機能を本仕様の実装済みと扱わない。
- `SCR-07` は初期構想画面であり、`SCR-17` と別の実装を作らない。`SCR-10` の歌音声配置を音声選択へ引き継ぎ、`SCR-16` のショット範囲を出力範囲として受け取る。`SCR-24` から診断ログを開ける。
- ガイド、ギズモ、自由視点カメラを出力映像へ焼き込まない。エラー時は失敗したフレーム・工程と再試行／設定変更の導線を示し、未完成ファイルを「完了」と表示しない。

## ジョブデータ・保存／復元

`RenderJob` は ID、プロジェクト revision、シーンスナップショット hash、素材 ID/hash、範囲 `[startFrame,endFrame)`、有理数 FPS、幅／高さ、背景／アルファ方式、コーデックプリセットと実 encoder、色空間、音声素材 ID とサンプル単位の開始オフセット、出力先、状態、進捗、診断ログ ID、検品結果を持つ。投入時のシーンを固定し、進行中の編集が結果へ混入しない。原素材・既存の完成ファイルを上書きしない。保存先には一時名で書き、検証後に完成名へ確定する。

状態は `draft → queued → preparing → rendering → encoding → verifying → completed`。失敗・中止は `failed/canceled` と理由を記録する。再起動後はキューと工程状態を復元し、中間フレームの hash と入力スナップショットが一致する連番ジョブだけ再開可と表示する。コンテナ MP4 のエンコード途中からの再開は保証せず、保存済みの検証済み連番から再エンコードする。キャンセルは FFmpeg 等の子プロセスまで止め、部分成果物を別名・期限付きで管理する。

## 形式・同期・出力の契約

| ID | 必要な仕様 |
|---|---|
| `RENDER-001` | Camera View と同じカメラ評価をフレームごとに固定時刻で行い、モデル・ステージ・照明・モーションを同期描画 |
| `RENDER-002` | 単色／クロマキー色／透過を明示。透過不能な組合せは実行前に拒否。straight/premultiplied をメタデータ化。透過初期受入は RGBA PNG 連番 |
| `RENDER-003` | 幅・高さ・有理数 FPS を保存。横 1920×1080・60 fps と縦 1080×1920 の投稿プリセットを提供し、任意値を検証 |
| `RENDER-004` | H.264 等の encoder を利用環境で列挙し、短い試験エンコードと再読込で使える組合せだけ選択可能にする。H.265/VP9/AV1/ProRes は各組合せの検査を通った環境で提示 |
| `RENDER-005` | RGBA PNG 連番を透過の初期受入形式とし、EXR・アルファ動画は対応環境での実書出し・再読込後に提示。透過輪郭と欠番を検査 |
| `RENDER-006` | FFmpeg の引数配列で映像と音声を多重化。`AUDIO-001` の確定配置を入力とし、頭出しオフセット、尺、チャンネル、サンプルレートを記録。MP4 のH.264映像と音声encoderの組合せを実測し、使えない場合は音声付きプリセットを無効化。音声なしへ黙って変更しない。同名出力は版名を提案し、明示置換時は旧版を退避する |
| `RENDER-007` | ショット／カメラごとに独立ジョブをキュー化し、順序・依存・失敗理由を表示 |
| `RENDER-008` | 入力 hash と影響範囲が一致するショットのみ再利用。判断不能なら全範囲を再描画し誤再利用しない |
| `RENDER-009` | 実ファイルを再読込し、寸法、FPS、フレーム数、尺、音声トラック、無音・黒画面・欠番・ちらつき候補を検査。候補は人が確認できる位置を示す |
| `RENDER-010` | 進捗、取消、失敗後の再試行、連番チェックポイントからの再開可否を表示 |

音声はプロジェクト基準時刻からサンプル位置へ有理数変換する。映像フレームごとの時間を丸めて足し合わせない。音声の既知同期点（先頭・中間・末尾）と映像イベントのずれが各点で1映像フレーム以内か検品結果に記録する。音声が入っていない場合は警告し、無音での意図的出力を明示確認する。

## 描画・音声・ファイル確定の実装境界

- 画面プレビューとジョブは、同じ「シーンスナップショット＋整数フレーム→評価済みカメラ・モデル・照明・エフェクト」の関数を通す。ジョブ側は壁時計の経過や表示中のUI状態で時間を進めず、`startFrame`から`endFrame-1`まで各フレームを固定時刻で評価する。プレビューとの差分は比較用フレーム番号と入力hashを添えて記録する。
- 画素の読出し・PNG化は描画成功と分ける。GPUコンテキスト喪失、欠落テクスチャ、異なる寸法、書込失敗が起きたフレームはジョブを失敗状態にし、完成したように次へ進めない。復旧時はスナップショットと中間フレームhashを照合する。
- 出力区間の先頭を動画時刻0とし、音声クリップのプロジェクト開始フレーム・素材内開始サンプルから、区間内の音声位置を絶対時刻の有理数計算で求める。クリップが区間途中から始まれば前を無音で埋め、区間より前から始まれば素材の先頭を適切に飛ばす。元素材には変更を加えず、選んだ音声ストリーム・サンプルレート・オフセットをジョブに固定する。
- `SCR-17` のプリセットは寸法・FPS・背景・音声の希望値と、実際のencoder名・コンテナ・画素形式・音声codecを分けて表示する。`RENDER-002/004/005/006` の検証で不適合ならジョブを投入させず、設定変更先を示す。音声なしやアルファなしへ黙って変えない。
- 中間成果物はジョブ固有ディレクトリに置き、フレームごとの寸法・hash・レンダー元revisionと期待フレーム数をマニフェストに残す。MP4などの一時ファイルは、encoder終了コードだけでなく実ファイル再読込・期待値照合を通してから完成名へ確定する。失敗・取消・検品未了の出力は履歴で未完成と表示する。
- ジョブの保存・再起動復元は、工程名と最後に検証済みのフレーム／成果物を区別する。再開可否は形式とhashで判断し、MP4エンコード途中のバイト位置からの再開とは表示しない。外部プロセスが止まらない場合も完了扱いせず診断ログへ記録する。

## 手動 UI・WebMCP・標準 MCP

共通 `RenderService` の契約案: `listCapabilities`、`createJob`、`validateJob`、`startJob`、`cancelJob`、`resumeJob`、`getJob`、`listJobs`、`verifyOutput`。三経路とも同じ入力検証・revision 競合判定・権限・ログを用いる。外部入力の任意コマンド文字列を実行せず、FFmpeg は固定 executable と引数配列で呼ぶ。保存先は許可されたローカル領域に限り、MCP へ無制限のファイル書込を公開しない。診断ログに素材本体・秘密情報を含めない。

## 受け入れ条件・テスト方針

- 横／縦プリセットで、実カメラのフレーム 0・中間・末尾・切替境界がプレビューと一致する。出力へガイドやギズモが映らない。1920×1080・60 fps MP4 に歌音声を含め、再読込結果に寸法・有理数 FPS・フレーム数・音声トラックと同期差を表示する。
- 30000/1001 fps、範囲の途中開始、歌音声の先行／遅延配置、素材内の頭出し、音声が途中で終わる場合を用意し、先頭・中間・末尾の音声位置を絶対時刻から計算した期待値と比較する。音声のないジョブは明示的な無音選択を要求する。
- PNG 透過連番でアルファ境界と欠番を確認する。透過非対応 codec、encoder 欠如、無効 FPS、不正範囲、容量不足、不正パスを投入前に拒否または失敗として明示する。
- ジョブ途中で編集しても出力は投入時のスナップショットに一致する。キャンセルは子プロセス停止・未完成表示・既存完成物不変を確認する。再起動後は連番チェックポイントだけ hash 検証して再開する。
- GPUコンテキスト喪失、素材欠損、PNG欠番、FFmpegの異常終了、終了コード0だが再読込できないMP4、同名ジョブの同時投入を失敗系として試し、完成表示や既存ファイル変更が起きないことを確認する。
- 差分レンダリングは素材・カメラ・エフェクト変更時の失効を試験する。黒画面・欠番・音声なし等の検品サンプルを用意し、見逃しと誤検出を記録する。
- 手動 UI／WebMCP／標準 MCP から同条件のジョブを作り、検証結果・エラー・履歴が等しいことを確認する。Windows/Linux、FFmpeg 有無、実ブラウザー/GPU を別々に報告する。

## 価値

- 使う側: 音声付き歌唱動画と透過素材を、設定ミスと未完成ファイルを見分けながら制作できる。
- 売る側: 投稿形式・再現性・検品を一続きに提供し、外部 MMD/編集ソフトへの依存を減らせる。

## 所有者決定

- `O-RENDER-01` MP4 の既定 encoder: **所有者決定A** 利用環境で使用可能な H.264 と音声 encoder の組合せを試験エンコード・再読込で確かめて表示する。
- `O-RENDER-02` 完成物の同名衝突: **所有者決定A** 新しい版名を提案し、明示置換時だけ旧版を復元可能に退避する。安全な退避・確定ができなければ置換を拒否する。
- `O-RENDER-03` 透過動画: **所有者決定A** 初期受入は RGBA PNG 連番。EXRとアルファ動画は実書出し・再読込を通してから提示する。
