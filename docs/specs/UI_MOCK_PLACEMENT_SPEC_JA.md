# 承認済み未完成要件の新UI配置仕様（草案）

対象: `SPEC_BACKLOG_FOR_CODEX_JA.md` の A1〜A3、B1〜B4。根拠: `studio/js/screens.js`（`bfa1033` 時点の25画面）、`docs/ui/SCREEN_IMPLEMENTATION_MATRIX.json`、7件の領域別仕様。本書は操作位置と最小限の画面要素を決める。実装完了の主張ではない。Owner は新規専用画面を FX と歌詞の2件だけ追加し、ダンサー・格闘は既存画面へ置く案を選択した。

## 判定規則

1. 既存モックのパネル・右タブ・下部タイムラインを先に使う。同じ対象と操作を複数画面へ実装しない。素材は `SCR-08`、場面配置は `SCR-06`、時刻付き編集は `SCR-10/13/16`、出力は `SCR-17` を原則の所有画面とする。
2. 現在の `mock` や `unimpl` は実機能ではない。追加するモック操作も接続・自動テスト・実素材検証までは `◇ 未実装` と表示し、実測値、成功表示、保存済み表示を出さない。手動 UI と両 MCP は同じサービス契約を使う。
3. 画面にある未承認候補（`SCR-09` の `NF-001` ノード編集、`SCR-10` の `NF-002` EQ 等、`SCR-17` の `NF-016`〜`018` AOV 等）は見た目を残すが、この仕様で実装しない。
4. 操作は基本欄と詳細欄を分ける。主操作・現在の対象・保存状態を固定し、長い素材／キー／検品一覧だけ内部スクロールにする。狭い画面でも選択中モデル、トラック、フレーム、単位が分かるようにする。
5. P2 と Phase E の進行中の画面・API を上書きしない。取り込み時に現行 `studio/js/screens.js` と突き合わせ、画面・パネルの状態表示とテストを同時に更新する。

## 新規ページの判断と開発境界

Owner の回答により `SCR-26`（MMD FX）と `SCR-27`（歌詞・MV構成）を追加する。いずれも既に承認された ID の操作を収めるための画面で、機能追加ではない。ダンサーと格闘は `SCR-06/13` の用途別タブに配置する。`SCR-26` が FX スタックと割当の編集を所有し、`SCR-06` は対象選択と効果表示、`SCR-17` は出力差分を扱う。`SCR-27` が歌詞キューと文字配置の編集を所有し、`SCR-16` はショット参照、`SCR-06` はステージ内での表示確認を扱う。
`SCR-27` は絵コンテと歌詞イベントのショット参照だけを編集し、ショット本体の編集は `SCR-16` が所有する。新UI共通ヘッダの「FX」「歌詞」リンクから両ページへ移動できる。

### JIZURA に基づく SCR-27 のページ境界

2026-10-20 に [JIZURA 実画面](https://jizura.net/)（表示 v0.10.0）、[公式ガイド](https://jizura.net/guide/)、[公式リポジトリ](https://github.com/852wa/JIZURA) を確認した。JIZURA は歌詞行・曲・行とカットを左、プレビューとタイムラインを中央、かんたん／詳細の演出設定を右に置き、同じエディタ内で表示を切り替える。BAI の `SCR-27` も同一ページの表示切替を採用する。右「かんたん」は候補づくりと行の局所修正、「詳細」は行・カット、配置、文字モーション、演出パック、MV参照のタブを表示する。切替時に左の入力・中央の再生位置・選択行を保持する。実際のソース・パック・SRT直接入力をJIZURA由来と誤認させない。上流 README の記載版 v0.9.0 と実画面 v0.10.0 の差は実装前の版固定で解消する。

`SCR-26/27` 中央の画像は組み込み画像生成ツールで制作したコンセプト画像（`studio/assets/mock-previews/mmd-fx-concept.png`、`lyrics-mv-concept.png`）で、リアルタイム描画結果ではない。FXは仮想ダンサーとマゼンタ／シアン照明、歌詞は歌い手を右に置き左にUI側の文字を重ねる構図を指定した。下部には仮の効果区間・発話区間・キーを置き、本体ドラッグで区間長を保った移動、端ドラッグでトリム、キーの移動とフレーム単位のキーボード操作を試せる。これらは画面内だけのサンプル状態で保存されず、再読込で初期値へ戻る。特に歌詞の3つの発話例は無音と重なりを示し、正規SRTの開始・終了時刻を「次の開始」に置き換えない。実素材の解析・音声同期・効果描画・動画反映は未実装と表示する。

モックの追加が必要な場合は `codex/specs` だけで、未実装状態の表示・既存 25画面の動作・画面検索・ルートテストを保つ。Claude Code の P2 実装ブランチと `docs/handoff/WORK_STATE.json` は変更しない。

### 追加画面・区画の受け入れ試験

- `SCR-26/27` のサイドバー移動、直接URL、再読込、戻る／進む、画面検索、未実装ダイアログの機能 ID・導線を自動試験する。既存25画面も同じ試験を継続する。
