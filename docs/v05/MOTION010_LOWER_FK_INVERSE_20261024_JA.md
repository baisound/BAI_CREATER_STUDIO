# MOTION-010 下位FKレイヤーの3D直接編集

2026-10-24、Issue #106。既存の複数層3D操作を、条件を満たす下位FKレイヤーの単一骨に拡張した。ソロ・ミュート・重み・有効区間を適用した層のうち、選択層より上に有効な層がある場合だけ、後段差分を逆算する。レイヤー順の変更は追加していない。

## 計算と停止条件

- 選択骨のキーを選択層から一時的に除き、同一時刻に「選択層まで」と「全有効層」を同じMMD評価器で再生する。前者の姿勢を基準、両者の差を後段差分とする。
- 回転は `inverse(q_base) × q_target × inverse(q_upper)`、位置は `p_target - p_base - p_upper` を選択層の差分へ変換する。仮表示後に同じ評価器で再生し、既存の姿勢誤差ゲートを通ったときだけキー化する。ドラッグ中のレイヤー変更も停止する。
- 上位有効層に対象以外の骨のキーがある場合、骨の親子関係で後段差分が変化しうるため操作を拒否する。対象骨がPMX IKの目標・エフェクタ・リンク、または付与の対象である場合、IK・付与定義を読めない場合も拒否する。腕・膝・IKの3Dハンドルは引き続き有効最上段層で操作する。

- `npm run typecheck`、変更したJavaScriptの `node --check`、`git diff --check` は通過。
- `tests/studio-v05-pmx-fk-lower-layer-real.test.cjs`：実PMX `Baisound-New-V5.0.0-B_新狐面差替_紐鈴物理_調整v6.pmx` と実VMDを隔離サーバーへ複製し、F240の頭骨で下位位置0.02、上位位置0.01・Y回転0.2radを重ねた。下位層の頭回転、続いて頭位置を実ポインタでドラッグし、仮表示・保存・再読込の局所姿勢が一致した。上位層のキーJSONと下位層のもう一方のチャンネルを保持し、センター位置を変えなかった。上位層へ別の骨のキーを加えると下位層の3D操作が理由付きで無効になることを確認した。
- `tests/studio-v05-pmx-fk-multilayer-gizmo-real.test.cjs`：下位層の頭FKは有効で、脚IKハンドルは無効になる条件を追加。既存の上位層の頭・腕IKドラッグも回帰対象とした。
