# v0.5 3D入りMP4の600F拡張（2026-11-05）

対象はロードマップ順3、Issue #63/#69、`RENDER-001`。3Dシーンの固定時刻PNG連番と限定MP4の上限を300Fから600Fへ広げた。720p、作業連番256MiB、出力全体10分の各制約、入力hashと保存revisionの照合、終了時の連番削除は維持する。画面はAPIの `max_scene_frames` を使って現在の上限を表示・判定する。

## 隔離試験

`tests/studio-v05-scene-long-mp4.test.cjs` は合成GLBとWebPを隔離作品へ登録し、画像クリップ12秒、3Dシーン、In/Out `F60..F659` を保存する。600枚の3D PNGを固定時刻で描き、H.264/AAC・1280×720・600Fの完成MP4を再読込した。3Dなしの同範囲MP4と比べ、先頭と末尾の両方で200画素超の差を確認した。元GLBのSHA-256は前後一致し、ジョブの入力hashも一致した。作業連番フォルダーは完了後に消えていた。

次に `F0..F600` の601Fへ保存範囲を変更すると、APIは理由付き422、画面の書き出しボタンは無効となった。先の600F完成物は同じSHA-256で再読込できた。保存範囲・シーン・画面・出力の四つを同じ作品IDで照合している。

`CHROMIUM_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe`、`BAI_TEST_CONCURRENCY=1` で `node tests/run-guarded.cjs tests/studio-v05-scene-long-mp4.test.cjs` は1件成功（約32秒）。利用者の `data/` 5ファイルと `exports/` 0ファイルは前後hash一致。Node構文と `npm run typecheck` も成功。描画器のGPU種別はこの試験では判定していない。
