# v0.5完成MP4の同名版管理（2026-11-05）

対象はロードマップ順3、Issue #63/#69、`RENDER-006`。作品の出力画面で完成物の名前を指定する。同じ名前がすでにあれば `-v02` から未使用の版名を提案し、そのまま新規保存できる。「この名前の完成物を置換」を選んだときは画面で確認してからジョブを作る。旧完成物の実ファイルはUUIDの別名で不変のまま残し、名前台帳では旧版に移す。履歴の「この旧版を復元」で現行版と旧版の参照を入れ替え、どちらのMP4も再読込できる。

名前は作品ごとの台帳 `data/studio_v05_media_renders/names/` に保存する。NFC・大文字小文字をそろえて衝突を判定し、パス区切り、Windowsの予約名、MP4以外の拡張子などは拒否する。版名・置換対象・台帳revisionを出力開始時と完成直前に照合する。置換前には現行ファイルのサイズとSHA-256を確かめる。新MP4を別名で検証した後だけ名前台帳を原子的に切り替え、台帳書込に失敗したら新MP4を撤去して旧参照を保持する。サーバーが切替直後に中断した場合は、確定前に保存したサイズ・hash・probeと台帳参照が一致するときだけ成功ジョブへ復旧する。

## 試験結果

- `tests/studio-v05-render-names.test.cjs`：隔離作品で「作品.mp4」を出力し、同名の候補「作品-v02.mp4」を確認して両方を完成させた。APIの誤った置換対象は409で拒否。明示置換で旧版を保持し、旧MP4のSHA-256が一致することを確認。画面の旧版復元を実操作し、置換確認を取りやめたときはジョブ数が増えず、承諾したときだけ新ジョブへ切り替わった。古いrevisionでの復元は409で拒否。隔離Chrome/FFmpegで1件成功。
- `tests/test_studio_v05_render_names.py`：名前台帳の原子書込失敗時に旧MP4と現行参照を保持し、同サイズの旧版改変を復元前に拒否し、中断直後の検証済みファイルを復旧する。危険な名前も拒否。4件成功（名前の5小ケースを含む）。
- 既存の `tests/studio-v05-media-render.test.cjs` と `tests/test_studio_routes.py` も成功（それぞれ1件・6件）。`node tests/run-guarded.cjs` の隔離試験で利用者 `data/` 5ファイル、`exports/` 0ファイルの前後hash一致。

既存の名前未指定APIは、従来どおりUUID別名で完成物を保持する。履歴の旧版は元の名前に「旧版」とジョブIDを添えてダウンロードできる。現時点では名前と版履歴の手動UI・共通HTTP APIまで。WebMCP・標準MCP、Linux、実制作の多数版・大容量MP4、別名書出し先への直接保存は未検証または未接続。`RENDER-006` 全体は完成扱いにしない。
