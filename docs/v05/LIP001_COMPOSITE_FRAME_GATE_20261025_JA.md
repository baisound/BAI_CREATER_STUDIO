# LIP-001 元VMD・採用口形・手動表情のフレーム比較ゲート（Issue #187）

## 実装した範囲

単一の元VMDが作品時刻0から再生される場合の、API非依存の別名候補計算を追加した。元VMDのモーフ値、SRT発話の半開区間にある採用口形、手動表情キーの順で各時刻を評価する。対象モーフを30fpsの各整数Fへ焼き込み、前段のバイナリ書換器を通して骨・補間・カメラ等の区画を保持する。元ファイルや作品台帳には書き込まない。

生成した候補を構造再読込し、作品の全整数Fと各VMD Fの中間（60fps相当）で画面規則との差を測る。最大モーフ重み差が0.0001を超えた場合は候補バイトを返さず、対象モーフ・時刻・期待値・実値を報告する。SRT開始で元値0.2から採用値0.8へ不連続に変わる例、24fpsの手動キーが30fps格子の間にある例を拒否した。滑らかに接続する採用口形と手動0キーの優先は通る。重複・逆順の発話範囲、同一モーフの同一時刻キー、非有限値、上限超過も拒否する。

このゲートは作品からの元VMDクリップ選択、採用候補の再照合、生成ファイルの保存やダウンロード、実PMX描画をまだ接続していない。比較は指定された作品範囲内のサンプルであり、任意の連続時刻の同値証明ではない。元VMDの有効範囲と作品尺の一致は製品接続時に検査する。

## 検証

- `python -m pytest -q tests/test_studio_v05_lip_vmd_composite.py tests/test_studio_v05_vmd_morph_rewrite.py`：実長尺VMDを含む9件成功。長尺は12001作品F＋6000中間F、対象1モーフの18001値を比較した。
- Python側の優先評価を画面で使用する `evaluateLipCueTracks` と `evaluateFaceKeys` に同じ時刻を渡して照合。WindowsのNode標準入出力はUTF-8を指定した。
- 実VMDの非モーフ区画と元ファイルのSHA-256は不変。実PMXの表示同等性、製品API/UI、最終MP4、WebMCP、標準MCP、Linuxは未検証。

モデル区分: 設計・実装・試験とも標準モデル。
