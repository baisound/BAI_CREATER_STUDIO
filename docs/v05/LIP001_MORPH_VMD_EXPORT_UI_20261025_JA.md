# LIP-001 v0.5別名モーフVMD候補の画面操作と実PMX検証（Issue #187）

## 画面でつながった範囲

作品のSRT欄から確定済み登録PMX口形対応を選び、「出力条件を検査」→「別名VMD候補を生成」→ファイル取得へ進む。検査は保存しない `dry_run` で全発話、元SRT/読み/下書き/PMX対応と30fps衝突を確認する。成功時に発話数、明示無音数、モーフキー数を表示し、その検査版でのみ生成ボタンを有効にする。生成後は `LIP001-<id>.vmd` へのリンクを示す。作品・SRT・PMX対応の変更、読み/下書きの未保存編集では古いリンクと検査結果を消す。未採用かつ実PMX外観の確認が必要と画面に明記した。

候補は作品タイムラインへ自動配置しない。登録・採用、元VMDとの合成、Undo/Redo、統合 `production.lip`、WebMCP/標準MCP、実ユーザー歌音声との同期は続く。元SRT本文・開始終了時刻、元PMX、元VMDは変更しない。

## 実Chrome/実PMX確認

隔離サーバーに登録済み実PMX A（SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`）と関連テクスチャをコピーし、SRT `あい` を画面で登録、読み確定、口形下書き保存した。実PMXの確定MorphMapから画面でdry-run→候補生成→ファイル取得。Three.js MMDParserでモーフ「あ」F30=0.8/F60=0、「い」F60=0.35/F90=0を再読込。**試験内だけ**候補バイトを隔離MMD素材台帳に登録して実PMXへ配置したところ、Chromeプレビューのモーフ値はF30「あ」0.80000001、F60「い」0.34999999、F90「い」ほぼ0となり、F30とF60のキャンバス画素ハッシュが異なった。これを製品の採用・自動配置実装の証拠とは扱わない。

- `node tests/run-guarded.cjs tests/studio-v05-srt-source-ui.test.cjs tests/studio-v05-lip-vmd-export-real.test.cjs`: 隔離Windows Chrome 2/2。PMX対応なしでは検査無効、未保存下書き編集で古い取得リンク非表示。監視対象data 7件・exports 0件のハッシュ一致。元PMX/SRT原本も不変。
