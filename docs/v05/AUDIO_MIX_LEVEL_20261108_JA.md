# プレビューとMP4の混音音量一致（2026-11-08）

順3、Issue #81/#39/#63、AUDIO-001・RENDER-006・DATA-002/008。保存済み配置を使う既存プレビューはHTMLメディアの既定音量1、完成MP4は暗黙amix正規化により無音ベースも含む入力数で減衰し、終了時には残った音が増幅する。今回の範囲はこの出力差の修正。

## 契約

- 各保存クリップの元音量をそのまま加算し、勝手な音源数正規化をしない。音声/楽曲/動画内音声、ミュート、元素材区間・時刻、In/Out、保存の形式を保持する。複数の大きな信号はブラウザー同様に出力範囲でクリップし得る。新リミッター/音量自動調整は追加しない。
- 既存の完成物は再生成/置換しない。修正後に作成する新しい出力だけに作用する。ミキサー/EQはAUDIO-001の明示対象外。行別音量/新規ミキサーは作らない。
- 実際に再生しているChromeメディアをWebAudioへ接続して処理前PCMを採取し、重なり前/中/後の周波数振幅を完成AACのPCMと比較する。OSスピーカー/アンプ/主観聴感とは区別する。

## 受入れ条件

1. 変更前の単独/重なり/終了後で元音量からの減衰をPCMで再現。修正後は安全な合成3周波数（異なるサンプルレート、WAV/MP3/動画内音声）で振幅差3%以内、消した周波数は十分小さい。端のコーデック過渡は避けた窓を用いる。
2. 種類別/全ミュート/解除、保存再読込、非0元素材位置/非0In/29.97fpsでも残る音の音量を変えない。開始後の設定変更は既存のジョブ固定契約どおり。全ミュートはPCM0、映像と原本/クリップは保持。
3. 標準MCP/ネイティブWebMCP/手動UIの既存操作で同じ保存値を使用。Windows実ChromeとUbuntu SDK/FFmpegを区別。実登録音声の隔離複製も出力PCMと照合し原本/index不変。
4. 対象と関連の試験/型検査、台帳/Issue/証拠を更新してmainと8765を同期。Linuxブラウザー/実スピーカー聴感/任意素材の非クリップ保証/ミキサー/順3全体を完成にしない。

モデル区分：高性能（混音方式と計測判断・実装・検証）。

## 検証結果

- 変更前の実測: Chromeの実HTMLメディアをMediaElementAudioSource→ScriptProcessorへ接続して採取したPCMは元音量比0.9997〜1.0001。完成MP4は0.7/2.3/3.2秒で約0.25、4.3秒で約0.333、5.3秒で約0.5だった。無音ベースを含めたamix正規化が原因と一致。
- 修正後: Windows Chrome/公式SDK/ネイティブWebMCP2成功0skip、Ubuntu SDK/FFmpeg2成功0skip。短尺240Fを通常・音声/楽曲/動画各ミュート・全ミュート・解除の6本、非0Inの102Fを1本確認。440/660/880Hz（44.1/48/32kHz、AAC内包MP4/MP3/WAV）の5窓で音量比Windows0.99923〜1.00009、Linux0.99621〜1.00155。全ミュートは全PCM0、解除後の出力hashは最初と一致。元区間0.25秒・クリップ/原本hash保持・再読込を確認。操作はSDK/ネイティブWebMCPと手動ミュートボタン。
- Chrome実再生PCMは通常5窓と各ミュート時の重なり窓を採取。元音量比0.99968〜1.00002。時計補正などで位相が不連続になる場合に長いFFT窓で音量低下と誤認しないよう、3音すべてが整数周期になる50ms窓4個の局所振幅の中央値で比較。OSスピーカー音量・アンプ・聴感は観測していない。
- 実登録WAV230.2秒と登録原MP3見本を隔離複製し、開始1.2秒/元1.1秒/228.5秒の楽曲に10/110/210秒からMP3の2秒片を重ねた。背景232秒、29.97fps/6924F。各OS117安定窓で振幅比±3%以内、相互相関の時刻差0sample/48kHz。Windows0.97014〜1.00063（最小相関0.99744）、Ubuntu0.97988〜0.99871（最小0.99403）。原本/index/配置は不変。
- PythonはWindows28成功+5subtests、Ubuntu28成功。既存ミュート/音声楽曲行/動画行のWindows回帰3成功2任意実データskip。型・差分検査成功。Linuxで最終のChrome計測専用変更は作用しない。

### 途中失敗と再実行

通常制限環境のPythonは一時領域作成前に権限で停止し、実行可能な隔離環境で再実行成功。Linux起動スクリプトのCRLFが試験名へ混入し2回未実行（初回はGit未登録と誤推測してstageしたが原因ではなかった）、LFへ直して成功。長尺試験は背景なしで作品終端を超すIn/Outを要求して1拒否、検証用背景232秒へ揃えて成功。製品の終端拒否は変更していない。並行/単独Chrome採取で長窓FFTの位相相殺と通信時間切れ、全尺先読み待ちの時間切れがあった。局所振幅・シーク完了/短尺の先読みを採用し、長尺の不要な全尺先読みを外して最終2成功。Linux実曲210秒の切替直後は振幅比0.9596となり3%条件に失敗。AAC過渡を避ける契約に沿って安定窓を境界+0.4秒へ変更し、切替直後そのものは未合格として保持する。これらの元ログを納品先に保持。
