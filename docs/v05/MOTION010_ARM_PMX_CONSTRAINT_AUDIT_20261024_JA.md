# MOTION-010 PMX腕IK定義・関節制限の入力監査

2026-10-24、Issue #106。現在の登録PMX 4ファイルを原本のまま読み取り、SHA-256で同一内容のA/Bコピーを除く3モデルを調べた。腕IKはPMXのIKボーンではなく、画面内の3D二関節解で腕・ひじ回転2キーに変換する。PMX自身が腕・ひじ・手首に作用するIKを持つ場合は二重IKや角度制限の不一致が起き得るため、その腕のIK編集を保存APIと画面の双方で拒否する。画面には拒否の理由を表示する。

| SHA-256 | 骨数 | 腕・ひじ・手首 | 腕に干渉するPMX IK | PMX IK角度制限 |
|---|---:|---|---|---|
| `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488` | 201 | 左右あり | なし | 左右ひざ各1 |
| `d67b58016738a6b4de832420fc0411b26cffe90c0b9a3dca9856c74df0fd20e5` | 201 | 左右あり | なし | 左右ひざ各1 |
| `d784722b85991df3a89931ef1066786205f1a9845a7995d611206ecca0bdd841` | 246 | 左右あり | なし | 左右ひざ・足首各1 |

画面の腕ハンドルには、対応PMXに腕IKの角度制限定義がないことと、手先の到達範囲を上腕・前腕の骨長で制限することを表示する。これを解剖学的な肘可動域の検証とは呼ばない。PMX IKのcontroller・effector・linkのどれかが腕・ひじ・手首に一致する場合は、対応理由を示して操作不可にする。保存APIも同じ条件で拒否し、原本・既存キーを保持する。

`python -m pytest -q tests/test_studio_v05_motion_edits.py`は10件成功し、角度制限付き腕IKの合成入力が保存されないことを確認。隔離Chrome/SwiftShaderの201骨・246骨実PMXでは制限説明を画面で読み、左右の実ハンドルと別名VMD物理OFF全骨往復が回帰成功。`npm run typecheck`、Node構文・JSON・diff確認は成功。入力PMXと利用者データのSHA-256は不変。

腕IK角度制限を実際に持つ登録PMXは存在せず、その制限を解く経路は未実装・未検証。固定軸や解剖学的な関節範囲もこの検査からは保証しない。物理ON、実GPU、Linux、標準MCP、候補採用・作品配置、Owner採用も未確認。AC-M-01/02とMOTION-010全体は「要検証」。画像・動画成果物はなくEagle登録対象なし。モデル区分: 入力監査と実装・試験に標準モデル区分を使用。
