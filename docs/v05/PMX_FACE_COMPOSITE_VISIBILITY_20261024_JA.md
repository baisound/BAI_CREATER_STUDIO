# v0.5合成画面でのPMX顔視認性（Issue #96）

## 再現と変更

[三時点の顔検査](PMX_FACE_THREE_POINT_20261024_JA.md)では、保存した口モーフ「あ」が1でMP4の顔画素も変わった一方、既定の合成編集画面では操作パネルが顔を覆い、同じ時刻の画面比較が0画素差になった。単独画面では顔画素差が出ることを確認した。これは保存や描画計算ではなく、重ね表示の操作領域が中央を覆う配置の問題だった。

`studio/v05/js/multi-model-ui-v58.js`の合成パネルを右端の最大320px・ステージ幅38%に収め、高さ上限を82%にしてパネル内スクロールで操作へ到達できるようにした。骨編集から通常表示へ戻るときも同じ寸法へ復帰させる。作品のシーン、モーフ、カメラ、VMDや保存形式は変更しない。

## 実機で確認した範囲

- 実PMXと10秒VMDを用いた隔離Chromeで、合成画面のパネル左端がキャンバス幅59%より右にあり、パネル外の中央を切り出したF120の口形「あ」変更前後に58画素の差が出た。単独画面のF0/F120/F270と各1フレームMP4、6キー保存再読込・頭骨姿勢不変も同じ実行で成功した。`tests/studio-v05-pmx-face-three-point.test.cjs`は1/1成功。
- 既存の実PMX表情キー手動UI試験とGLB合成プレビュー試験は合同2/2成功。細くしたパネルから顔キーの保存・移動・値変更・Undo/Redoへ到達でき、幅900pxのブラウザでもパネルはステージ中央より右、保存視点ボタンへスクロールで到達できた。狭い画面の追加単独実行も1/1成功。
- `npm run typecheck`、変更JSと試験の構文検査、JSON構文と差分検査を実施。実PMX/VMDの原本SHA-256、監視対象の利用者data 7件・exports 0件は各隔離試験の前後で不変。

これらは既定の合成画面と900pxブラウザでの限定結果である。任意モデル・任意カメラ構図で顔を常に隠さない保証、さらに狭い画面、タッチ操作、Linux、Owner採用は未検証。LIP-004/009とUX全体は未完了。
