# MOTION-010 長尺VMDの90秒実補正

2026-10-24、Issue #106。203.633秒の登録済み実VMD `神っぽいな.vmd`（SHA-256 `fa224ad0f7c8af26b5214c4726e0be93ed719d1fcc539b679571761377225189`）と201骨の実PMXを隔離サーバーへ複製した。200秒の同一作品クリップをPMXへ結び、作品60fpsのF5400（90秒）で頭骨に実際のFK補正を入れた。

- v0.5画面の数値入力で頭骨Y回転12°・X位置0.15を仮表示した。頭骨の回転・位置は元姿勢から変化し、センター骨の局所回転・位置は1e-5以内で不変。取消では頭骨が元姿勢へ戻った。
- キー化後、作品別の補正revisionは1、保存キーはF5400・頭骨、位置 `[0.15,0,0]`。保存データが元PMX/VMDのSHA-256を保持した。仮表示と保存後の頭骨局所姿勢、保存後とページ再読込後の頭骨局所姿勢は各成分差1e-5未満。
- `node tests/run-guarded.cjs tests/studio-v05-pmx-fk-long-real.test.cjs`：修正後1件通過、0失敗、0スキップ。`data` 7ファイル・`exports` 0ファイルの前後ハッシュと元PMX/VMDのSHA-256は一致。

初回試験は旧デモタイムラインの `BAIStudioTimeline.seek(90)` を使い、v0.5の保存済みメディア位置が更新されず失敗した。試験を `BAIStudioMediaPreviewV68.seek(5400)` に直した。次の実行では90秒の補正自体は通ったが、隔離サーバーの初期カメラが300フレームで終了し、別系統のカメラ評価がF5400でHTTP 400を4回返した。試験データのカメラ範囲をF12000まで明示して再実行し、HTTPエラーなしで通過した。長尺作品で短い旧カメラプロジェクトを併用するときの境界は別途確認が必要。

この検証は物理OFFの隔離Chrome/SwiftShader、1モデル・1作品の90秒に限る。長尺VMD候補の生成・実PMX往復・採用、物理ON、実GPU、Linux、標準MCP実通信、Owner採用、MOTION-010全受け入れ条件は未確認。画像・動画成果物はないためEagle登録対象なし。モデル区分：試験・文書に標準モデル区分を使用。
