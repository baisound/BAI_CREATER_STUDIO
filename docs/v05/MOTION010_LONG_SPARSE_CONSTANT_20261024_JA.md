# MOTION-010 長尺実VMDの疎な一定補正候補

2026-10-24、Issue #106。元の動く曲線を密キー化で壊さない限定経路を検証した。登録済み `神っぽいな.vmd`（203.63秒、SHA-256 `fa224ad0f7c8af26b5214c4726e0be93ed719d1fcc539b679571761377225189`）と201骨PMX（SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`）を読み取り、頭骨にY12°・X位置0.15の**全区間で一定**の補正を保存した。保存キーは90秒の作品F5400に置いたが、一定補正として全クリップへ適用する。時間限定補正ではない。

既存の `legacy_sparse` 候補方式は、対象骨の元キー時刻と補間データを保って姿勢値だけを変える。前段で判明した隣接30fpsキー挿入による中間姿勢損失を避けられるか、隔離Chromeの独立PMX二体で全骨・全フレームを調べた。作品100秒は6000作品F＋3000 VMD F、作品204秒は12240作品F＋6120 VMD F。後者は元VMD全長を含む。両方とも201骨の物理OFF往復に合格し、最大ワールド位置差 `0.0000017793` MMD単位（右ひざ・作品F3090）、最大回転差 `0.0000261763°`（頭・作品F1954）。許容上限は位置 `0.001`、角度 `0.01°`。候補VMDの非骨区画は元とbyte一致、追加骨キー0、原本PMX/VMDの前後SHA一致。

各隔離作品で候補を明示採用し、同じクリップID・開始時刻・長さを保った配置を読み返し、元VMDへの復元も確認した。候補は検査前には `candidate_requires_real_pmx_validation` のままで、自動採用しない。試験が使う別名候補と採用素材は隔離サーバーの一時データであり、利用者の実作品へは配置していない。

実測に合わせ、実PMX検証の上限を作品12600F・合計19000標本へ引き上げた。超過入力は引き続き間引かず拒否する。`node tests/run-guarded.cjs tests/studio-v05-vmd-long-constant-real.test.cjs` は2件通過、0失敗、0スキップ。隔離ChromeはWindows上のANGLE SwiftShader。守護検査は実データ `data` 7件、`exports` 0件の前後ハッシュ一致を確認。`npm run typecheck` とJS構文確認も通過。

この結果の範囲は、登録済み1種類の実PMX・実VMD、60fps、全クリップ一定の頭FK補正、物理OFFである。**90秒付近だけの時間限定補正は別の密キー境界問題で拒否されたまま**。別PMX/他FPS、物理ON、実GPU、Linux、標準MCP実通信、Owner採用、MOTION-010全ACは未確認。画像・動画成果物はないためEagle登録対象なし。モデル区分：境界判断に高性能、実装・試験・文書に標準モデル区分を使用。
