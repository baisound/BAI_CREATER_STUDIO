# LIP-004 頂点型PMX口モーフの強度候補（Issue #175）

## 計算と画面

口パネルの頂点型モーフだけ、利用者が選んだ基準モーフの移動距離中央値を各モーフの中央値で割り、0〜1へ制限した候補を示す。計算をNode解析とv0.5画面で共用する。比が1を超えた場合は上限への丸めを表示する。グループ型・無変位型・非頂点型は `manualRequired` とし、候補を出さない。画面ではA/I/U/E/Oの選択済みモーフに候補を表示し、明示した「候補を重みに入力（未確定）」だけが頂点型の重み欄を変更する。入力は0.01刻みで、下書き保存も確定も自動では行わない。候補は形状の尺度の目安であり、自然さは実プレビューと利用者判断を要する。

## 試験

`BAI_REAL_MMD_DATA` 指定の `node --test tests/pmx-morph-analysis.test.mjs` は人工・実PMXで2/2成功。実PMX A（SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`）の「口上」中央値0.09341278を基準に「口下」中央値0.18191308との比を照合し、グループ型「あ」は候補nullとした。人工データでは上限丸めも確認。実PMX Bは口モーフ0件。

`node tests/run-guarded.cjs tests/studio-v05-pmx-morph-analysis-ui.test.cjs` は隔離Chromeで1/1成功。実PMX Aの画面でA=口上、I=口下、U=グループ型「う」として候補1.000/約0.51/手動確認を表示し、明示入力でA=1、I=0.51、Uの既存重みを保持した。その時点のMorphMap revisionは0で自動保存なし。その後、既存のグループ母音の一時プレビュー・手動重み保存・再読込・原本hash失効を通した。Bの口モーフ0件では候補計算不可。元PMX A/B、監視実データ7ファイル・exports 0ファイルのハッシュは前後一致。型チェック、JS/JSON構文、差分検査も成功。
