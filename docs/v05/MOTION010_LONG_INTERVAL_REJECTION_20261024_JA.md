# MOTION-010 長尺の動く元VMDに対する区間候補の拒否

2026-10-24、Issue #106。203.633秒の実VMD `神っぽいな.vmd` を使い、90秒F5400の頭骨FK補正を保存した後、別名VMDを約2秒の修正区間だけで作れるか隔離環境で調べた。

- 元VMDの頭骨にはVMD F2669とF2732に実キーがある。作品60fpsの区間をF5338〜5463、VMDの半開区間を `[2669,2732)` とし、前後各2作品フレームのなじませを設定した。候補生成の対象骨は頭だけ、書き換え予定のVMDキーは62件。区間外の元骨レコード26,845件、作品12,000F、元VMD6,110Fを比較対象にした。
- `mode: interval` の候補生成はHTTP 422で拒否した。報告された最大位置差は `0.07499784307626885`（作品F5463）、最大角度差は `6.07363381162536°`（作品F5339）。区間外を含む全時刻の最大角度差も `0.031324697951665724°`。いずれも位置1e-3 MMD単位、角度0.01°の受け入れ上限を超える。元曲線と60fpsなじませを30fps候補へ安全に再現できない入力として扱う。
- 候補ID・候補ファイルは作られず、作品の補正revisionは区間設定後から変わらなかった。元PMX/VMDのSHA-256、`data` 7ファイル・`exports` 0ファイルの前後ハッシュは一致。
- `node tests/run-guarded.cjs tests/studio-v05-pmx-fk-long-real.test.cjs` は1件通過、0失敗、0スキップ。試験はHTTP 422、区間・比較フレーム数、候補ファイル不在、補正revision不変を明示的に検査する。

この結果は長尺の実補正プレビュー・保存が可能でも、この動く元VMDの区間候補は現在の方式では合格できないことを示す。別名VMDの採用・書き出し品質は未達。曲線を保った密キー化などの修正は別の実装・実PMX往復ゲートが必要。画像・動画成果物はないためEagle登録対象なし。モデル区分：試験・文書に標準モデル区分を使用。
