# MOTION-010 実PMX膝ポールの解法・保存設計

2026-10-24、Issue #106。対象はv0.5のPMX＋VMD骨編集。承認済み[リグ編集仕様](../roadmap/RIG_EDITING_SPEC_20261020_JA.md) §2.2–2.3と[詳細設計](../roadmap/MOTION010_V05_DETAILED_DESIGN_20261024_JA.md)段階Bを具体化する。ポール操作はまだ実装済みとしない。

## 1. 実素材と現行ソルバーの確認

対象の実PMXでは左右足IKが各2リンクで、膝リンクはX曲げ0.5°〜180°、Y/Z固定に変換される。Three.jsの現行`CCDIKSolver`はこのリンク制限を使うが、独立したポール目標の引数は持たない。そのため、膝のマーカーを動かすだけでは次のフレームや別名VMDに膝方向を残せない。

隔離Chrome/SwiftShaderの[再現試験](../../tests/studio-v05-knee-pole-feasibility-real.test.cjs)で、実VMDを再生する作品F240の左足骨にY回転差分を±20°仮入力した。膝の世界位置は基準からそれぞれ0.00872/0.00737シーン単位変わり、両方向間は0.01を超えた。左足首の基準差は0.000184、IK目標との残差は0.000184、右足首の差は0。仮補正を取り消すと作品revisionは0のままだった。

同じ+20°を作品キーとして保存し、既存の別名VMD候補と独立PMXの全骨検査へ通した。物理OFFの作品600F＋VMD300F、201骨で、最大位置差3.669e-8シーン単位、最大角度差4.012e-5°となり、閾値を満たした。候補は未登録・作品未配置。`run-guarded`の利用者`data/`と`exports/`、試験内の元PMX/VMDハッシュは前後一致。これは**このPMX・このVMD・このフレームの太もも回転差分**がポール方向の保存媒体になれる証拠であり、任意PMXに対する普遍的な解法の証明ではない。

## 2. ポール操作の契約

1. 対応するPMX足IKは、実IK定義が1つだけのターゲット・足首・膝・太ももの親子2リンクで、膝に有限な角度制限がある場合に限る。標準名だけで解法を選ばず、骨階層とIK定義を検査する。未対応は操作不可と理由を表示する。
2. FK→IK編集方法の切替時には、ポールの表示位置を**同フレームで評価した膝の世界位置**へ置く。切替だけでキーやUndo、骨姿勢を変えない。ハンドルは撮影/MP4へ写さない。
3. ユーザーのドラッグ先は股関節から足首目標へ向かう軸に垂直な平面へ投影し、膝の向きだけを指定する。股関節・足首・膝がほぼ一直線で方向を定義できない場合、ゼロ移動、投影不能、非有限値は保存せず理由を出す。
4. 解く値は現在の元VMD＋下位レイヤーからの**太もも局所回転差分**。PMXのCCDを毎回同じ順序で評価し、候補角を探索して膝方向の角度誤差を最小にする。±20°を固定変換式にしない。複数解がある場合は現在の差分に最も近い候補を選び、単調でない・到達差が悪化する場合は拒否する。膝の制限値を緩めない。
5. マウスを離すまでは未保存プレビュー、`Esc`は完全取消。確定時は既存の同作品・同インスタンス・同クリップ・同F・同レイヤーの太もも回転チャネルへ渡し、位置と他骨のキーを保持する。オートキーOFFの既定では明示的な［このFをキー化］まで保存しない。1操作は最大1 Undo。
6. 仮表示後に実骨世界位置で膝方向誤差、足首目標残差、未編集側の姿勢差を測る。膝方向が目標へ近づかない、足首残差が1e-3を超える、未編集側が1e-4を超えて動く、保存再読込または別名VMD実PMX往復が閾値を超える場合は成功扱いせず、候補を採用しない。

## 3. 次の実装ゲート

- 純粋な幾何関数で軸投影と有向角を定義し、ゼロ長・直線姿勢・符号反転・左右対称を試験する。
- 実PMXで膝ハンドルを現姿勢へスナップし、実ポインタの両方向ドラッグ、Esc、足首/右脚不変、保存・Undo/Redo・再読込を確認する。ドラッグ中のPMX姿勢更新がない間は画面にその制限を明示する。
- 保存済みポール由来の太ももキーを別名VMD候補に焼き込み、物理OFFの全骨・全作品F・全VMD Fを比較する。密な元VMD曲線や物理フラグが安全に保てない入力は従来どおり拒否する。
- 別PMX・別VMD、左右脚、物理ON、実GPU、Linux、MCP入口を個別に検証するまでAC-M-02とMOTION-010全体は「要検証」。

モデル区分: ソルバー構造の調査、実素材検証、設計と試験の定型実装まで標準モデル区分を使用。画像・動画の成果物はなくEagle登録対象はない。
