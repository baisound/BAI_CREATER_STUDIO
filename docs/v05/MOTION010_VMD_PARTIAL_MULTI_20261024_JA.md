# MOTION-010 部分VMDの複数区間と境界キー欠落

2026-10-24、Issue #106。修正区間だけの別名VMD候補について、骨ごとに複数の異なる補正区間を扱う計算を追加した。VMD30fpsへ正確に写せる区間を骨別に結合し、各区間の `[開始, 終了)` 内だけにキーを作る。区間外の元骨レコードと非骨区画はbyte一致を必須にする。境界の元キーが無くても、追加キーによる元動作の変化が誤差上限内なら候補を認める。既存の開始キーに補正が残る入力、30fpsに一致しない端、作品・VMD全時刻の姿勢差が位置1e-3 MMD単位または回転0.01°を超える入力は、候補作成前に拒否する。

挿入キーは区間外の元キーを変更しなくても、その前後の補間を変え得る。そこで、局所骨姿勢を作品の全フレームと元VMDの最終骨キーまでの全30fpsフレームで検査する。Three.jsの境界ベジェ近似も計算に含める。実PMXのIK/grant後は独立したブラウザ検査で全骨を確認し、このVMD時刻の検査範囲と採用レポートの範囲を一致させた。原本素材と採用前の作品配置は変更しない。

## 残る条件

現行の保存API/画面は同一クリップに一つの補正レイヤーしか作れない。複数区間は計算器の単体試験のみで、画面から複数レイヤーを作り実PMXで往復した証拠はない。動く元曲線の境界欠落は拒否する入力があり、万能変換ではない。物理ON、実GPU、Linux、標準MCP、Owner採用、MOTION-010全ACは未確認。画像・動画の納品成果物はなくEagle登録対象なし。モデル区分: 設計・実装・試験・文書化に標準モデル区分を使用。
