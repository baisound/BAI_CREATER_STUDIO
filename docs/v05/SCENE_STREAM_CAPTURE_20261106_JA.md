# 長尺3Dの逐次キャプチャ（2026-11-06）

対象: v0.5順3、Issue [#81](https://github.com/baisound/BAI_CREATER_STUDIO/issues/81)/[#39](https://github.com/baisound/BAI_CREATER_STUDIO/issues/39)、`RENDER-001/006`、`AUDIO-001`。

## 設計と制約

従来は720pのPNG全量を256MiBまで保存し、3Dを600Fへ制限していた。今回、同じブラウザ・作品・時計で描いたPNGを1枚ずつFFmpegの標準入力へ渡し、透過を保持するFFV1/BGRAの可逆動画へ変換する。PNG書込みの完了を待って次へ進むため、描画側の未処理バッファはフレーム数に比例して増えない。途中でブラウザを開き直したり、PMXの動作を区間ごとにリセットしたりしない。

上限は720p・36,000F・10分・可逆動画2GiB。FFV1 encoderがない環境では3Dの利用可否をfalseにする。2GiB超過・キャプチャ/エンコード失敗・タイムアウトでは両子プロセスを終了して待ち、一時動画を削除する。OSによるサーバー強制終了からの自動再開は今回追加しない。再起動時の既存interrupted表示を維持し、その場合の一時領域回収は未検証である。

可逆動画を再読込し、codec・BGRA透過形式・寸法・全フレーム数を照合してから2D/音声と合成する。Matroskaの時刻丸めを引き継がないよう、合成時はフレーム番号と作品FPSから時刻を作り直す。途中編集のrevision照合と原素材hash、別名MP4の確定前再読込、旧完成物保持を維持する。描画manifestのPNGハッシュ列と可逆動画のhash/容量を記録する。PNG原本列はディスクへ保存しない。

## 試験契約

- `tests/studio-v05-scene-long-mp4.test.cjs`: 非0開始の720F、透過3Dと画像背景、完成MP4の先頭・末尾、途中編集による失敗・一時領域削除・既存MP4保持。
- `tests/studio-v05-real-song-600f.test.cjs`: `BAI_REAL_RENDER_FRAMES`で600〜13,800Fを指定し、実PMX/VMD/WAVを隔離コピー。保存再読込と開始・中間・終了のプレビュー、完成MP4全フレーム数と映像差、原WAVと完成音声の時刻を照合する。
- 2D/動画内音声の媒体出力試験、保存範囲と完成物版管理のPython回帰、構文・型検査を実行する。

## 未検証

上限36,000F/10分と2GiB境界そのもの、異なるFPS・音声サンプルレート、動画内音声と実曲の重なり、ステージを含む長尺保存カメラ、時刻付きカメラ、物理の長尺品質、Linux、実MCPクライアント、サーバー強制終了時の子プロセスと作業領域回収。今回の結果で順3全体を完成扱いにしない。

## PR #239の停止処理レビュー

タイムアウト時のNode強制停止だけではChromeが残り得るため、Windowsは所有する描画PID配下をtaskkill /Tで回収し、POSIXはPlaywrightのSIGTERM処理でブラウザを閉じる方式に修正した。Windowsの実親子プロセスを起動するpytestが1成功。720F出力と途中編集時の停止・旧完成物保持も再試験する。Linuxとサーバー自体の強制終了からの回収は未検証のまま。
