# LIP-001 元VMDとの合成候補を製品APIと画面へ接続（Issue #187）

## 実装した範囲

[比較ゲート](LIP001_COMPOSITE_FRAME_GATE_20261025_JA.md)を、作品の中で選んだ入力につないだ。設計は [A1実装設計 §4.1](../specs/A1_LIP_IMPLEMENTATION_DESIGN_JA.md)。

- **入力**: 場面インスタンスに割り当てた `ready` の登録VMDクリップ1本（MOTION-010と同じ判定）、同インスタンスの採用口形（`lip/adoptions`）、同インスタンスの手動表情キー（シーン保存の `face_keys`）。口形採用・シーン・タイムラインの3つのrevisionが現在値と違えば409。
- **拒否**: 採用口形の失効は409 `adoption_stale`。30fps VMDで画面と同じ値を再現できない時刻（不連続）は422 `discontinuity` とし、モーフ・時刻・期待値・実値を返す。発話区間や手動キーがクリップ範囲外、合成するキーが無い場合も422で理由を一覧にする。開始0秒以外・非整数FPSは2026-11-05から受け入れる（末尾の追補を参照）。黙って切り捨てない。
- **書き出しと読み直し**: `POST /api/studio/v05/lip/composite-candidate`（`dry_run` あり）。別名の新規ファイル `data/studio_v05_lip_composite_candidates/<作品>/<ID>.vmd` を作り、書いたファイルを読み直す。照合内容は、SHA-256、元VMDの骨・補間・カメラ等の区画のバイト一致、対象モーフの全キー（float32）、対象外モーフの全キーのバイト一致。ダウンロード名は `LIP001-COMPOSITE-<元VMD名>-<ID先頭8桁>.vmd`。
- **失効の検査**: `GET .../composite-candidate/file` を受けるたびに、現在の作品状態で合成し直す。元VMD・モデル・採用候補・手動キーのハッシュ、または出力バイトが違えば409で配らない。
- **画面**: v0.5のSRT欄、「作品の3Dモデルへ口形を採用」の下に「元の動作VMDと合成した別名VMD候補」を置いた。対象モデルのVMDクリップを自動で選び（1本だけのときに限る）、最新のrevisionで作成する。結果のリンクか、作れない理由の一覧を表示する。
- 元VMD・PMX・SRT・採用台帳・シーン・タイムラインは書き換えない。作品への配置、素材登録、MP4への反映もこの段階では行わない。

## 境界の平滑化（2026-11-04、所有者決定）

- 曲線の形は [A1実装設計 §4.1](../specs/A1_LIP_IMPLEMENTATION_DESIGN_JA.md) の「口形の開始・終了の曲線」。30fpsの整数VMDフレームでは従来の値、その間は直線。境界をまたぐ1区間（1/30秒）だけが傾きになる。30fps VMDで正確に再現できるので、元VMDの値と採用口形の値が合わない境界でも合成候補は成功する。
- Python合成（`studio_v05_lip_vmd_composite._lip_base`）、3D表示とプレビュー/MP4撮影（`applySavedFace` → `evaluateLipCueTracks`）が同じ規則を使う。画面は境界の区間だけ元動作を前後の整数フレームへシークしてモーフ値を読み、表示時刻へ戻してから当てる。
- 本物の不連続は引き続き422。手動表情キーは平滑化しないため、VMDフレームの間の手動キーや、傾きの途中で切り替える手動キーは拒否する。
- 作品FPSが30以外のとき、傾きは作品の1フレームではなくVMDの1フレーム（60fpsでは作品の2フレーム、24fpsでは0.8フレーム）。作品の1フレームちょうどの傾きは30fps VMDで表せないため。
- 試験:
  - `tests/test_studio_v05_lip_vmd_composite.py`: 24/30/60fpsで、元0.2・採用0.8の急な開始と途中で切れる終了が成功し、F29=0.2・F30=0.8・F29.5=0.5になること。1フレーム未満の間隔で元の値へ戻らないこと。傾きの途中の手動キーは拒否されること。Python・画面の評価関数・書き出したVMDの3つの曲線が、作品の全F・VMD中間F・1/4F点で一致すること（元の口が動く場合を含む）。
  - `tests/test_studio_v05_lip_composite_candidate.py`: 口を閉じたままの元VMDで、1.0秒に0.8へ開くSRTを採用して、HTTPで候補が書き出され、全キー読み直しに通ること（以前は422）。そこへ1.0秒の手動0キーを足すと422 `discontinuity` になること。
  - `tests/studio-v05-lip-boundary-ramp.test.cjs`: `applySavedFace` を取り出して、元動作の前後フレームの値を読んで表示時刻へシークし直すこと、3D表示（`seekScene`）とMP4撮影（`captureFrame`）が同じ関数を通ること。
- 未検証: 実PMXでの見た目、実歌音声SRTでの境界の自然さ、採用口形を含む完成MP4、実長尺VMDでの合成候補。

## 2026-11-05 追補：作品時刻が0以外のクリップと非整数FPS

- クリップ開始時刻を元VMDの局所0秒へ写す。SRT発話と手動表情キーは作品時刻で評価し、候補VMDは局所30fpsフレームへ書く。候補の記録へ `clipStart` と `clipDuration` を含め、取得時に現在の配置と照合する。
- 作品F、VMD中間F、クリップ開始と終了直前、作品30fps格子の境界、手動キー直前を比較する。非整数FPSでも合成可能な曲線は受け入れる。開始位置がVMD格子の間にあり、候補で画面と同じ値を再現できなければ422 `discontinuity`。発話・手動キーがクリップ外にある場合も422のまま。発話終了がクリップ終端と重なる場合は、画面の元動作が終端で0へ戻ることも局所VMDへ反映する。
- 隔離HTTP試験で開始1秒・29.97fpsの作品から候補を作成し、読み戻し・ダウンロード・原VMD不変を確認。Pythonとブラウザ評価関数を23.976/29.97/59.94fpsで比較し、ずれた格子で再現不能な開始位置も拒否を確認。実VMD原本を読み取り専用で与えた対象試験は22件成功。隔離Chromeの画面/境界試験も4件成功。実PMXの見た目、完成MP4、実歌声SRT、LinuxとMCPは未検証。
