# LIP-001 元VMDとの合成候補を製品APIと画面へ接続（Issue #187）

## 実装した範囲

[比較ゲート](LIP001_COMPOSITE_FRAME_GATE_20261025_JA.md)を、作品の中で選んだ入力につないだ。設計は [A1実装設計 §4.1](../specs/A1_LIP_IMPLEMENTATION_DESIGN_JA.md)。

- **入力**: 場面インスタンスに割り当てた `ready` の登録VMDクリップ1本（MOTION-010と同じ判定）、同インスタンスの採用口形（`lip/adoptions`）、同インスタンスの手動表情キー（シーン保存の `face_keys`）。口形採用・シーン・タイムラインの3つのrevisionが現在値と違えば409。
- **拒否**: 採用口形の失効は409 `adoption_stale`。30fps VMDで画面と同じ値を再現できない時刻（不連続）は422 `discontinuity` とし、モーフ・時刻・期待値・実値を返す。クリップ開始が0秒でない、作品FPSが整数でない、発話区間や手動キーがクリップ範囲外、合成するキーが無い場合は422で理由を一覧にする。黙って切り捨てない。
- **書き出しと読み直し**: `POST /api/studio/v05/lip/composite-candidate`（`dry_run` あり）。別名の新規ファイル `data/studio_v05_lip_composite_candidates/<作品>/<ID>.vmd` を作り、書いたファイルを読み直す。照合内容は、SHA-256、元VMDの骨・補間・カメラ等の区画のバイト一致、対象モーフの全キー（float32）、対象外モーフの全キーのバイト一致。ダウンロード名は `LIP001-COMPOSITE-<元VMD名>-<ID先頭8桁>.vmd`。
- **失効の検査**: `GET .../composite-candidate/file` を受けるたびに、現在の作品状態で合成し直す。元VMD・モデル・採用候補・手動キーのハッシュ、または出力バイトが違えば409で配らない。
- **画面**: v0.5のSRT欄、「作品の3Dモデルへ口形を採用」の下に「元の動作VMDと合成した別名VMD候補」を置いた。対象モデルのVMDクリップを自動で選び（1本だけのときに限る）、最新のrevisionで作成する。結果のリンクか、作れない理由の一覧を表示する。
- 元VMD・PMX・SRT・採用台帳・シーン・タイムラインは書き換えない。作品への配置、素材登録、MP4への反映もこの段階では行わない。

## 検証（隔離データ・合成素材）

- `tests/test_studio_v05_lip_composite_candidate.py`（HTTP、1件）。合成PMX（`tools/make_test_pmx.py`）と、骨2・別モーフ2・カメラ1を持つ合成VMDを使った。
  - 確認したこと: 余分な項目の拒否、revisionの食い違い（409）、dry-runでファイルを作らないこと、全91F×1モーフと対象外2キーの読み直し。
  - 区画と値: 骨・カメラ区画は元とバイト一致。F30=0.8（採用口形）、F75=0・F84=0.3・F90=0.5（手動キー）。
  - 拒否: 0.5秒の手動0キー（VMDフレームの間で値が跳ぶ）、クリップ範囲外の手動キー、開始1秒のクリップ、読みの変更による採用の失効。
  - 候補の失効と復帰: 入力が変わると候補は409になり、元に戻すと再び200で取得できる。
  - 原本: 元PMX・VMD・SRT、作品の各保存ファイルのSHA-256は前後で同じ。
- `tests/studio-v05-lip-composite-ui.test.cjs`（隔離Chrome、1件）。画面だけで次を通した: SRT取込→読み確定→下書き→モーフVMD候補→採用→合成候補作成→リンクのダウンロード。
  - 照合: Three.js MMDParserで91キーを読み、F45=0.4・F90=0.5。
  - 拒否: 不連続キーを追加すると、画面に「再現できない」と表示し、旧候補の取得は409。元VMD・PMXはバイト一致。
- pytest全体: 基線（変更前のmain）は失敗1・成功607・スキップ21、変更後は失敗1・成功608・スキップ21。残る失敗1件 `test_v05_timeline_drag_static` は、タイムラインのドラッグ処理を文字列で照合している試験で、ソース側の引数が増えたため一致しなくなったもの。#187とは無関係で、変更前から失敗している。
- `npm run typecheck` は成功。`tests/studio-v05-srt-source-ui.test.cjs` も成功。

## 未検証・制約

- 実PMX・実長尺VMDでの合成候補、元VMDとの顔・身体の見た目の比較、最終MP4への反映、実歌音声SRTの境界品質。
- WebMCP・標準MCPのツールは未作成（LIP系は全体でMCP未接続）。Windowsでの実行。
- **既知の制約**: SRTから作る口形候補は、発話の開始で重みを跳ね上げ、終了で0にする。元VMDの同じモーフの値が開始・終了の時刻でこれと一致しない限り、30fps VMDでは画面と同じ値を作れず、拒否される。現実の素材では多くの場合拒否になる見込み。境界に1フレームの傾きを付けるか、許容差を変えるかは所有者の判断が要る（画面の優先表示の規則も変わるため、承認なしに変えない）。

モデル区分: 設計確認・実装・試験とも高性能モデル（Opus）で一括実施（委任された単一作業のため切替なし）。
