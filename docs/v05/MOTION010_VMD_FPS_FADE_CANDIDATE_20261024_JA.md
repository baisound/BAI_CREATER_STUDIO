# MOTION-010 24fps作品と前後なじませの別名VMD候補

2026-10-24、Issue #106。作品24fpsのFK補正をVMD30fpsへ写し、有効区間 `[48,192)` 作品フレーム、前後24フレームのなじませを含む候補を実PMXで検査した。元VMD/PMXは読み取り専用で、候補は別名の検証前ファイルに留める。

終了直前の30fpsキーを無条件に足すと、補正値がほぼ0でも元VMDの回転曲線を分断する。実VMDの計算では作品F173付近で最大`1.67°`の角度差が生じ、誤差ゲートが候補を拒否した。境界キーは補正の局所位置が`5e-4` MMD単位または角度が`0.005°`を超える場合だけ追加する。なじませの始端・終端と重み変化の折点は30fpsへ標本化し、**全作品フレームの誤差判定を最終条件**とする。これにより不要な境界キーを省き、区間前に補正が先走ることも防いだ。すべてのソース曲線や任意FPSで合格するという意味ではなく、閾値を超える入力は拒否する。

## 検証

- 実VMDを使うPython試験を含む`32件成功`。24fps・前後なじませ条件の局所位置最大差`0.0005084746283621098` MMD単位、角度最大差`0°`。区間始端が移動中の元VMD曲線を分断する別条件は角度最大差約`1.71°`となり、候補を拒否することも確認。元VMDの非骨区画と未編集骨、原本を保持した。
- 隔離Chrome/SwiftShaderで実PMXの原VMD＋補正と別名候補を全240作品フレームで比較した。頭骨のワールド位置最大成分差`0.0000406779702689688`、四元数成分最大差`2.9771038634329727e-8`。候補APIの読み戻しバイト一致と作品FPS設定を確認した。
- 60fps・頭FK/左足IKの既存隔離試験も再実行し、全600作品フレームで従来の位置差を維持した。両ブラウザ試験とも利用者`data/`7ファイルと`exports/`0ファイルの前後ハッシュ一致。原PMX SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、原VMD SHA-256 `3ae724f9d1d36a7e74a911d6b1bbfad7d2459e5e256fcac43521ebebd0a3d234`は不変。
