# MOTION-010 / CAM-015 旧カメラ撮影プレビューとMP4の接続差

2026-10-24、Issue #106。v0.5の旧カメラ撮影プレビューは保存済み `camera_project.json` を秒数で評価し、前段で実PMXのカット画素差まで確認した。一方、限定MP4は `tools/render_v05_scene_frames.cjs` から `BAIStudioMultiScenePreview.captureFrame()` を呼び、そのビューワーの `sceneSnapshot.camera` または自動構図カメラを使う。旧カメラのショット列はこの書き出し経路の入力に含まれていない。これはコードからの経路推定であり、次の隔離出力でも確認した。

実PMX `Baisound-New-V5.0.0-B_新狐面差替_紐鈴物理_調整v6.pmx`（SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`）を保存済みシーンへ配置し、同じ1フレーム範囲を2回720p MP4へ出力した。間に隔離旧カメラ原本の位置Xを0→5へ変更し、カメラAPIが新位置を返すことを確認。旧カメラのSHAは `e4ddd7f30c3ba375190680b4ebfdba925f4a7424e5ef30b15ea0fd816b8825da` → `175c8c5cb29cb8f1531ddcda3ff7a952fe09bbeadac9368445a23b19e67e0cc7`。それでもMP4から復号した320×180の画素差は0、画素SHAは両方 `9f57cc8d0e4e4542571b043ed1bb882e1b3f5ce584b995f42636499bc763291e` だった。両ジョブは実PMX1体・1フレームを描画し、NVIDIA GeForce RTX 4070 SUPERを報告した。実PMX原本SHA不変、隔離一時データはテスト終了時に破棄した。

この結果は、**旧カメラの撮影プレビューに見えるカットが現在の限定MP4へ自動反映されない**ことを示す。既存の保存済み3Dシーンカメラは別経路でMP4へ使われるため、その選択を曖昧に上書きしない。旧カメラと3Dシーンカメラのどちらを作品・書き出しに使うか、保存・画面表示・API・revisionと原本保持をそろえるCAM-015の接続設計が残る。今回この選択UIやMP4経路は変更していない。旧カメラのカット編集UI、任意構成、物理ON、Linux、標準MCP実通信、Owner採用、MOTION-010/CAM-015全ACも未確認。

一時MP4は比較検証用で納品成果物ではなく、Eagle登録対象なし。モデル区分：経路調査・隔離検証・文書に標準モデル区分を使用。
