# MOTION-010 別名VMDの骨区画を非破壊で書く基盤

2026-10-24、Issue #106。段階Cの基盤として`studio_v05_vmd_rewrite.py`を追加した。呼び出し元が用意した**VMD座標系の完成骨サンプル**だけを既存レコードへ置換または新規レコードとして追記する。原VMDを読み取り専用にし、未編集の骨レコードと骨区画後のモーフ・カメラ・照明・影・IK等のbyte列をそのまま保持する。別名出力が既にあれば拒否する。

ヘッダー、CP932のモデル名・骨名、重複骨フレーム、非有限値、四元数、件数、切断を検査し、生成ファイルを既存の`vmd_readback.py`で読み直す。生成結果は`binary_only_requires_real_pmx_roundtrip`と明示し、この基盤単体をv0.5のVMD出力UI・完成VMDとは呼ばない。出力は256MiB以下の入力に限定する。

## 試験と確認範囲

- `python -m pytest -q tests/test_studio_v05_vmd_rewrite.py tests/test_v0163_vmd_readback.py`: 15件成功。既存/新規骨レコード、原本SHA-256、未編集骨・非骨suffixのbyte一致、同名出力拒否、異常入力を確認。
- 実VMD`狐面物理確認用_頭振り_F000-0300.vmd`の1骨レコードを隔離一時先へ別名出力し、原本SHA-256と非骨suffix一致、骨件数の再読込を確認。元データの出力ディレクトリへは書いていない。
- `python -m py_compile`と`git diff --check`成功。初回のpytestは既定TEMPへの権限で開始できず、作業ツリー内の隔離TEMPへ切り替えて上の件数を完走した。

手元の長尺`キラメキのシンフォニー1005.vmd`は20 byteモデル名の末尾でCP932の文字が切れているため、厳格な既存読込器が拒否する。名称を勝手に修復して元VMDや非骨データを書き換えない。別の正常な実VMDを使って補正キーのサンプリングとPMX往復を進める。
