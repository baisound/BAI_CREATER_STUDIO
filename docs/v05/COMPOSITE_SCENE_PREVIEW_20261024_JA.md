# v0.5 保存済み3Dと画像・動画の同画素プレビュー（Issues #63/#69）

2026-10-24。作品の登録画像・動画を表示する編集ビューに、同じ作品で保存済みの3Dシーンを透明なWebGLキャンバスとして重ねる。「同じ作品の3Dを画面に重ねる」から開く。従来の3D単独画面もモード切替で保持する。3D、画像、動画は既存の作品フレーム操作を共有し、シーク・再生・停止・再読込・作品切替に追従する。元の素材、配置時刻、シーン変換は変更しない。連続したシークでは、前の保存応答が遅れても入力中のフレーム値を上書きしない。

## 検査

- Windowsの隔離Chrome/SwiftShaderで、登録画像WebP、登録動画MP4、保存済みGLBシーンを同一作品に配置した。画像の画面に3Dを重ねた前後の884×350スクリーンショットを画素比較し、中央領域で38,497画素が変化、左下角の平均差は0。WebGLの不透明背景が画像を覆っていないことを確認した。F60で画像と3D、F150で動画と3Dを同じ編集枠に表示し、動画の元素材位置0.5秒を確認した。
- 作品再読込後もF60と同じシーンIDを確認。既存の3D＋WAV共通時計・失敗表示、HOME再生位置、画像/WAV/MP4プレビューの隔離Chrome試験も合格。F150→F60の連続シークで編集中の入力値を保持した。`run-guarded` で元の `data/` 7ファイルと `exports/` のハッシュは前後一致。
- 型検査、JS構文、JSON構文、差分検査を実行。現行のChromeはSwiftShaderであり実GPUの合格とはしない。実PMX/VMDの骨・画素差は先行PR #87で別画面を確認済みだが、実PMXと画像・動画の同画素合成は未検証。

これは編集画面の限定プレビュー接続。3Dを含むMP4書き出し、カメラ・照明・字幕・内包動画音声の統合、実GPU、Linux、MCP、長尺の映像音声同期は未接続・未確認。`DATA-008` とロードマップ順2/3の全体を完成扱いしない。
