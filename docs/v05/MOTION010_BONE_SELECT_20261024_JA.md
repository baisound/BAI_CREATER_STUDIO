# MOTION-010 実PMX骨の階層選択と3Dマーカー

2026-10-24、Issue #106。v0.5の既存3D編集画面に、読み込んだPMXの実骨階層を深さ付きで表示し、名前検索と画面上の骨マーカーから既存のFK数値欄へ対象骨を渡した。骨を選ぶだけでは姿勢も作品データも変更しない。元PMX/VMDのスキニング・ウェイトには触れない。

## 変更

- 選択中のPMXインスタンスの実スケルトンから骨名と親階層の深さを読む。リストと3D表示は同じ骨を参照する。名前検索時は該当骨を最大12個までマーカー表示し、通常は選択骨だけを表示する。
- 同名骨は名前だけでは一意に保存できないため、階層リストとFK選択欄で編集対象から除外する。モデル選択、既存FKキー選択、フレーム移動、カメラ移動、3D画面の閉じ直しに表示を追従させる。
- 合成プレビューで操作欄がマーカーを覆う位置では、操作欄の下へ矢印付きで移動表示する。撮影・MP4のキャプチャ画面にはリストとマーカーを作らない。

## 試験

`tests/studio-v05-pmx-fk-edit-real.test.cjs`を拡張し、実PMX＋実VMDで階層リストの「センター」と頭骨の画面マーカーをクリックした。両方とも既存FK選択欄へ同期し、選択前後の頭骨の四元数差は1e-5未満だった。続けてFKの仮表示・保存・再読込・Undo/Redo、撮影モードのマーカー不在、原本ハッシュを検査した。

最終実行は`BAI_REAL_MMD_DATA=<既存data>`、`CHROMIUM_PATH=<Chrome>`、`BAI_TEST_CONCURRENCY=1`で`node tests/run-guarded.cjs tests/studio-v05-pmx-fk-edit-real.test.cjs`が1/1成功。`npm run typecheck`、JS構文、`git diff --check`も成功。Chromeの描画器報告はSwiftShader。元PMX SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、元VMD SHA-256 `3ae724f9d1d36a7e74a911d6b1bbfad7d2459e5e256fcac43521ebebd0a3d234` は前後一致。`run-guarded`で利用者`data/`7ファイルと`exports/`の前後ハッシュも一致した。

途中で3Dマーカーが合成画面の操作欄の下に隠れ、クリックできない失敗を検出し、移動表示で解消した。別の再実行では画面再読込中に隔離試験サーバーへの接続拒否が出た。試験の再読込前に3D画面を明示的に閉じて実PMXを解放する手順へ修正し、最終回帰を通した。接続拒否の発生条件は未特定。
