# LIP-001 元VMDのモーフ区画だけを書き換える基盤（Issue #187）

## 対象と契約

VMD 0002 の元バイト列を読み、指定したモーフキーの追加・置換・削除だけを別のバイト列として生成する。骨キーと補間、モデルヘッダー、カメラ・照明・セルフシャドウ・IK表示の区画はバイト単位で保持する。元ファイルへの書き込みは行わない。未知の末尾、重複モーフ、範囲外の値、未定義の削除対象は拒否する。再読込後のモーフキー、非モーフ区画のハッシュ、件数を照合する。

この関数は合成VMDの安全な書き出しに必要なバイナリ基盤であり、元VMD・採用口形・手動表情を時間上で合成する製品経路はまだ接続していない。特に原SRT境界の60fps表示を30fps VMDキーで正確に表現できるかは別の比較ゲートが必要。バイナリ再読込だけで実PMXの同等描画と判断しない。

## 検証

- 人工VMDの骨、補間、カメラ、照明、セルフシャドウ、IK表示を保持したままモーフを追加・置換・削除し、未知末尾と存在しない削除対象を拒否した。
- 既存のモーフ専用候補が持つ既知の空の追加末尾も保持した。
- 実 `神っぽいな.vmd` の26859骨キー、37モーフキー、IK末尾を読み、口キーを別バイト列に追加して、骨を含む前半とモーフ後半のハッシュが同一であること、原ファイルのSHA-256が前後同一であることを確認した。
- `python -m pytest -q tests/test_studio_v05_vmd_morph_rewrite.py` は実VMD指定で3件成功。Python構文、JSON、差分検査も実施。実PMX再生、合成VMDの画面・API・MP4、WebMCP、標準MCP、Linuxは未検証。

モデル区分: 設計・実装・試験とも標準モデル。
