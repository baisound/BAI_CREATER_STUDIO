# MOTION-010 長尺VMDの24fps候補と境界拒否

2026-10-24、Issue #106。登録済み `神っぽいな.vmd`（203.63秒、SHA-256 `fa224ad0f7c8af26b5214c4726e0be93ed719d1fcc539b679571761377225189`）と201骨PMX `Baisound-New-V5.0.0-B_新狐面差替_紐鈴物理_調整v6.pmx`（SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`）を隔離作品に登録し、作品FPSを24に設定した。

204秒の全クリップ一定頭FK補正（Y12°、X位置0.15、90秒の作品F2160）から元VMDキー間隔と補間を保つ `legacy_sparse` 候補を作成。隔離Chromeの物理OFF全骨比較では4896作品F＋6120 VMD Fの最大ワールド位置差が `0.0000017793` MMD単位、最大回転差が `0.0000261763°` で、位置0.001・角度0.01°の上限内だった。別名VMDのSHAと非骨suffixを確認し、同じクリップへの明示採用後に配置とファイルを読み返し、元VMDへ復元した。元PMX/VMDの前後ハッシュは一致した。

同じVMDの動く頭骨を作品F2134〜2265、前後各4Fのなじませ、Y8°・X位置0.15で区間限定すると、候補の局所評価は作品F2135で最大角度差 `1.198514°`、最大位置差 `0.0224996` となり上限超過で拒否された。元頭骨の平坦キー対VMD F2667/2669・F2831/2833は24fps作品の整数フレームへ両端とも一致しない。拒否の実VMD回帰テストは原本byte不変も確認した。任意の24fps区間候補が不可能という意味ではなく、この境界と補正量での判定である。

`node tests/run-guarded.cjs tests/studio-v05-vmd-long-sparse-real.test.cjs` は既存60fpsの6件を含む7件通過、0失敗・0スキップ。`python -m pytest -q tests/test_studio_v05_vmd_temporal.py` は14件通過。初回のブラウザ試験はテストのfps引数漏れで7件失敗し、修正後に全件再実行した。保護検査は実データ `data` 7件・`exports` 0件の前後ハッシュ一致を確認。今回は試験と文書のみ変更した。実GPU、物理ON、任意PMX・任意境界、長いなじませ、通常画面の長尺手操作、Linux、標準MCP実通信、Owner採用、MOTION-010全ACは未確認。画像・動画成果物はなくEagle登録対象はない。モデル区分：試験・文書に標準モデル区分を使用。
