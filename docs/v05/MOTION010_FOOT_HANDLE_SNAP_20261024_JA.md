# MOTION-010 足IKハンドルを現在の足首位置へ置く

2026-10-24、Issue #106。v0.5の実PMX骨編集で足IKターゲットを選んだ際、3D位置ハンドルをターゲット骨の原点ではなく、現在のVMDと保存済み補正を評価した足首の世界位置に置く。PMXの実IK定義から追従骨を取得し、別の非描画オブジェクトへ操作ハンドルを付ける。ドラッグ終了時の世界移動量をターゲット骨の親座標へ変換し、既存の未確定位置補正へ渡す。画面の選択・再生や元PMX/VMDを変更しない。

3Dキャンバスからドラッグした後の`Esc`が従来のパネル内キー処理へ届かない不具合も修正した。未確定補正がある場合は文書側のキー処理で取り消し、ドラッグ中は既存ギズモ側の取消を優先する。

## 実PMX/VMDの検査

- `BAI_TEST_CONCURRENCY=1 node tests/run-guarded.cjs tests/studio-v05-pmx-fk-gizmo-real.test.cjs`: 隔離Chrome/SwiftShaderの1件成功。F240で左足IKに保存済み位置補正を持つ条件を使用。
- IKターゲットと評価済み左足首の世界位置差は約`0.000503`シーン単位。新ハンドルと左足首の開始位置差は`1e-6`未満。実マウスドラッグ後、左IKターゲットと左足首がともに`0.005`超移動し、右足首の差は`1e-4`未満。
- ドラッグ後`Esc`で保存済み足首姿勢との差は`1e-5`未満へ戻り、補正のrevisionは増えなかった。従来の頭FK回転・位置、足IK数値補正、往復シーク、保存再読込も同じ試験で通った。
- 最初のブラウザ実行はWindowsのソケット不足による別リソースの読込エラーで失敗した。共通テスト手順に従い並列度1で隔離再実行して成功。取消の初回試験では上記の`Esc`到達不良を検出し、修正後に成功。`run-guarded`の利用者`data/`と`exports/`の前後ハッシュは一致した。原PMX/VMDの入力ハッシュは[先行する実素材記録](MOTION010_PMX_FOOT_IK_TARGET_20261024_JA.md)と同じで、前後一致。
- `npm run typecheck`、変更JSの構文検査、`git diff --check`は成功。

## 未確認

ギズモをドラッグしている最中は表示ハンドルだけが動き、PMX姿勢の仮評価はマウスを離した後に行う。今回の実ポインタ試験は仮表示と`Esc`取消までで、ポインタ補正のキー保存と再読込は別ゲート。膝ポールのスナップ、腕IK、到達不能・角度制限の表示、別PMX名、実GPU、物理ON、Linux、標準MCPの実呼出し、Owner採用も未確認。AC-M-02とMOTION-010全体は「要検証」を維持する。画像・動画の納品物はなくEagle登録対象はない。
