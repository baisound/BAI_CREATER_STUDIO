# LIP-001 口形候補の画面表示（Issue #187）

## 接続した範囲

v0.5のSRT発話欄で「選択した発話の候補を確認」を押すと、登録済みの読みを使って候補APIを読み、元SRTの `[start,end)`、作品FPS、モーラごとのA/I/U/E/O/Closed候補、ミリ秒と整数フレーム、時間重なり・短区間等の警告を示す。未確定は候補なし、明示無音も候補なし。提案読みは未確定の候補として扱う。表示を「未採用」と明記し、読みの未保存変更がある場合は計算ボタンを無効にする。作品/原本/発話の変更と読み保存では古い候補表示を消す。

この画面は候補の読み取りだけで、採用キーや元VMDに書き込まない。候補の時刻・形・強度を手で直すUI、別名モーフVMD書出と再読込、実音声同期、WebMCP/標準MCP、統合production.lipは続く。LIP-001完成とは扱わない。

- `node tests/run-guarded.cjs tests/studio-v05-srt-source-ui.test.cjs`: 隔離Windows Chrome 1/1成功。原本を画面登録後、未確定は候補なし、確定かな「アイウ」からA/I/U候補、元区間1250〜2750msと作品F表示、重なるSRTを「要確認」、別発話の明示無音は候補なしと表示。保存・再読込、別作品、原本変更時の保存無効も引き続き確認。監視対象data 7ファイル・exports 0ファイルの前後ハッシュ一致。
- `npm run typecheck`、JS構文、JSON、差分検査は成功。
- 実ユーザーSRT、実音声での境界、候補の編集・採用、VMD出力、Linuxは未検証。
