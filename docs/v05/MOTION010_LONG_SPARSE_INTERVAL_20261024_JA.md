# MOTION-010 長尺VMDの時間限定・疎な候補の成立条件

2026-10-24、Issue #106。203.63秒の登録済み `神っぽいな.vmd` を204秒作品に置き、90秒付近の作品F5338〜5463だけにY12°・X位置0.15の補正を置いた。なじませは0。原本VMDの頭骨はこの区間で動くが、PMXの `髪_16-03` 骨に元VMDキーはない。この骨だけを補正する `legacy_sparse` 候補は、既存キーを密に分割せずに局所姿勢ゲートへ通った。一方、同じ条件で頭骨を補正すると元曲線分割で最大角度差が1°を超え、候補生成を拒否した。

最初の隔離Chrome実PMX検査では、疎な候補の開始作品F5338を浮動小数のVMDキー直前として読んで最大約12°の差を報告した。検証器は密な候補だけにVMD整数キーの微小時刻補正を使っていた。これをサーバーが `vmd_frame_span` を報告した疎な時間限定候補にも適用し、追加した終端VMDキーを検査対象に含めた。採用APIも同じ報告範囲を要求するよう合わせた。範囲不一致のレポートは引き続きHTTP 422で拒否する。

修正後は、204秒作品の12240作品F＋6121 VMD Fを、独立した201骨PMX二体で物理OFF全骨比較した。最大ワールド位置差 `0.0000021633` MMD単位（髪_16-03・作品F5462）、最大回転差 `0.0009257065°`（同骨・作品F5337）。上限の位置0.001・角度0.01°以内。隔離作品で候補を明示採用して同じクリップへ配置し、元VMDへ復元した。非骨区画byte一致、入力PMX/VMD SHA-256不変、守護検査の実データ7件・exports0件の前後ハッシュ一致を確認。

`node tests/run-guarded.cjs tests/studio-v05-vmd-long-sparse-real.test.cjs` は一定補正の回帰2件と時間限定髪骨1件の計3件通過、0失敗、0スキップ。`python -m pytest -q tests/test_studio_v05_vmd_temporal.py tests/test_studio_v05_vmd_adoption.py` は18件通過。途中の2回の失敗は、実PMXの境界時刻差と採用APIの末尾標本数差として修正後に再検査した。

成立したのは**元VMDがその骨を動かしていない、なじませ0の時間限定補正**である。頭骨の動く元曲線を時間限定で忠実に焼く方式、なじませ付きの高振幅補正、別PMX/他FPS、物理ON、実GPU、Linux、標準MCP実通信、通常画面の長尺手操作、Owner採用、MOTION-010全ACは未確認。候補生成や局所ゲートの通過だけでは採用しない。画像・動画成果物はないためEagle登録対象なし。モデル区分：原因調査に高性能、実装修正・試験・文書に標準モデル区分を使用。
