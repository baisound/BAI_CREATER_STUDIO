# MOTION-010 腕IKの3D実証条件

2026-10-24、Issue #106。対象はv0.5のPMX＋VMD骨編集。[承認済み仕様](../roadmap/RIG_EDITING_SPEC_20261020_JA.md) §2.2–2.3と[詳細設計](../roadmap/MOTION010_V05_DETAILED_DESIGN_20261024_JA.md)段階Bに従う。ここでは実PMXの構造と現行保存経路から実装の入口を定める。腕IKハンドルは未実装、AC-M-01/02は未合格。

## 実PMXで確認した構造

- 登録済みの201骨PMXと246骨PMXには、左右の足・つま先IK定義はあるが**腕IK定義はない**。Three.jsのPMX CCDへ腕ターゲットを渡すだけでは腕は動かない。専用の3D二関節解を使い、結果を腕・ひじ骨のローカル回転差分として保存する必要がある。
- 左右とも、肩の補助骨→腕→腕捩→ひじ→手捩→手首の親子経路を持つ。腕捩1〜3と手捩1〜3は経路の途中ではなく付与を持つ枝であり、腕・ひじだけを回す場合も実PMXの付与評価後に手首と他骨を測る必要がある。標準名の存在だけでは対応可とせず、実際の親子経路、重複名、有限な骨長を照合する。
- 隔離Chrome/SwiftShaderで元VMDを作品F240へ評価した201骨PMXを読み取り、左右の腕→ひじ長は約0.21724、ひじ→手首長は約0.24259シーン単位だった。肩から手首への直線距離は約0.45983137で、2骨長の和との差は約0.00000018。**ほぼ完全に伸びた姿勢**なので、現在の肘をそのままポール方向に投影すると数値的に不安定になる。
- [再現試験](../../tests/studio-v05-arm-ik-geometry-real.test.cjs)は左右の肘の直線軸からの距離が約0.0002005であることを確認した。手首目標を腕軸に沿って0.04シーン単位内側へ置くと、二球交円の肘半径は約0.09362になり、目標が到達可能でも初期ポールの退化が問題になる。隔離試験1件成功、元素材と利用者`data/`・`exports/`のハッシュは前後一致。

## 解法と保存のゲート

1. 目標手首の世界位置を対象インスタンスの空間へ変換し、肩を中心とする二つの骨長から到達区間 `[|L1-L2|, L1+L2]` を求める。範囲外なら近い境界へ目標を射影し、不足距離を画面に示す。数値異常、ゼロ長、重複骨、異なる親子経路は拒否する。
2. 手先軸に垂直な肘ポールを選び、二球の交円から肘位置を求める。ほぼ直線の姿勢では現在肘からのポールを使わず、PMXの局所軸と左右の向きを照合した安定な初期方向を選ぶ。腕の現在のねじれ、二解の連続性、ポール反転を試験する。左右を一律の符号でミラーしない。
3. 腕の回転で肘を目標位置へ、ひじの回転で手首を到達点へ寄せる。腕捩・手捩・回転付与を含む**現行の実PMX評価器**で再評価し、手首残差1e-3以下、胸・頭・反対腕など未編集領域の世界姿勢不変を測る。実姿勢が外れれば仮補正を破棄する。
4. 1回の手先操作は少なくとも腕とひじの2キーを必要とする。現行`studio_v05_motion_edits.py`の`set`は1キー1 Undo、`previewFk`も1キーなので、2回の`set`で代用しない。作品・素材・時刻・レイヤーを共通検証した**2キーの原子的な保存操作**と、一つの仮プレビュー・一つのUndo/Redoを先に作る。既存キーの位置チャネルと他骨キーは保つ。
5. FK→腕IKの切替は手首・肘ハンドルを現在の実姿勢へ置くのみとし、キーやUndoを増やさない。IK→FKも同フレームの全骨世界姿勢差が1e-4を超えるなら拒否する。初期値は腕FK。VMD候補は非骨区画をバイト単位で保ち、腕・ひじキーを焼いた後に実PMXの全骨・全作品F・全VMD Fで照合する。

## 次の最小実証

1. PMX実骨から肩・肘・手首を同時刻で読む隔離試験を正本化し、直線姿勢、目標が内外の到達境界、左右ポール、付与を含む再評価を測る。
2. 2キーの原子的なAPI保存と仮プレビューを実装し、競合・素材変更・不正キーで全体を拒否、成功時は1 Undoとする。既存の1キー経路を保つ。
3. 対応条件を満たす実PMXだけで腕IKハンドルを有効にし、実ポインタ、Esc、保存・Undo/Redo・再読込、別名VMD候補の全骨往復を検査する。実GPU、物理ON、VRM、Linux、標準MCPとOwner採用は個別ゲートのままにする。

実測はローカルの登録PMX/VMDを隔離サーバーへ複製して読み取った。原本の編集・画像/動画の生成はない。モデル区分: 実素材の構造・解法と保存契約の検討に標準モデル区分を使用。
