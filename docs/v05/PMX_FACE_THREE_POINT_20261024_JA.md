# 実PMXの表情・口キーを先頭・中間・末尾で照合（Issue #96）

## 対象と比較方法

v0.5の同一隔離作品へ201骨・168モーフの実PMXと10秒の頭振りVMDを配置した。元PMXのSHA-256は`542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、元VMDは`3ae724f9d1d36a7e74a911d6b1bbfad7d2459e5e256fcac43521ebebd0a3d234`。作品の30fpsでF0/F120/F270に「まばたき」表情行を1/0/1、「あ」口行を0/1/0として6キーを保存した。原本は直接変更しない。

変更前の同じ作品・同じVMD・同じ時刻の3Dプレビューと1フレームMP4をそれぞれ採り、6キー保存後に画面を再読込してから、保存値と各時刻の3D・MP4実画素を比較した。保存した表情キーだけで体VMDの「頭」姿勢が変化しないことも確認する。試験は`tests/studio-v05-pmx-face-three-point.test.cjs`。初回は操作パネルが顔を隠さない「単独画面で表示」で比較し、後続の合成画面修正後は同画面の中央顔領域で比較する。

## 結果

PR #172時点の隔離Chrome合同試験5件が成功。再読込後の6キーと時刻ごとの両モーフ値は保存APIと一致した。640×360に復号してRGB差の最大値が5を超える画素は、単独プレビューのF0/F120/F270で30/24/30、MP4で999/979/1,125。MP4側はNVIDIA GeForce RTX 4070 SUPER、画面側は隔離ChromeのWebGLで確認した。体の頭骨姿勢は各時刻の変更前後で一致した。監視対象の利用者data 7ファイルとexports 0ファイル、および原PMX/VMDのSHA-256は不変。画素数はこの素材と実行環境での比較値である。

途中の診断では、保存キーの配列がモーフ名→時刻順で返るため、試験の時刻→モーフ名順という期待だけが不一致だった。比較順を現行APIに合わせた。続く合成画面のスクリーンショットでは、操作パネルが顔を覆い、口の値が1でMP4も変わるのにプレビューの画素差が0だった。パネルを退避できる既存の「単独画面で表示」に切り替えると、口元のプレビュー画素差を確認できた。この差は撮影範囲によるものであり、保存値だけから画面品質を合格と判定しない。

合同試験の初回は5件中4件成功し、既存の保存カメラ試験だけが状態表示待ちでタイムアウトした。保存APIのrevisionと画面の成功表示は正常で、試験が複数ある`small[role="status"]`の先頭のみを読んでいた。`tests/studio-v05-scene-mp4.test.cjs`の判定を全状態表示から成功文を探す形に修正し、単独3件と合同5件を再実行して成功した。`npm run typecheck`、JS構文、`git diff --check`も成功。`python -m pytest -q test_v05_scene_instances_v57.py`は初回にサンドボックスのローカルソケット制限でHTTP試験1件が失敗し、隔離データで再実行して11件成功した。Python試験には無いモーフ名・無効値・古いrevisionの拒否と保存・削除の検査が含まれる。

この試験は実PMXの2種類のモーフと3時点の保存・再読込・実画素に限定する。任意PMX、長尺全区間、Linux、標準MCP実通信、視線編集、SRT/音素からの自動リップ、頂点変位解析・母音強度最適化、Owner採用は未確認。LIP-004/009全体の完成判定には用いない。
