# LIP-001 口形VMD候補の明示採用と3D優先表示（Issue #187）

## 実装した範囲

生成済みの別名モーフVMD候補を、作品の登録PMXインスタンスへ明示採用する。採用は元のVMDクリップや手動表情キーを書き換えない別台帳に、候補ID・SRT/PMX/出力ハッシュを保存する。解除・Undo/Redoはこの台帳だけを対象とする。読込時に候補バイト、元SRT、読み、下書き、MorphMap、対象PMXを再照合する。失効した候補は参照を残して理由を表示し、3Dへキーを渡さない。1件のGETに大量のキーを返さないよう、再生用の発話別キーは対象インスタンス指定時だけ返す。

3Dシークでは元VMDの後に採用口形を原SRTの半開区間内で評価し、最後に手動表情キー（0を含む）を適用する。区間外は元VMDへ戻る。画面から候補の採用・解除・Undo/Redoを行い、保存後の再読込でも状態を復元する。読み・下書き・SRT・PMX口形対応の変更時には採用状態を再照合する。

## 隔離試験

- Python HTTP＋実PMX候補試験2件成功（関連codec・draftを含む11件成功）。採用、古いrevision拒否、解除、Undo/Redo、候補失効、失効時のキー非供給、元SRT/PMX/シーンの手動0キー不変を確認。
- 隔離Chrome実PMX A試験1件成功。元VMD「あ」0.2、採用口形F30「あ」0.8・F60「い」0.35、元SRT外F90「あ」0.2、手動0キーの優先、手動解除、採用Undo/Redo、画面再読込、読み変更による採用失効と元VMDへの復帰を確認。F30/F60の実描画像素は異なる。元PMXのSHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、元VMD試験素材のSHA-256 `d01fc96c559bee7d25a2242e9c3ade6dde4247aac93e7e4b2e292a92da6e7ef1` は不変。監視対象data 7件・exports 0件も前後一致。
- 既存SRT画面の隔離Chrome試験1件成功。`npm run typecheck`、Python/JS構文、JSON・差分検査成功。

口形の自然さ、実歌音声との一致、採用結果を元VMDへ合成する別名VMD出力、製品の最終MP4での口形、Linux、WebMCP/標準MCPは未検証。採用操作は利用者の意図を記録し、品質の承認とは区別する。
