# MOTION-010 動く頭骨曲線へ時間限定補正を焼ける境界

2026-10-24、Issue #106。203.63秒の登録済み `神っぽいな.vmd` と201骨PMXを使い、頭骨の元曲線が動く区間へ疎な別名VMD候補を試した。元VMDの頭骨キーF2667/F2669は同じ姿勢、F2831/F2833も同じ姿勢だったため、作品60fpsの補正区間をF5338〜5665（VMD `[2669,2833)`）に置いた。Y回転8°・X位置0.15、なじませ0、保存キー作品F5400。区間の中では元頭骨曲線が実際に動く。

元曲線を密キー化しない `legacy_sparse` 候補はサーバーの作品全12240Fの局所姿勢ゲートで位置・角度上限内。12°へ増やすと境界の最大角度差が約0.011146°となり、0.01°の上限超過で拒否した。先の約2秒区間 `[2669,2732)` も終了側が動く曲線を分割するため、拒否を維持する。

隔離Chromeで候補を独立したPMX二体へ読み込み、204秒作品の12240作品F＋6121 VMD F、201骨を物理OFFで全件比較した。最初はVMD F2833のFloat32キー時刻が数学上の `2833/30` より約1.02マイクロ秒後ろにあり、固定1マイクロ秒の検証時刻補正ではキー直前を読んで約8°の差が出た。検証時刻を `Math.fround(VMDフレーム/30)` 以後の微小時刻にした後、最大ワールド位置差 `0.0002038909` MMD単位（装飾_02-02J_Opt_R_CatEar2_end_01、作品F5664）、最大回転差 `0.0074305631°`（頭、作品F5664）で許容上限の位置0.001・角度0.01°以内となった。隔離作品で別名候補を明示採用し、同じクリップへの配置と元VMDへの復元を読み返した。

`node tests/run-guarded.cjs tests/studio-v05-vmd-long-sparse-real.test.cjs` は一定補正2件・時間限定髪骨1件・動く頭骨1件の計4件通過、0失敗、0スキップ。実データ `data` 7件・`exports` 0件、入力PMX/VMDの前後ハッシュ一致。`python -m pytest -q tests/test_studio_v05_vmd_temporal.py` は12件通過し、同じ境界の8°通過・12°拒否を固定した。
