# 実PMX・全身VMD・表情の同一作品検証 — 2026-10-24

関連: Issue #39/#96、`MOTION-002/006`、`LIP-001`、`RENDER-001`、v0.5最短制作経路の順2〜4。既存の配置・プレビュー・表情キー・限定MP4の接続を、全身ダンスの実素材で検証した記録。今回の変更は隔離試験と証拠文書のみで、制作データや本番コードは変更しない。

## 観測した範囲

- 登録済みPMXと全身VMDを一時データへコピーし、同じ新規作品のPMX一体にVMDを割り当てた。VMDは27,290,935バイト、骨キー245,461件、モーフキー1,939件、最終F5539（元30fpsで約184.63秒）。モデルとの名称照合は骨185/192、モーフ164件。VMDはプロジェクト時刻0秒に184.5秒のクリップとして配置した。
- 隔離Chromeの3Dプレビューで0・4・90秒をシークした。センター、上半身、頭、左右腕・左右足の骨を調べ、0→4秒で頭以外の骨も変化し、4→90秒も姿勢差を確認した。4→90秒の記録した最大位置・回転差は3.1628。描画コンテキストはSwiftShader。これは骨の数値と読み込みが動いた証拠であり、全区間の見た目や物理の品質評価ではない。
- 作品F240–242の720p MP4を、表情キーを入れる前後で別名出力した。3フレームを再読込し、描画側はNVIDIA GeForce RTX 4070 SUPER/D3D11と報告した。0秒で「まばたき」値0、4秒で値1を保存すると、4秒のデコードフレーム1280×720でRGB各画素の最大差が5を超える画素が初回3,315点、再試験3,264点あった。表情キー保存後も同じ骨姿勢で、3Dプレビュー再読込とページ再読込後に顔値1と骨姿勢が復元した。
- 原PMX SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、原VMD SHA-256 `f75a0bf518aef532c400e5ed31211d71ce294c2a69916ebf55ad16c3bfabd3d2` は前後一致。`run-guarded`が監視した利用者`data` 7ファイルと`exports`も前後一致した。実素材バイナリと試験用MP4はGitに追加しない。

## 試験

`BAI_REAL_MMD_DATA=<実登録素材を含むdataディレクトリ> BAI_TEST_CONCURRENCY=1 CHROMIUM_PATH=<インストール済みChrome> NODE_PATH=<この作業ツリーのnode_modules> node tests/run-guarded.cjs tests/studio-v05-full-pmx-dance.test.cjs`：隔離Chrome試験1/1成功。テストは元PMX/VMDの前後hash、実VMDの対象割当、骨姿勢、表情値と骨姿勢の独立、保存再読込、2本のMP4のフレーム数と画素差を検査する。実素材がない環境では明示的にスキップする。最初の再試行2件はローカルソケットが使えない実行環境でサーバー起動待ちに失敗し、次の1件は`CHROMIUM_PATH`未設定でPlaywright付属ブラウザがないため起動に失敗した。いずれも製品の描画・保存処理まで進まず、正しい隔離Chrome設定で再実行した。

90秒シーク時に、旧カメラシーケンス評価が別保存の300フレームの範囲を超え、`/api/camera/sequence/evaluate?frame=5400`がHTTP 400を返した。現在の共通時計から旧カメラへの橋は作品ごとの範囲に統合できていない。テストはこの一件だけを既知のHTTP失敗として認め、他のHTTP失敗と未処理ページ例外を拒否する。またMMDParserから`unknown char code`が2回の読込で計10件出た。モデルとVMDの文字名を実際に読めて骨・顔の変化が起きた範囲は確認したが、未知文字の影響を全キーで評価したわけではない。

長尺全区間の映像・音声同期、全身動作の見た目・接地・物理、カメラの共通時刻、他モデル、Linux、WebMCP/標準MCPの実運用、Owner採用は未検証。限定MP4は300フレーム以内の短い区間のみで、184.5秒の全尺書き出しは行っていない。`MOTION-006`等の機能全体や最短制作経路を完了扱いにしない。

実装段階は標準モデル区分。原因調査も同区分で実施した。
