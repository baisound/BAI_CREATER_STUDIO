# 複数の音声・楽曲行（2026-11-07）

順3、Issue #81/#39/#63、AUDIO-001・DATA-002/008・RENDER-006。既存の画像/動画行の安定ID契約を音声/楽曲へ接続する。原本・旧作品・元ID/区間・既存の音量方式を保持する。

## 仕様と保持範囲

- audio/musicそれぞれ初期1・最大16行。`audio_lanes/audio_lane_ids/next_audio_lane_id` とmusic側の同名フィールドをレイアウトへ追加。旧保存は読取時だけ1/[1]/2へ補い、そのための書換えはしない。行IDは増加のみで削除番号を再利用しない。
- クリップのある行/最後の1行/存在しない行/古いrevisionの削除は保存せず拒否する。空行の削除は配置ロック→レイアウトロックの順で検査・保存し、他の番号とクリップを改番しない。
- 行名はaudio:<ID>/music:<ID>。旧audio/musicの行名は行1へ互換表示し、明示して行1を改名した時だけ旧別名を解消する。他種の行・muted/locked/order/heightsは保持。
- 手動UIは折りたたみ［音声・楽曲の行］に追加/空行削除を置く。直接ドラッグ・配置/編集の行選択・元区間・分割を共通APIで保存。任意の既存行への明示移動は元区間を保持する。行省略の同種編集/バッチは元行保持、種類変更で行を省略した旧APIは従来どおり行1を使い、行1が無ければ拒否する。
- 種類ごとのロック/ミュートはその種類の全行へ作用する。行別音量・ミキサー・新混音方式は作らない。全行の内包音声を従来の混音へ送り、画像/3D/動作の操作は変えない。
- API POST `/timeline/audio-lanes`・`/music-lanes`、削除は各`/remove`。標準MCP/WebMCPは既存track_layout_setへadd/remove_audio_lane、add/remove_music_laneの4actionを追加。ツール数と旧5action/省略更新は維持する。

## 受入れ条件

1. 旧レイアウト/クリップ/名前/フラグの読取不変。音声・楽曲各2を削除して1/3を保持、次4/次番号5。互いの番号と画像/動画設定も保持。占有/最後/不正/削除済み/上限/競合を拒否する。
2. 同じWAV/MP3等を複数の音声/楽曲行へ置き、行間の実マウス移動・種類間の明示移動・元区間編集/分割・名前保存・再読込を確認。バッチ移動/既存Undoで削除済み行が復活しないこと、ロック・元素材尺・古いrevisionの保存不変を確認。
3. 手動UI、公式MCP SDK、ChromeネイティブWebMCPで同じ保存値を照合。合成の異なる周波数3音源を重ね、プレビューのメディア時刻/ミュートとMP4の周波数PCMを比較。音声全行/楽曲全行のミュート、全ミュートの無音、映像保持を確認。
4. 実曲と登録MP3見本を隔離複製し、長尺の複数行/重なり・保存再読込・完成PCMと入力hashを確認。Windows/Ubuntuを区別し、Linuxブラウザー/実スピーカー/全形式/混音音量一致・ミキサー/全Undoを完成にしない。
5. 検証済みPRをmainへ統合し、利用者data/exportsと変更一覧を保持して8765の制作画面を同期。順3全体・順4の読み/採用・順5の判定は維持。

モデル区分：高性能（保存互換と接続判断・実装・検証）。

## 操作

タイムライン編集で［音声・楽曲の行］を開き、音声/楽曲の行を追加する。素材を行へドラッグするか、配置先と行を選んで配置する。クリップ編集では元素材の開始秒と配置行を選び、保存する。行名をダブルクリックで変更できる。削除はこの折りたたみ内で空行を選ぶ。音声/楽曲のミュート・ロックはそれぞれ全行が対象。
