# 実PMX・実曲VMD/WAVの600FプレビューとMP4確認（2026-11-06）

対象はロードマップ順3、Issue #39/#81、`AUDIO-001`、`RENDER-001/006`。既存の合成GLBによる600F確認に対し、Ownerの登録済みPMX、同じ曲の実VMDと実WAVを一つの隔離作品に置き、保存再読込からMP4まで確認した。原本・利用中の8765番サーバー・共有dataへは書き込まない。

## 入力と確認方法

- `BAI_REAL_MMD_DATA` にOwnerの登録素材data、`BAI_REAL_LIP_VMD` に `KYOKAI_DANCE_MASTER_LIPSYNC_BLINK.vmd` を読取専用入力として指定。実PMXと登録テクスチャ139件、実VMD、同曲の登録WAVを試験サーバーの一時dataへ複製した。試験は `tests/studio-v05-real-song-600f.test.cjs`。
- 同じ作品IDにPMX場面インスタンス、実VMDモーションクリップと対象インスタンス、実WAV音声クリップ、In/Out F0..F599を保存した。Chromeの編集画面でF0/F300/F599へ移動し、音声要素の時刻がそれぞれ0/5/9.983333秒、F0とF300のPMX骨姿勢が異なることを確認。ページ再読込後に配置をAPIで照合した。
- 製品の限定MP4ジョブを720p・60fps・600Fで実行し、完成H.264/AACファイルを再読込した。復号映像のF0/F300とF300/F599には、160×90・RGB差24超の画素がそれぞれ1,220/1,123点あった。ジョブは実VMDの動作1件と入力3件のSHA-256を記録し、作業用PNG連番は完了後に残らなかった。
- 原WAVと完成MP4を8kHzモノラルPCMへ復号し、1/5/9秒付近の0.3秒窓で相互相関の最大位置を比較した。3点とも測定上のずれは0サンプル、相関は0.99992以上だった。これは実曲音声の配置時刻の確認であり、振付と音楽の主観的な一致判定ではない。

## 実行結果と限界

Windows、Node 22、Chrome 156、NVIDIA GeForce RTX 4070 SUPER / D3D11で `node tests/run-guarded.cjs tests/studio-v05-real-song-600f.test.cjs` が **1成功・0失敗・0スキップ**。`CHROMIUM_PATH` と `BAI_TEST_CONCURRENCY=1` を指定した。実PMX `542a4daa...a205488`、実VMD `61ce920e...9939`、実WAV `f00671c7...a9f0e` の試験前後SHA-256は一致し、共有dataの5ファイルとexportsなしのガード前後hashも一致した。

初回の制限付き実行は隔離HTTPサーバーの起動待ちで失敗した。FFmpegの旧 `-vsync` が現行版で拒否されたため、試験のフレーム抽出を `-fps_mode passthrough` に修正した。画面の音声時刻移動は製品の媒体プレビュー `seek(frame)` を使うよう試験を修正した。これらの失敗試行は最終成功件数へ含めない。

確認範囲は実曲の先頭10秒・上限600F、単一PMX/VMD/WAV、60fpsの隔離作品。600Fを超える3D、曲全体230秒、動画内音声との重なり、異なる作品FPSと音声サンプルレート、先頭無音、素材欠損、保存カメラ・時刻付きカメラ、Linux、実MCPクライアントは未確認。`AUDIO-001` と `RENDER-001/006` の全受け入れ条件、順3全体は未完了のまま。

モデル区分：既存の試験契約に沿った実データ結合試験・記録は標準モデル。
