# MOTION-010 別名VMD候補の実PMX全骨検査

2026-10-24。Issue #106。段階Cの候補検証を、v0.5の手動3D画面に追加した。候補の採用・素材登録・作品配置はこの段階に含めない。

## 操作と判定

保存済み補正から別名VMD候補を作った後、［実PMXで全骨・全Fを検査］を押す。候補メタデータに固定したPMX・元VMD・候補VMDのSHA-256を検査前後に照合する。独立したPMXを2体読み込み、元VMD＋保存補正と候補VMDを同じローカル時刻へシークし、IK・grant適用後の全骨ワールド位置と回転を比較する。作品FPSの各フレームとVMD30fpsの各フレームを全件調べ、最大誤差・骨・フレームを表示する。位置1e-3 MMD単位、角度0.01°以下なら画面内で「実PMX検査合格」と表示する。

作品の補正revision、シーンrevision、モーション配置revision、対象モデルや候補が変わると中止する。利用者は検査中に中止できる。作品6000Fまたは合計10000標本を超えると、間引きで代用せず検査を拒否する。元PMX/VMD、候補、作品データの書き込みは行わない。候補メタデータは引き続き `candidate_requires_real_pmx_validation` で、登録素材や作品クリップへ自動昇格しない。画面内の合格表示はそのブラウザと対象ハッシュでの読み取り検査結果であり、全モデルの採用判定ではない。

## 実行した試験

- `npm run typecheck` 成功。
- Chrome（Windows、ANGLE SwiftShader）・隔離サーバーで `node --test tests/studio-v05-vmd-fps-fade-real.test.cjs` 成功。24fps、前後なじませ付き頭FK候補を作品240F＋VMD300F、実PMXの201骨で照合。位置最大0.0005084752（髪_16-03、作品F180）、角度最大0.000002958°（頭、作品F98）。候補作成→画面ボタン→合格表示も確認。偽の候補SHA-256は読み込み前に拒否。
- 同じ環境で `node --test tests/studio-v05-vmd-constant-real.test.cjs` 成功。60fps、時間変化頭FK＋左足IK候補を作品600F＋VMD300F、201骨で照合。位置最大0.0000043101（左つま先、作品F598）、角度最大0.000022199°（左ひざ、作品F598）。
- 入力PMX SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、元VMD SHA-256 `3ae724f9d1d36a7e74a911d6b1bbfad7d2459e5e256fcac43521ebebd0a3d234`。両試験は隔離一時データを使い、試験前後の原本ハッシュ一致を確認した。
