# VST固有画面と再生に追従する音量表示（Owner追加報告）

AUDIO-002 / UX-006 / DATA-002 / RENDER-006、Issue #69。従来は汎用パラメーターと区間ピークのみ。固有GUIと再生連動表示は未実装だったため、今回の追加要求として優先する。

## 実装・受け入れ条件（作業中）

- インサートのダブルクリック、Enterで到達できる明示ボタンから、検出済みVST3の固有画面を別プロセスで開く。画面のクラッシュがサーバー・作品・完成動画を壊さない。
- 固有画面での編集を閉じると、正規化パラメーターとプラグイン状態を作品へ保存。状態ファイルはローカルの内容ハッシュで管理し、任意パスはAPIから受け付けない。汎用パラメーターも同じ状態を扱う。
- 開いた時点の作品・スロット・revisionへ結び、作品切替や別保存・並べ替え時に別のVSTへ上書きしない。変更回収・破棄・クラッシュ・競合時の復旧を明示する。
- 同じ状態を処理後試聴・共通作品再生・MP4へ適用。固有GUIの表示だけで完了とはしない。
- 音量表示を共通時計へ連動。各実行、種類別バス、マスターの処理後信号を対象とする。区間ピークと時系列の表示を区別する。
- ラウドネス（LUFSを意図しているかOwnerへ確認中）は計測定義と代表信号による参照比較を持つ。メーターの表示だけを実測合格にしない。

使用中のPedalboard 0.9.26にメインスレッド用の`show_editor(close_event)`があることをローカル実装と[公式API](https://spotify.github.io/pedalboard/reference/pedalboard.html#pedalboard.VST3Plugin.show_editor)で確認。サーバー内から直接呼ばず、専用子プロセスのメインスレッドを使う。

3Dのモデル・カメラ・動き／表情連動は `codex/timeline-scene-runtime-20261113` / 7ee8669 に途中状態を保全。新しいaudio修正の後に再開する。未検証3Dをmainへ混ぜない。
