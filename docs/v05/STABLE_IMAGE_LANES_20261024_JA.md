# v0.5 画像トラック番号の保持（Issue #80）

2026-10-24。画像行の保存値を単なる行数から、安定した `image_lane_ids` と単調増加の `next_image_lane_id` へ拡張した。旧作品の行数と旧クリップの行省略は読み取り時に画像1からの番号へ変換し、原本を自動書換えしない。新規追加で削除済み番号を再利用しない。空の行だけ削除でき、クリップが残る行と最後の1行の削除は拒否する。配置・編集は存在する行IDを検査する。画面の画像行、配置先、編集先、削除先は同じIDを表示する。

## 検査

- Python単体12件合格。旧行数の読込、画像1/2/3の画像2削除、画像3のクリップ保持、新規画像4、古いrevision、存在しない行、最後の1行、レイアウト更新後のID保持を確認。
- 隔離Chromeのタイムライン試験1件合格。画像1/2へ配置し、画像3へ既存画像2クリップを移動して空の画像2を削除。画像1/3の表示とクリップを保持し、新規行が画像4となり、ページ再読込後も行ID `[1,3,4]` と配置が一致した。実データ5ファイルのハッシュは前後一致。
- Windows Chromeで確認。Linux、WebMCP/標準MCP、既存実ユーザー作品での行削除は未確認。

画像行の安定IDは `DATA-002` の一部であり、全媒体の複数トラックと共通映像出力の完了を意味しない。
