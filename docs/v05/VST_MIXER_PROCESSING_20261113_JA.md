## 経路と受け入れ条件

1. 作品の楽曲・音声・映像音を各バスへ送り、インサート→フェーダー→マスターの順で処理する。ミュート・ソロ・dB値を作品別に保存し、再読込で復元する。既存トラックミュートも尊重する。
2. 検出したローカルVST3エフェクトを追加・並べ替え・バイパス・削除し、汎用パラメーターを編集できる。プラグインは別プロセスでロードし、失敗・異常終了・時間切れ時に原音へ黙って切り替えない。音源VSTi・VST2・プラグイン固有GUIは今回の経路に含めない。
3. 保存した設定から生成した48kHzステレオPCMを、作品プレビューと動画出力で共有する。素材単体もバスとマスターを通して試聴できる。これは処理後の試聴で、低遅延ライブ入力ではない。
4. 元素材は読み取り専用。設定競合をrevisionで拒否する。出力は開始時の設定・素材ハッシュを固定する。処理失敗は完成動画の保護経路へ戻す。
5. 隔離した合成音声で実VST（TDR Nova）、ゲイン比、ミュート/ソロ、原本不変、保存再読込、処理後PCMとMP4の対応、Chrome操作と幅1024/1440を検証する。実装の存在だけで全VST対応を宣言しない。

## 使い方

「制作→音声編集→エフェクト・ミキサー」で作品を確認し、音量・M/S・VSTを調整して「作品へ保存」。VSTはチャンネルの「＋VSTを追加」から検出済みのエフェクトを選び「読み込んで追加」。右欄で汎用パラメーター、バイパス、順序を変更する。「作品の音を処理して試聴」は保存済み作品の全音声を処理する。未保存時は「保存して処理・試聴」と表示する。

素材単体は「音声素材・配置」で送信先の音声/楽曲を選び再生すると、保存した同じバスとマスターを通す。「この作品に配置」は原本の参照を配置するため、後からミキサー設定を変えても再編集できる。制作タイムラインのプレビュー、MP4出力も保存済みミキサー設定を使う。未設定作品は従来の音声処理経路を保つ。

WAVは素材管理で選択→右の「この素材をタイムラインで選ぶ」→制作側の配置先を音声/楽曲→「選択素材を配置・保存」で配置できる。この手動経路も隔離Chromeで確認済み。

## セットアップと制限

このPCのPythonへ `python -m pip install -r requirements-audio.txt` を実行済み。FFmpeg/ffprobeも必要。既定のVST3ディレクトリを検出し、追加ディレクトリはサーバー起動時の `BAI_VST3_PATHS`（OS標準のパス区切り）で指定できる。他社プラグインとライセンスは配布しない。

処理はオフライン。設定の変更中は旧音のまま鳴らさず、保存後に再処理する。各トラック種類の全行を同じバスへ送る。末尾の残響は作品の長さまでなので、必要なら画像などで作品末尾に余白を足す。最大2時間は入力制限であり、2時間の負荷試験を成功とは扱わない。メーターは直前に処理した区間のピークで、ライブ入力メーターではない。単音声のmono→stereoは既存FFmpegと同じ等電力変換。

未対応/未検証：VST2、音源VSTi、プラグイン固有GUI、低遅延入力、全VST互換、Linuxの実プラグイン/ブラウザー、実スピーカー聴感、SR/200%拡大/タッチ。順3全体を完成へ昇格しない。モデル区分：本体は同一モデルで調査・実装・検証、独立UI批評は既存の標準モデル3名を再利用。
