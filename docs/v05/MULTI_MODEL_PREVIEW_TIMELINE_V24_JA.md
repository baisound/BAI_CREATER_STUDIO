# MM-05 複数モデル3Dプレビューとタイムライン同期（設計のみ）

状態: **設計のみ／未実装**。既存の単一モデルプレビューを置換・変更しない。

## 識別子と状態
- `project_id`: 作品識別子。作品切替ごとに非同期処理世代 `generation` を更新。
- `scene_instance_id`: 3D空間内の配置インスタンス。素材IDと混同しない。同じ素材から複数個配置可能。
- `asset_id`: VRM / GLB / FBX / PMX 原本の参照。共有キャッシュは参照カウントで管理。
- `clip_id`: 時間軸上の一意なクリップ。`target_scene_instance_id` を必須として誤適用を防ぐ。
- `track_id`: 表示トラック識別子。順序や高さが変わってもモデル識別は変わらない。

## 3Dプレビュー構成
単一レンダラー、共有シーン、共通カメラをホストが所有する。モデルインスタンスごとにTransform、スケルトン／ミキサー、表情状態、再生状態を保持する。既存の単一モデル描画関数を複数回実行してキャンバスを重ねる方法は禁止。追加・削除・切替時はGPUバッファ、テクスチャ、ミキサー、登録イベントを適切に解放。参照共有素材は別インスタンスの利用中に破棄しない。

## 同期アルゴリズム
1. マスターの再生位置（秒）を読み取る。すべての評価はこの値を使う。
2. 対象時刻の有効クリップを列挙し、`target_scene_instance_id` でグループ化する。
3. `offset_seconds=(master_seconds-start_seconds)*speed+source_offset_seconds` を計算する。負値・非有限数・範囲外を検査。
4. 各モデルのモーションは適用優先順位とブレンド設定に従い決定的に評価。表情・口は独立レイヤーで競合キーの優先順位を定義。
5. 全モデルの姿勢を評価後、ライト・エフェクト・カメラを同じ時刻で評価し、描画は一回のみ実行。
6. モデル未ロード時は `not_ready`、失敗時は `failed` を返し、他のモデルを停止させない。世代違いの非同期結果は破棄。

## UI
シーン内一覧：モデルごとの選択・表示・ロック・読み込み状態。ビューポート：XYZギズモ、選択モデルに注目、複数選択。タイムライン：キャラクター単位グループの配下にダンス・表情・口。クリップ設定には対象モデルの明示選択。対象モデル削除時は関連クリップの参照を残し `missing_target` 警告を表示し、勝手に別モデルへ付け替えない。

## API/MCP/WebMCP予定契約
`scene_instance_list`, `scene_instance_add`, `scene_instance_remove`, `clip_target_set`, `timeline_seek`, `scene_preview_status`。表示名に依存しないIDを使用。UI/API/MCP/WebMCPは共通サービス層へルーティングし、ロック・競合・存在・権限を同一に検査。MCP・WebMCPの登録だけで動作完了とは判定しない。

## 受け入れ条件
- 同一素材を2体配置しても各Transform/モーションが独立。
- A体に割り当てたVMDがB体の姿勢を変更しない。
- 10.00秒へシーク後、全モデル・表情・カメラが共通時刻で確定。
- シーク連打・作品切替・素材読込中の古い非同期結果を破棄。
- 3体以上でもレイヤー・描画順が決定的で、1体のエラーが他モデルを破壊しない。
- UI/API/MCP/WebMCPの状態に不一致がない。
- 実モデルWebGL統合検証・メモリリーク検査・GPU負荷測定が通るまで完了判定しない。
