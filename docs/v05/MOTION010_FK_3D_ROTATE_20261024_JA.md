# MOTION-010 実PMX骨の3D回転ハンドル

2026-10-24、Issue #106。[実骨階層選択](MOTION010_BONE_SELECT_20261024_JA.md)に続く部分接続。同じv0.5の3D編集画面で選択中の実PMX骨に局所回転リングを表示し、ドラッグを作品Fの未確定FK補正へ変換する。既存の「このFをキー化」で作品別の補正キーを保存する。ドラッグだけでは保存しない。元PMX/VMDの骨格・ウェイト・素材は変更しない。

## 操作と安全条件

- 「このFを3D表示」で作品の共通時刻を対象Fへ移動する。表示中の3D時刻と対象Fが一致しない場合、ハンドルを無効にする。メディアがない作品ではメディア時刻と旧タイムラインの時刻がずれることを実機で確認したため、3D画面の実表示時刻を判定に用いた。
- 実PMX＋実VMD、骨名が一意、インスタンス未ロック、補正データに不一致なし、該当時刻がレイヤー重み100%の有効区間内でなじませの外、単一レイヤーの場合だけ有効にする。条件を満たさないと理由を表示して無効化する。
- 3Dリング操作中は、既存のモデル全体の配置ハンドルを隠し、カメラ操作も止める。合成画面ではFK操作欄を骨の反対側へ寄せてリングを露出する。ハンドルを隠すとモデル配置欄を戻す。撮影画面ではリングを作らない。
- ドラッグ終了時に対象骨だけの保存補正を一時的に外した同フレームの姿勢から局所四元数差分を求める。元レイヤーとシーンをすぐ復元し、既存の数値FK仮プレビュー経路へ渡す。再評価後の角度差が0.01radを超えた場合は仮補正を破棄する。Escはドラッグ前の姿勢へ戻し、キーを作らない。

## 実機試験

`tests/studio-v05-pmx-fk-gizmo-real.test.cjs`を追加した。実PMX＋実VMDのF240で、F不一致時の無効化→同時刻へ移動→3Dリングの実マウスドラッグ、Esc取消、頭骨だけの仮表示、既存FKキー保存と画面再読込、モデル配置欄への復帰を検査。ドラッグ後の頭骨四元数差は0.685652、無関係のセンター骨差は1e-5未満。保存キーはF240・頭骨。マーカーと操作欄が重ならない実画面座標も検査した。

`BAI_REAL_MMD_DATA=<既存data>`、`CHROMIUM_PATH=<Chrome>`、`BAI_TEST_CONCURRENCY=1`で`node tests/run-guarded.cjs tests/studio-v05-pmx-fk-gizmo-real.test.cjs`と従来の`tests/studio-v05-pmx-fk-edit-real.test.cjs`が各1/1成功。`npm run typecheck`、JS構文、`git diff --check`も成功。Chrome描画器はSwiftShader。元PMX SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`、元VMD SHA-256 `3ae724f9d1d36a7e74a911d6b1bbfad7d2459e5e256fcac43521ebebd0a3d234` は前後一致。両試験の`run-guarded`で利用者`data/`7ファイルと`exports/`の前後ハッシュも一致した。

途中の1回はChromeが操作後に`ERR_NO_BUFFER_SPACE`を記録して試験失敗となり、隔離ブラウザを閉じた再実行では同じ全操作が成功した。原因は未特定。診断用の一時画像は試験後に削除し、成果物として納品していない。
