# LIP-004 v0.5口形対応表の編集画面（Issue #175）

## 接続範囲

口モーフ解析の折りたたみ欄内にA/I/U/E/O/Closed/Restの7枠を設けた。登録済みPMXの解析で得た実在口モーフだけを選択でき、グループ型・無変位型には「手動確認」を表示する。各枠の重み0〜1を明示し、下書きまたは5母音必須の確定として、既存の作品別MorphMap APIへrevision、素材ID、原本hash、解析hashとともに保存する。これは表情キーへの自動適用や自然な強度の自動認定を行わない。作品・モデル切替時は旧解析入力を消し、保存済み表は再読込する。原本hash変更の旧表は消さず失効を表示する。

## 試験

`BAI_REAL_MMD_DATA` を指定し `node tests/run-guarded.cjs tests/studio-v05-pmx-morph-analysis-ui.test.cjs` を隔離Chromeで実行し1/1成功。実PMX A（SHA-256 `542a4daa561f0b0da578fc303af9b8c6dc4acdd8d380771a170e96e95a205488`）の48口モーフからグループ型の「あ/い/う/え/お」に試験重み0.8/0.7/0.6/0.7/0.9を指定し、下書きrevision 1、確定revision 2をGETで読み返した。画面の再読込後にも選択と重みが復元された。別の実PMX B（SHA-256 `d784722b85991df3a89931ef1066786205f1a9845a7995d611206ecca0bdd841`）は口モーフ0件で保存ボタンが無効。同じ隔離サーバー内のPMX Aコピーを変更してハッシュを変え、旧表IDを保ったままAPI `source_status=changed` と画面の原本変更表示を確認した。作品scene revision・表情キーは不変で、実データ7ファイル・exports 0ファイルの監視ハッシュと元PMX A/BのSHAは前後で一致した。

最初の試験は入れ子の見出しに対するテストセレクタの曖昧さで失敗し修正。次の試験はBの口モーフ0件でも保存ボタンが有効だったため修正。全面再読込を重ねた失効試験ではWindowsの `ERR_NO_BUFFER_SPACE` が発生したので、選択PMXの解析操作で再読込する手順に絞り、最終試験でエラーなしを確認した。`npm run typecheck`、JS構文、差分検査も成功。

試験重みは保存契約の値であり、実見た目を確認したOwner採用値ではない。表情キーへの適用、強度の実プレビュー調整、VRM表情、WebMCP/標準MCP、Linux、統合production保存・耐障害性は未実装・未検証。LIP-004全体は未完成。
