# 実素材由来の混合音声・FPS確認（2026-11-06）

対象: 順3、Issue #39/#81、`AUDIO-001` / `RENDER-006`。製品の時刻計算は変更せず、既存の音声混合を復号PCMで検証する。

## 入力と測定方法

Ownerの登録動画 `library:e1d28fe47744328e3d66fe54` は3秒・12fps、音声トラックなしだった。登録WAV `library:fd895f1ca8efd8b2bfbe0f43` とともに読み取り専用入力とし、試験用一時領域だけで次の派生素材を作った。元から音声を内包する実動画の検証とは区別する。

- 登録動画を繰り返した15秒のコピーへ、実WAVの10秒位置からの音声をAAC/44.1kHzで内包。
- 実WAVの40秒位置から15秒を48kHzの独立WAVへ変換。
- 動画を作品0.37秒、元位置1.1秒、長さ10秒で配置。独立WAVを作品1.13秒、元位置2.2秒、長さ8.6秒で配置。背景画像は12秒、合成GLBを場面に配置。
- 作品FPSは24／29.97／60。Inを `ceil(0.5*fps)`、Outを `ceil(11.5*fps)-1` とし、非0開始の3D入り720p MP4を書き出す。

動画とWAVを独立に8kHzモノラルへ復号し、保存した配置・元位置から参照波形をサンプル単位で組み立てる。完成MP4のPCMに対して0.7／1.6／4／8.9／10秒（作品時刻）の0.3秒窓で相互相関の最大位置を探す。音量の正規化に影響されない相関で時刻差を検査し、動画だけの区間・両音声の重なり・独立WAV終了後の区間を含める。10.8秒付近は両クリップ終了後の無音も検査する。

## 確認範囲と限界

`tests/studio-v05-mixed-audio-fps-real.test.cjs` は派生入力の44.1/48kHz、登録素材と元hash、保存再読込後の元位置、作品FPS、完成物264/330/660F、ジョブの入力hashを照合する。原本動画・WAV・登録indexの前後hashを照合し、利用者dataや8765番サーバーへ保存しない。

これは短い実素材由来の派生入力での音声配置検証。実動画の元からの内包音声、他のcodec、長尺の混合、映像内容と音の意味的な一致、動く3Dの時刻、Linux/実MCPは未確認。全作品への同期保証や順3完了へ広げない。

モデル区分: 標準モデルで試験実装・実素材検証・記録。

## 実行結果

Windows・Chromeで `BAI_REAL_MMD_DATA` と `CHROMIUM_PATH` を指定したNode隔離試験は、1成功・0失敗・0スキップ（約31秒、内部3条件）。24/29.97/60fpsの出力は264/330/660F。5地点×3条件の計15地点で時刻差0サンプル、相関0.99958以上、両クリップ終了後のRMSは0だった。原本動画・WAV・登録indexとガード対象data 5ファイルは前後hash一致。Node構文と差分空白検査は成功。

初回は作品の最終クリップより後へOutを置いた試験設定が400で拒否された。背景画像で12秒の作品尺を確保して無音区間も測れるよう試験を修正し、最終版を再実行した。製品の時刻計算の変更は不要だった。
