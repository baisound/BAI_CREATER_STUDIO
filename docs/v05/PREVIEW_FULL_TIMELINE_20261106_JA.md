# 保存済み書き出しOutによるプレビュー途中停止（2026-11-06、Issue #39）

## 原因と変更

v0.5の作品プレビューは、書き出し用の保存済みIn/Outを再生開始・終了にも使っていた。稼働中のローカルサーバーへ読取専用GETを送り、1作品で保存クリップの最終時刻が11.8秒、書き出し範囲がF60〜F119、作品最終Fが707であることを確認した。この状態ではプレビューがF119（約1.98秒）で止まり、F120以降へシークできない。作品名・素材名・原本は変更していない。

`studio/v05/js/project-media-preview-v68.js` のプレビューは、作品の保存済みクリップから計算した `final_frame` を再生終端に使い、先頭はF0とした。書き出しのIn/Outは従来の保存APIと出力処理に残す。書き出しマーカーが古くなって範囲が無効でも、作品のクリップ終端が有効ならプレビューを開ける。

## 検証

- Windows Node 22.16.0、Chrome 156.0.8078.80、隔離データの実ブラウザで `node tests/run-guarded.cjs tests/studio-v05-project-media-preview.test.cjs tests/studio-v05-render-range.test.cjs tests/studio-v05-home-time-playhead.test.cjs` を実行し、4件成功・失敗0・スキップ0。
- 新しい回帰例は6秒の保存画像クリップと書き出しOut=F59を作り、プレビューが最大F359を示し、F180へのシークとF190を超える連続再生を確認した。書き出しAPIを再読込してもOut=F59を保持した。
- 試験前後の実 `data/` 5ファイルと `exports/` なしのハッシュは一致。共有作品への書き込み、稼働中8765番サーバーの再起動は行っていない。

## 残る範囲

稼働中の作品を新コードで再生する確認、実楽曲・実PMXの長尺再生、Linux/実GPU、Issue #39全体のPMX＋GLBダンス同期と音画1F以内は未確認。`AUDIO-001` は「一部実装・未検証」のまま。
