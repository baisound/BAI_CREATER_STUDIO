# MOTION-010 下位FKの複数上位層とIK・付与拒否

2026-10-24、Issue #106。下位FKを直接3D編集する限定条件を、実PMXのIKリンク骨・付与対象骨と非可換な2つの上位同骨補正で確認した。

## 対象

- 201骨の `Baisound-New-V5.0.0-B_新狐面差替_紐鈴物理_調整v6.pmx` は、PMX定義で `左足` が `左足ＩＫ` のリンク、`左目` が回転付与の対象。下位層を選んで各骨を選択すると、3Dハンドルを無効にしてIK・付与の影響を理由として表示した。上位層に対象と異なる頭骨キーが共存する場合も、IK・付与の理由を先に示すようにした。
- 246骨の `avatar-front-garment-v04.pmx` では、下位層に頭骨位置0.02、上位第1層に頭骨Y回転0.2rad・位置0.01、上位第2層に頭骨X回転0.24rad・位置 `[0,-0.008,0.004]` を保存。X・Y軸の回転は非可換。下位層の頭骨回転と位置を別々に3Dドラッグし、仮表示・キー保存・再読込後の局所姿勢一致（各成分差1e-5未満）、上位2層のキーJSON不変と未操作チャンネル保持を確認した。
- `node tests/run-guarded.cjs tests/studio-v05-pmx-fk-lower-layer-real.test.cjs`：修正後の2モデルは2件通過、0失敗、0スキップ。`data` 7ファイルと `exports` 0ファイルの前後ハッシュ一致。`npm run typecheck`、`node --check`、`git diff --check` も通過。

最初の実行ではIKリンク骨が拒否されるものの、上位の別骨キーを理由として先に表示したため、理由を検査する試験が1件失敗した。判定順をIK・付与優先に直し、再実行で通過した。入力PMX/VMDは隔離サーバーに複製し、原本の前後ハッシュは一致した。

この検証は物理OFFの隔離Chrome/SwiftShaderと上記2モデルに限る。別のIK・付与構成、物理ON、実GPU、Linux、標準MCP実通信、Owner採用、MOTION-010全受け入れ条件は未確認。画像・動画成果物はないためEagle登録対象なし。モデル区分：実装・試験・文書に標準モデル区分を使用。
