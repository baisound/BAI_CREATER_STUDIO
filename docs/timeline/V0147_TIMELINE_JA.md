# v0.14.7 共通タイムライン編集：基礎実装

## 目的と範囲

既存のコンビネーションの元モーションを変更せず、クリップの「開始フレーム」「長さ」「再生速度（0.1〜4.0）」「接続用ブレンドフレーム（0〜120）」を計画・保存する編集基盤を追加。

**重要な未対応**：設定値をFBX/GLB/PMX/VMDの3D再生エンジンへリアルタイム反映する機能、ブレンド演算、時間リマッピングのレンダリング、ドラッグ編集、クリップの実行可能性検証、動画/VMD書き出しは未実装。現在はタイムラインのメタデータを可視化・編集・永続保存する基礎段階。速度や補間値を変えても、現時点で3D再生結果は変化しない。

## UI

ページのメインワークスペースの下に独立した「タイムライン編集」領域を追加。コンビネーション取り込み、クリップ追加、数値編集、削除、自動保存、読み直しが可能。
元のコンビネーションと別管理で、取り込み時点のコピーを作る。プロジェクト履歴のUndo/Redoとはまだ統合していない。

## API

- GET `/api/timeline-editor`: 保存済みスナップショットを返す
- POST `/api/timeline-editor`: `{"schema":1,"clips":[{"name":"Kip Up","start":0,"duration":90,"speed":1,"blend":6}]}`
- サーバー側で形式・範囲・件数を検証し、`data/timeline_editor.json` に原子的に保存。
- 最大200クリップ、リクエスト最大256KiB。
- 登録済み素材との照合は今回未実装。

## WebMCP・標準MCP

- `mixamo_timeline_get`
- `mixamo_timeline_set`

WebMCPはブラウザ画面も更新。標準MCPは保存APIを更新するが、開いたブラウザへの即時反映は未対応（再読込操作で反映）。今後共通同期を予定。

## 検査

- Python構文検査
- JS通常スクリプトの構文検査（importmapは対象外）
- HTTP GET → POST → GET readback確認
- 保存先のテスト生成データは配布版に含めない
- 実ブラウザの表示・編集・動画再生は未検証
