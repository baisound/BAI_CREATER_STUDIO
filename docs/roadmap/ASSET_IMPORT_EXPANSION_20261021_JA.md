# 素材取り込みを制作の入口へ広げる（Issue #37）

2026-10-21のオーナー直接指定。既存ロードマップよりこの入口を先行する。元のFBX/GLB/VRM/PMX/VMD登録と制作状態を残し、素材の登録・選択・確認までを先に整える。新しい素材をシーンへ適用する機能は別の既存要件で扱い、この画面で適用済みと表示しない。

## 利用者の流れ

1. SCR-08の「素材を取り込む…」で複数ファイルを選ぶ。各行で種類を選び、対応形式、上限、同名や重複の扱いを取り込み前に確認する。
2. 成功した素材を一覧に表示する。ステージ・小物・キャラクターは実モデルの画像、材質・エフェクト・画像は画像そのもの、動画は代表フレーム、音声は実波形を見本にする。画像生成中・失敗時も名前と形式で選べる。
3. 詳細欄に登録名・元ファイル名・形式・種類・容量・登録元・タイトルの出典・利用できるメタデータを示す。3Dは回転できる実モデル、音声と動画は再生・一時停止・停止・前後5秒・シーク、画像は原画像を表示する。
4. 音声・動画・画像のタイトルは利用可能な埋め込みタイトルを優先し、無ければ拡張子を除いたファイル名にする。メタデータを読めない場合も取り込みを止めず「ファイル名から」と示す。

## 取り込み契約

| 分類 | 入力 | 見本・詳細 |
|---|---|---|
| ステージ・小物 | 単一ファイルにまとまったGLB | 実モデルの3Dと正面寄りの保存済み画像。GLBの外部参照は取り込まない |
| マテリアル | PNG/JPEG/WebP/AVIF/BMP画像 | テクスチャ画像と寸法。モデルへの材質適用とは区別 |
| エフェクト | PNG/JPEG/GIF/WebP/AVIF画像、またはGLB | 画像／3D形状を見せる「エフェクト素材」。動的なMME実行・シェーダー適用はまだしない |
| オーディオ | WAV、MP3 | 実サンプルから描く波形、HTML音声再生、再生位置・時間 |
| 動画 | MP4、WebM、OGV | 動画フレームの保存済みサムネイル、HTML動画再生、寸法・時間 |
| 画像 | PNG、JPEG、GIF、WebP、AVIF、BMP | 一覧と詳細に原画像。GIFは詳細でアニメーションを保持 |
| 既存キャラクター・モーション | 従来形式を維持 | 既存の詳細情報・再生を壊さず、同じ詳細欄へ種類別情報を統合 |

ブラウザが復号できないコーデックや画像形式は、登録の可否と再生の可否を分けて表示する。SVGはスクリプト混入の危険があるため、この段階では対象にしない。TIFF/HEIC等はブラウザ標準表示を保証できないため受け付けず、理由を表示する。MP4/WebM/OGVの再生可否は実際の動画・音声コーデックにも依存する。

## 保存・安全

- 新しい `library_assets.py` と `DATA/library_assets/` を使う。元ファイルはSHA-256由来の保存名で別名保存し、索引JSONを原子的に更新する。既存のmanifest、統合素材、MMD素材を変更しない。`BAI_DATA_DIR`に従う。
- `POST /api/library-assets/upload?kind=...&name=...` は登録種類と拡張子の組を検査し、先頭の形式署名も確かめる。通常は最大400 MiB、GLBステージだけ最大1 GiBとし、空ファイル・危険な名前・未知形式を拒否する。同じ内容・種類・元名なら同じIDを返し、黙って既存ファイルを上書きしない。
- 2026-10-21の追加受領により、**GLBステージだけ**上限を1 GiBに拡張する。他分類は400 MiBのまま。128 MiB超のGLBは一覧・詳細で自動3D読込しない。詳細では明示操作時だけ開く（[Issue #44の負荷記録](STAGE_PACK_GPU_20261021_JA.md)）。
- `GET /api/library-assets/file/<id>` は登録済みIDだけを配信する。音声・動画シーク用に単一のHTTP Rangeを扱い、未登録パスを開かない。`GET /api/assets`には種類、表示タイトル、元名、形式、容量、タイトル出典、検出できた寸法・時間、見本URLを加える。
- 見本はブラウザで元ファイルから生成し、`POST /api/library-assets/thumbnail?id=...`へPNGを送る。サーバーは登録ID・PNG署名・寸法・容量を検査して別名保存する。画像形式は元の配信URLをそのまま使い、3Dと動画は初回表示時に生成する。既存登録素材でも画像が無ければ遅延生成する。失敗時は再試行できる。
- 作品素材、ウェイト、骨、原本には書き込まない。Gitへ元ファイルを追加しない。公開可能なサンプルでも利用条件と入手先を記録する。

## 実装境界と順序

1. 保存APIと純関数検証：`library_assets.py`、`server.py`、Pythonテスト。索引破損・失敗時に既存ファイルを保全する。
2. 取り込みUI：`studio/js/features/import-rules.js`、`import.js`、`assets-model.js`、`assets.js`、`assets-view.js`。従来のPMX ZIP等を維持する。
3. プレビュー：音声実波形と再生、動画代表フレームと再生、画像、GLBステージ・小物の3D見本。画面移動と選択変更時に再生を止め、Canvas/WebGLを破棄する。
4. 利用許諾を確認した外部無料サンプルを取得し、`docs/roadmap/ASSET_SAMPLE_SOURCES_20261021_JA.md`にURL・作者・ライセンス・取得日・SHA-256・配置先を記録する。Crytek Sponzaは限定ライセンスのため使わない。
5. 台帳と自動試験を更新する。登録・再読込・範囲配信・メタタイトル優先・再生・見本・全分類の詳細、Windows/Linuxを確認する。実GPU、全コーデック、利用者の最終採用は別に記録する。

## メタデータの現実的な範囲

サーバーはPython標準ライブラリだけで起動する。MP3はID3v2のTIT2とID3v1、WAVはRIFF LIST/INFOのINAM、MP4は一般的な`moov/udta/meta/ilst`のタイトル、PNG/JPEGは一般的なTitle/EXIF説明を読む。未知・壊れたタグはファイル名に戻す。WebM/OGVやGIF等で標準的なタイトルが無いものもファイル名を使う。詳細には「メタデータ」か「ファイル名」かを必ず示し、全てのタグを読めると約束しない。

仕様照合: [ID3v2.3 TIT2](https://id3.org/id3v2.3.0)、[Microsoft RIFF/WAVE](https://learn.microsoft.com/en-us/windows/win32/multimedia/resource-interchange-file-format-services)、[HTML media seek](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime)。

- 従来5形式を再登録でき、新分類の全入力について適切な登録・一覧・詳細が表示される。取り込み後の再起動でも索引とサムネイルを読める。
- タイトル付きMP3/WAV/MP4/PNGと無タグの同形式で、メタタイトル優先・ファイル名へのフォールバックを示す。実波形は音声内容に応じて変わる。

- サンプルの出典・ライセンス・ハッシュを確認でき、外部素材をソース管理へ混ぜない。

設計判断：高性能モデル区分。既定を決めた後の実装・定型試験：標準モデル区分。
