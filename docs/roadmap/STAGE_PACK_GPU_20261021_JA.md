# 受領ステージ更新と大型GLBの負荷対策（Issue #44）

## 受領・保持

- Owner指定の受領READMEにある7件をサイズ・SHA-256で照合し、ローカル素材ライブラリへ非破壊で登録した。S01は既存IDを再利用、残り6件は別IDで追加。原本は読み取りのみ。ローカルの登録IDとハッシュは `data/library_assets/receipt_stages_20261021.json` に記録した（Git対象外）。
- S01の現在のシーン選択・位置、キャラクター、音楽、ライト、保存履歴は変更していない。新しい受領GLBの最終外観採用はOwner判断待ち。
- 最大のGLBは692,894,092 bytes（約661 MiB）。ステージGLBに限り上限を1 GiBに広げ、その他の素材は400 MiBを維持する。保存APIは既存の逐次コピーと署名・長さ・ハッシュ検査を使う。

## ブラウザ負荷と対策

- 2026-10-21、RTX 4070 SUPER／Direct3D11のChromeで、最大GLBの**読み取り専用単独プローブ**は完了した。GLB取得3,070 ms、解析2,365 ms、初回全景描画3,915 ms。9,777メッシュ、383テクスチャ、`EXT_mesh_gpu_instancing`から2個のInstancedMesh／16インスタンスを認識した。WebGLの描画器を確認した結果であり、全処理がGPUだけで行われる意味ではない。
- 全景視点では9,770描画呼び出し・約3.92億三角形、同じGLBの原点付近では1,871呼び出し・約7,800万三角形。10回の描画関数呼出しの中央値は各49 ms・19 msだった。実アニメーションのFPSや別PCの性能を保証する値ではない。
- 隔離ブラウザの追加検証中にPC操作が困難になり、Ownerが再起動した。CPU使用率・RAM・VRAMの同時記録はなく、原因を断定しない。ただし巨大GLBの別コピー、Chromeでの解析、既存アプリとの同時実行が高負荷を招いた可能性が高い。**この素材の全量ブラウザ試験は再実行しない。**
- 大型ステージの初期視点を原点支持面付近とし、全景を最初に描かない。素材一覧の自動3Dサムネイルと詳細欄の自動3D読込は128 MiB超で停止する。詳細欄は容量と負荷を示し、利用者が「3D見本を開く」を押した時だけ読込む。シーンでの明示選択は維持する。描画器は大型ステージのビュー内にGPU／ソフトウェアとして表示する。
- 描画距離によるLOD、ジオメトリ削減、実FPS保証は今回実装していない。原本を改変せず、品質を確認してから別途扱う。

## 確認済み・未確認

- 登録7件の入力ハッシュ一致、ライブラリID、最大GLBのHTTP Range取得を確認。取り込み分類のNodeテスト18件、ライブラリAPIの小型素材テスト3件、TypeScript検査に合格した。大型GLBの自動サムネイル抑止も通信しない単体テストで確認した。
- 最大GLBをシーンUIへ配置する隔離試験は、Owner端末に重大な負荷が出たため中断。原点付近への初期カメラ変更と自動読込抑止は小型素材・静的検査で確認し、最大GLBの実画面再試験は行わない。GPU上の単独プローブとシーンUIの完了判定を区別する。
- 低性能GPU、Linux、WebMCP／標準MCP、Owner外観採用は未確認。機能台帳は要検証のまま。
