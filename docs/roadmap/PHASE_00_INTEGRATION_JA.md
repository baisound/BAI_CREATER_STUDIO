# Phase 00：機能統合・UI再設計・スマートデータ移行（最優先）

## 位置付け
従来のPhase 01より前に置く**必須先行工程**。ユーザーの添付 `20261015_v02(1).zip` を対象として、118既存要件+12件の移植レビュー用IDを照合。**新規コード移植前のドキュメント専用変更**。

## 実装順と完了ゲート
1. **差分・権利・依存監査**：両アプリの機能とソースの対応、素材ライセンス、ファイルsha、依存グラフを確定（REVIEW-010）。
2. **共通プロジェクト・モデル台帳**：VRM/PMX/FBXのモデルID・リグ/モーションID・コンテンツhashを統一（DATA、MOTION、REVIEW-011）。
3. **UI統合再設計**：上位タブを「制作」「素材/モデル」「モーション」「比較/QA」「カメラ」「リリック」「エフェクト」「出力」に整理。比較は3画面元/対象/オーバーレイを別タブではなく共通ビューに集約。レビュー専用計測を右インスペクタで展開（REVIEW-001,002,012）。
4. **共通サービス層**：UI/WebMCP/標準MCPが同じ検証・保存APIを呼ぶ。clientId/プロジェクトrevision/排他・確認操作を揃える（REVIEW-003,004,005）。
5. **厳選データ移行**：VRM3、制作中FBX3、モーション原本/ライブラリ（重複hashを除外）、完成判定とボーンマップ、小道具専用データを参照可能にする。旧原本は変更しない。
6. **機能移植**：VRMアダプター、掌2軸校正、SpringBone比較、監査/キャプチャ/全身フレーミングを段階導入（REVIEW-006〜009）。
7. **容量整理**：監査生ログや画像は別アーカイブ、配布版は概要と参照インデックスのみ。削減率を測定。オフラインライブラリとライセンスは必要に応じ保持。
8. **受け入れ検査**：手動/両MCP・VRM・PMX・既存VMD・単体/3連結・モデルごと校正・QA・保存復元・Windows/Linux起動を検証。旧機能回帰を確認。
9. **Gitコミットとタグ**：監査、UI、移植、最適化の個別コミット＋テストゲート通過後にリリースタグ。
