# 添付 `20261015_v02(1).zip` 機能・データ監査（Phase 00）

## 結論
このZIPは **新春企画用・複数キャラクターVRM/FBXモーション動作確認ビューアー（レビュー v02）**。Mixamo動作、CC0モーション、専用扇モーションの実モデルへの転送と、フレーム毎の接地・衣装/手の干渉検査・3画面比較・標準MCPを持つ。既存Mixamo統合スタジオと重複する部分はエンジン/ビュー/診断で統合する。異なるのは現状VRM/FBX向けで、PMX/VMD制作は対象外という点。

## ソースから確認した数値
- ファイル数：224。展開サイズ：389.5MB。添付ZIP自体は約247MB。
- 動作：READMEに **203原子動作・15チェイン**。manifest値 atomic=203, chain=15。
- キャラクター定義：14体、完成VRM：3体、制作途中FBX：3件。
- GLBのモーションライブラリ：9件（コンテナファイル数≠動作本数）。
- 大型実行環境：`runtime/node.exe` 85.1MB。モデル素材の拡張子合計：185.4MB。
- `evidence/` のJSONだけで約56.1MB。診断はモーション・モデルhash・物理設定に依存する。
- `evidence/frontend_dependency_report.json` は静的モジュール解決 PASS、**ブラウザ実行保証ではない**。
- `evidence/mcp_test_report_v02.json` はstdio初期化/ツール検出/引数拒否などの PASS、**WebMCP対応の証拠ではない**。

## スマート化：保存 / 隔離 / 削減候補
**必ず維持：** 実モデルVRM/FBX原本、モーションの実体、ソースmanifest、キャラ別ボーンマップ、正本識別hash、権利表/ライセンス原文、要素別の校正コード、手動修正履歴、結果のうち採用された診断基準。

**移植せずアーカイブ候補：** `evidence/` の大容量フレーム全件監査JSON、`captures/` スクリーンショットの重複、`logs/` 内の複数の監査ZIP、過去の修正ログ、派生再検証JSON。プロジェクト用UIが参照しないことを検証後、ハッシュ/概要レポートだけを新プロジェクトに入れ原本はアーカイブ保管。

**一元化候補：** `kit/vendor` と `runtime/vendor` の重複依存、`runtime/node_modules`、Windows用 `runtime/node.exe` の配布形態。**完全オフライン要件とのトレードオフ**があるため未配置の代替依存を検証するまで削除しない。Windows配布の同梱Nodeも任意ダウンロード方式にしない限り保持が必要。

**対象外扱い：** 外部の絶対パス、既に削除された外部プロジェクトへの参照はそのまま移植せず、移植先の相対パス/コンテンツアドレスIDへ変更。`kit/` の未使用に見えるモジュールも静的/動的依存解析前は削除しない。

**安全原則：** 既存ZIP・原本を無変更で保存。移植対象をハッシュ照合して新ディレクトリへコピーし、テスト後にのみ不要候補を別アーカイブに移す。**今回削除したデータはゼロ**。

## 追加要件と制限
1. **全機能の手動UI・WebMCP・標準MCPの同等性。** 添付は標準MCPの実装があるがWebMCPが動作する証拠はない。
2. PMX/VMDは添付の機能対象外。既存MMD機能を置き換えずVRM向け検証を追加する。
3. 視覚QA/物理QAはモデルhash、fps、物理ON/OFF、プリロール、元動作hashを記録してから合否判定する。
4. 第三者素材やキャラクター原本の再配布条件を個別確認。元READMEも私的作業用であり公開再配布パッケージではないと明記。
5. 大規模監査の保存方針：結果概要をGit管理、巨大な生証跡・モデル・音声はGit外のアセット保管へ。
