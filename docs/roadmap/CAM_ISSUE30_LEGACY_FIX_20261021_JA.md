# Issue #30：旧 BAI Camera の構図・操作修正（2026-10-21）

依頼：[旧 BAI Camera の撮影と周回を直す #30](https://github.com/baisound/BAI_CREATER_STUDIO/issues/30)。関連IDは CAM-003（キー・再生）、CAM-004（被写体範囲）、CAM-010（周回）、CAM-011（顔ターゲット）である。Phase E 全体やこれらのID全体を完了と判定するものではない。

## オーナーが確認した操作と期待

素材表示名 `baisound-new-v3.5.1.vrm`（登録ファイル `21130746078bfaf0ce15.vrm`）を旧 `camera.html` で読み込み、`顔アップ（汎用ターゲット）` を現在フレームに適用し、撮影リグの `オービット` を `リグを現在構図へ適用` した。最初から顔が視聴者を向き、顔アップでは腰上ではなく顔が主役になり、撮影画面を自由に回せることを期待する。一周の動きも迷わず作れることが必要。

## 原因と修正

| 症状 | 原因 | 修正 |
|---|---|---|
| 初期正面で背中側 | VRMの正面がモデル空間の -Z、既存プリセットのカメラは +Z | 読み込み後の表示用ラッパーを180度回す。原本の節点・アニメーション・ウェイトは変更しない |
| 顔アップで胸から腰が入る | 固定座標 `target=[0,1.5,0]`、距離1.7でモデルの顔位置を見ていない | 目または頭ボーンの表示座標を求め、顔の高さを注視する。距離0.55、垂直FOV32度とする |
| オービット後に顔が外れる | 既定リグ中心 `[0,1,0]` が顔アップの注視点と違う | 静止オービットは現在の注視点を中心に回す |
| 撮影画面をドラッグしても回らない | モデル読込後に非表示となる2D canvasへ操作イベントを登録していた。回転計算の外積が3次元なのに2成分しか返していなかった | 可視の撮影パネルへイベントを登録し、外積を3成分に直す。ドラッグ中も構図を表示する |
| 周回の途中で止まったように見える | 保存済みカメラキーは90フレームで終了し、尺300フレームまで同じ構図が続く。最初のGLBクリップが T-pose の例もあった | 最終キーと再生範囲を画面に表示する。既存キーの次から残りの尺へ360度キーを一括生成する。素材名に一致する動作クリップを優先し、T-pose以外を次候補にする |
| 被写体範囲が実表示と違う | スキニング済みメッシュの境界を高速近似で測り、さらにワールド変換を二重に掛けていた | モデル行列更新後に変形後の頂点境界を正確に計算し、実際の位置で全身を収める |

顔アップとリグ適用は自動キーOFFではプレビューのみ。画面のボタン名に「1回適用（静止）」と記し、動画にする場合は「残りの区間を一周撮影にする」を選ぶ。後者は表示中の未保存プレビュー構図を開始構図に使うが、既存キーを上書きせず、生成キーもプロジェクトの保存操作までは未保存と明示する。
