# Phase E — プロジェクト状態の保存・再読み込み統合契約

決定日: 2026-10-19 / オーナー依頼 / 優先度: 高（Phase E完成前必須）

## 既存機能と不足
- `PROJECT_STATE_DEVELOPER_GUIDE_JA.md` の `GET/POST /api/project` はコンビネーション主体の単一プロジェクト保存。モデルバイナリは別管理、撮影カメラ等は履歴対象外。
- カメラには別系統の `camera_project.json` 保存処理があり、キー、リグ、追従、プリセット等の項目が段階的に追加された。
- これらが**一括して再開可能な状態に戻ることは未検証**。既存実装があるので別の保存機能を乱立させず、整合・統合する。

## 必須保存対象
1. アクティブモデル・素材の安定ID/参照、欠損時の警告（巨大バイナリのJSON埋込はしない）
2. モーション・クリップ・配置、再生FPS、現在フレーム、再生範囲
3. カメラキー、補間、VMD参照・追従状態、撮影リグ階層、レール/クレーン、撮影プリセット・ショット
4. レンズ（FOV/焦点距離/F値）、DOF ON/OFF、合焦距離、ボーンフォーカス追従、色分けフォーカステスト設定
5. 2画面の編集操作に必要な選択と表示設定（再生中フラグは原則停止状態で復元）

## 保存・復元の契約
- 単一のプロジェクト保存操作から関連状態を一貫したスナップショットにする。保存失敗は成功扱いにしない。
- 旧schema=1および旧カメラプロジェクトに対し後方互換・既定値の適用を用意し、未知フィールドの破棄を監査する。
- 参照素材の欠損は黙って他のモデルに置換せずユーザーに提示する。VMD原本・キーを勝手に上書きしない。
- 保存→アプリ再起動相当の初期化→再読込→全状態比較を実施。カメラキー、リグ、レンズ/DOF、追従、現在フレームを含める。
- UI、API、WebMCP、標準MCPの保存/開く操作と失敗応答を揃える。競合・原子的保存・ファイル参照整合性をテストする。
- CAM-005の光学・フォーカス連動は復元直後も維持。GPU描画は実機未検証なら完成と判定しない。

## 完了条件
実装・自動往復テスト・実ブラウザー統合テスト・MCP双方の確認・欠損素材テストを満たすまで未完成。追加機能ではなく以前から存在する保存・復元機能の完全化。

## 2026-10-19 実装チェックポイント（統合APIの初期段階）
- `GET/POST /api/project/bundle`、`project_state_bundle.py` を追加。従来のコンビネーションとカメラ状態を一括検証・保存する初期経路を作成。
- 未知のトップレベルフィールドは、黙って消さずエラーで返す。未保存のコンビネーション状態は `complete: false` として返す。
- 電源断耐性を備えた2ファイルの原子トランザクションではない。UIと双方のMCP、素材参照、タイムラインの再生位置、DOF設定の完全復元は未接続。Phase E完成ではない。
- 次の最優先: 既存UIの「保存/読み込み」を統合APIへ接続する前に、素材IDと選択状態を含む保存契約、復旧ジャーナル、旧データ移行を仕上げる。
