# P2-WP-05e 実装前照合（2026-10-21）

正本は [P2 詳細設計 §2.5](P2_PORT_DETAILED_DESIGN_20261020_JA.md) と [P2 進捗台帳](P2_PORT_STATUS.json)。対象は SCR-13［編集］の下部タイムライン（⑤-6）と非破壊モーション補正レイヤー（⑤-13）のみ。旧画面と既存 API は変更しない。

| 対象 | 現行の根拠 | WP05e の実装先 |
|---|---|---|
| クリップの編集・550ms 自動保存 | `index.html` の `safe`・`draw`・`queue`・`save`（約 790〜814 行） | `motion/chain.fork.js` と `features/motion-timeline.js`。内容比較を保存前に追加 |
| 再生時計・FBX の姿勢 | `index.html` の `timelineFrame`（約 260〜289 行） | `chain.fork.js` の計算と SCR-13［編集］の 3D ビュー。FBX 以外は再生不可 |
| 補正レイヤー・500ms 自動保存 | `motion_layers.js` の `safe`・`values`・`apply` | `motion/layers.fork.js` と下部の折りたたみ編集領域。モデルの回転への加算は再生中だけ |
| 保存 API | `server.py` の `/api/timeline-editor`・`/api/motion-layers` | 既存の GET/POST を `studio/js/api.js` 経由で利用。サーバーや保存形式は変えない |

現行の `motion-view.js` は SCR-13［編集］で PMX+VMD と GLB/VRM の単体再生を所有する。WP05e はモデル候補に登録 FBX `modelA/modelB` を追加し、タイムライン再生の開始時に単体再生を一時停止する。下部は `app.js` の `featureBottom` と `features/index.js` から `motionTimeline` を使い、未接続のサンプルトラックはサンプルとして残す。

保存の基準値は最後に GET／保存した正規化済み内容。編集後 550ms（レイヤーは 500ms）で再 GET し、内容が基準値と違えば POST せず競合を表示する。［上書き保存］は確認後にだけ POST する。サーバーの API に版条件が無いため GET と POST の間の競合は残る（設計リスク K12）。画面を離れる際の予約済み保存の実行と `beforeunload` 警告を区別する。

検証は計算・自動保存を偽時計で、編集・競合・FBX 再生・レイヤー回転を隔離サーバーと Chrome/SwiftShader で確認する。実 FBX と GPU 実機は未検証として台帳に残す。WP05b/c の必須独立レビューは未確認であり、この照合では完了扱いにしない。ボーンのスキニングとウェイトは対象外。
