# Issue #34・#35: モーションのグレーマンとキャラクター正面画像

2026-10-21 の Owner 直接指定。対象は SCR-08 の素材一覧・詳細。原本モデル、ボーン、既存ウェイト、制作状態には書き込まない。

## #34 動くグレーマン

- 既存の FBX/GLB モーションは、そのファイルに含まれる骨とクリップを再生する。VMD は既存の PMX 選択と MMDAnimationHelper の IK・grant 評価を使う。
- 元メッシュだけを表示から外し、同じ骨の世界座標から灰色の頭・胴・骨盤・腕・脚・手足の**剛体形状**を毎フレーム配置する。新しいスキニングやウェイトは作らない。[Three.js の Object3D 世界座標](https://threejs.org/docs/pages/Object3D.html)で姿勢を取得する。
- 再生・一時停止・シーク・クリップ/PMX切替・素材切替の既存操作を保つ。切替時は rAF、AnimationMixer/MMDAnimationHelper、WebGL リソースを解放し、二重再生を防ぐ。
- 必須骨を同定できない素材では、誤った人型を表示せず、従来の元形状プレビューで再生しながら「グレーマンに必要な骨がありません」と示す。VMD に PMX がない場合も既存の理由を示す。顔や指の細部はこの中立見本の対象外。

## #35 正面サムネイル

- 登録済みキャラクター（integrated GLB/VRM、MMD PMX、FBX modelA/modelB）を読み込み、正面からレンダリングした PNG を `data/asset_thumbnails/` に別保存する。実ファイルの上書きはしない。VRM は既存カメラ実証と同じ向きの補正を見本オブジェクトにだけ適用する。
- 初回登録後に生成を試みる。既存の画像なし素材は SCR-08 を開いたとき順に補完する。重複要求はまとめ、生成に失敗しても一覧や元素材を維持する。
- サーバーは登録済みキャラクター ID だけ受け付け、PNG のサイズ・形式を検証して保存する。キャッシュ識別には ID と元ファイルのサイズ・更新時刻を使い、元ファイルを差し替えた場合は古い画像を配信しない。保存済み画像 URL は `/api/assets` に反映し、再読込時に再生成しない。
- [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer) の一時描画から PNG を得る。低性能端末への負荷を抑えるため、生成は一件ずつ実行する。
