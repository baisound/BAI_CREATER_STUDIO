# Issue #34・#35: モーションのグレーマンとキャラクター正面画像

2026-10-21 の Owner 直接指定。対象は SCR-08 の素材一覧・詳細。原本モデル、ボーン、既存ウェイト、制作状態には書き込まない。

## #34 動くグレーマン

- 既存の FBX/GLB モーションは、そのファイルに含まれる骨とクリップを再生する。VMD は既存の PMX 選択と MMDAnimationHelper の IK・grant 評価を使う。
- 元メッシュだけを表示から外し、同じ骨の世界座標から灰色の頭・胴・骨盤・腕・脚・手足の**剛体形状**を毎フレーム配置する。新しいスキニングやウェイトは作らない。[Three.js の Object3D 世界座標](https://threejs.org/docs/pages/Object3D.html)で姿勢を取得する。
- 再生・一時停止・シーク・クリップ/PMX切替・素材切替の既存操作を保つ。切替時は rAF、AnimationMixer/MMDAnimationHelper、WebGL リソースを解放し、二重再生を防ぐ。
- 必須骨を同定できない素材では、誤った人型を表示せず、従来の元形状プレビューで再生しながら「グレーマンに必要な骨がありません」と示す。VMD に PMX がない場合も既存の理由を示す。顔や指の細部はこの中立見本の対象外。

## #35 正面サムネイル

- 登録済みキャラクター（integrated GLB/VRM、MMD PMX、FBX modelA/modelB）を読み込み、正面からレンダリングした PNG を `data/asset_thumbnails/` に別保存する。実ファイルの上書きはしない。VRM は正面の +Z、その他は左右の肩と上下の骨から前方向を推定する。
- 初回登録後に生成を試みる。既存の画像なし素材は SCR-08 を開いたとき順に補完する。重複要求はまとめ、生成に失敗しても一覧や元素材を維持する。
- サーバーは登録済みキャラクター ID だけ受け付け、PNG のサイズ・形式を検証して保存する。キャッシュ識別には ID と元ファイルのサイズ・更新時刻を使い、元ファイルを差し替えた場合は古い画像を配信しない。保存済み画像 URL は `/api/assets` に反映し、再読込時に再生成しない。
- [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer) の一時描画から PNG を得る。低性能端末への負荷を抑えるため、生成は一件ずつ実行する。
- PMXのテクスチャはモデル読込後も非同期なので、使用する拡散画像の読込を最大10秒待つ。サムネイル専用に同じ画像を使う単純な材質で撮影し、PMX原本・ボーン・ウェイトは変更しない。スキニング後の精密境界は縮小率が二重に掛かるため、PMXの構図だけ通常の境界を使う。背景だけのPNGは画素確認で保存しない。
- キャッシュが増えた際に一覧全体を作り直さず、表示中カードの画像だけ差し替える。スクロール・選択中にカードが消える競合を避ける。

## ステージの内部サムネイル（後続Owner指定、DATA-016）

- 従来のGLBサムネイルは全体の包囲箱にスカイドームを含み、S01では外側の球体だけを撮っていた。GLB内のメッシュ名と包囲箱を解析し、`SkyDome` 等の外殻を構図計算から除く。壁・天井やドームのある閉鎖型では室内、開放型では外から、水平8方向の候補カメラを作る。
- 候補を低解像度で実描画し、写った面積、色の変化、明暗・輪郭の情報量を比較して最も情報の多い方向を640×480のPNGにする。元GLBのメッシュ・材質・位置は変更しない。採点は構図の推定であり、芸術的な最適解の保証ではない。
- 一覧を開いた際に未生成の登録済みステージも一件ずつ補完する。旧 `id.png` は残し、新しい画像を `id-stage-v2.png` に保存する。カタログと取得APIは新版を参照する。S01の旧球体画像はバックアップしてから新しい室内画像をローカル登録した。
- 実S01を隔離Chrome SwiftShaderで読み、SkyDomeを除いた建築範囲、室内視点、画像の床の写り、保存・再読込と旧画像保持を確認。Owner確認画像は `2026-10-21_stage_light_40/S01_stage_interior_thumbnail_v2.png`。他の閉鎖型GLBでの構図、実GPU/Linux、Owner採用は未検証。
