# UI/UX設計標準（正式決定・全機能共通）

状態: **設計確定／コード実装・利用者テストは未完了**。適用範囲: Mixamo統合制作スタジオの既存機能と将来の全機能。対応要件: `UX-001`〜`UX-008`。

## 基本方針

ユーザーに親切で直感的であることが最重要。一画面に全機能を詰め込まず、制作工程と用途に沿ったタブで整理する。取扱説明書を最初に読ませることを前提にしない。高度な設定は必要なときにのみ開く。

## 画面レイアウト

- **固定の上部領域**：プロジェクト名、保存状態、戻す/やり直し、主要タブ、現在の処理状態を配置する。
- **ワークスペース領域**：プレビューを主役として中央に置き、主な操作は対象機能に応じて左右のパネルで行う。画面幅不足ならパネルを折りたたむ。
- **内部スクロール**：ヘッダーや操作ボタンは固定し、その下の一覧・ログ・検索結果・長い設定フォームだけスクロールさせる。独立スクロールの多重化は最小化する。
- **タブ**：モーション/モデル、タイムライン、ダンサー、カメラ、リップ、リリック、エフェクト、レンダリング、素材管理、設定など。実際の統合時に重複タブをまとめ、タブ内のサブタブは最小限にする。
- **短い注釈**：モードの目的、対象モデル、操作結果、単位（F/mm/m/°/fps等）を近くに表示する。
- **ツールチップ**：アイコンだけのボタンには必ず名前と操作内容を設ける。ホバー・キーボードフォーカス両方で表示し、モバイルでは別の説明経路を設ける。
- **空・エラー状態**：『何が足りないか』『次にどうすればよいか』を短く表示する。AI未接続は通常利用時にエラー表示しない。

## 操作設計

1. 新規利用は「素材を読み込む → モデルを選ぶ → モーションを選ぶ → プレビュー → 編集 → 保存/出力」を主導線とする。
2. 主要アクションを見つけやすくし、頻用操作は1〜2ステップで実行可能に設計する。破壊的操作は確認と復元手段を提供する。
3. プレビュー・タイムライン・選択中モデル/クリップの関係を一貫して可視化する。
4. 情報量の多い設定は「基本/詳細」を分離し、デフォルト値・ヘルプ・単位を明記する。
5. 画面の状態変更は保存対象か一時表示か明示し、保存中・保存成功・未保存を区別する。
6. 手動UI・WebMCP・標準MCPは同じ操作サービスを通し、権限・バリデーション・履歴・ログを共通化する。**AIなしでも作業を完結できること**。

## 完了の判定（各機能）

- 新規利用者が説明書なしで代表的タスク（読込→編集→保存）をたどれることを検証する。
- タブを切り替えても制作データが失われないこと。
- パネル一覧の長いデータで固定領域が隠れず、内部スクロールで末尾まで到達できること。
- ボタン・用語・設定にツールチップ等の補助説明があり、マウスを使わない操作でも理解できること。
- 1280px幅と狭い表示幅の両方で重要操作に到達できること。キーボード操作とフォーカス可視性を確認すること。
- 破壊的操作・エラー・AI停止時の動作が適切であること。
- API/WebMCP/標準MCPへの対応表と受け入れテストを用意し、UI操作と結果を照合すること。
