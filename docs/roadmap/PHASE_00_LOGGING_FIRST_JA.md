# Phase 00 最初の実装：診断ログ・ローテーション仕様（決定事項）

## 状態
仕様確定・**実装未着手**。本コミットは決定事項のドキュメント化のみ。最初の実装タスクとしてPhase 00の他作業に先行する。

## 目的
Windows/Linuxなど利用者の実環境でしか起きない異常を、外部AIサービスへの依存なく再現・解析可能にする。起動、HTTP/API、手動UI、WebMCP、標準MCP、FBX/GLB/BVH/PMX/VMD解析、Blender/FFmpeg、3D描画、レンダリング、同期、保存/復元を観測する。

## MUST要件
- **OBS-001 統一構造化ログ**：JSON Lines、タイムスタンプ（UTC ISO8601）、severity、component、event、session_id、request_id、project_id（匿名化）、operation、duration_ms、result、error_code。人間可読ログ表示は同じイベントから派生させる。
- **OBS-002 サーバーローテーション**：サイズ上限・世代数・保持日数の設定、例：10MiB×5世代・14日。設定で調整可能、ディスク容量上限を守る。起動時再開、競合、権限エラー、ディスク不足を扱う。
- **OBS-003 ブラウザログ収集**：JS例外、unhandledrejection、WebGL contextlost、読み込み/レンダリング失敗、操作イベントをUIで表示。バッファ上限・レート制御・再送/切断時の扱い。送信できない場合はローカルでエクスポート可能。
- **OBS-004 MCP観測性**：WebMCP/標準MCPの呼び出し開始・結果・所要時間・エラー、UIとの同期差分/競合。APIキーやユーザー入力全文を記録しない。
- **OBS-005 外部処理ログ**：Blender/FFmpegの開始・終了コード・実行時間・標準出力/標準エラーをサイズ制限付きで収集。コマンドの秘匿引数は伏せる。
- **OBS-006 診断パック**：ユーザー操作でログ期間を指定しZIPへ。環境情報、アプリバージョン/Gitハッシュ、匿名化した設定、例外と再現手順、ログ、ログ仕様バージョンを含める。PMX/FBX/VMD実ファイル・個人情報は既定で**含めない**。明示的な確認とプレビュー画面を設ける。
- **OBS-007 プライバシー・保護**：パス/アカウント名/トークン/秘密鍵/歌詞などの漏えいを防ぐマスキングとレビュー。通常運用ではローカル保存のみ。ログにモデル/素材本体を含めない。削除・保持期限設定可。
- **OBS-008 操作経路の同等性**：手動UI・WebMCP・標準MCPに、ログ設定の取得、ログの一覧・フィルタ、診断パック生成・確認・保存操作を共通サービス層経由で提供。読み取りと削除/共有は別権限にし、危険操作には確認を要求する。
- **OBS-009 テスト**：ローテーション境界、上限、同時書込、再起動、壊れたログ、切断、ディスク容量不足、秘匿情報除外、Windows/Linux動作、UI/API/MCPの整合性を検証。

## 推奨ファイル
`data/logs/` （Git管理から除外）、`config/logging.json`、`docs/operations/LOGGING_JA.md`、`tools/collect_diagnostics.py`、`tests/test_logging.py`。実装時には既存 `data/` 保存と競合しない命名を決め、起動BAT/SHに連携する。

## 実装順序
1. 既存サーバー/ブラウザ/標準MCP/WebMCPの処理経路を監査し、共通イベント・機密マスキングの設計を固定。
2. サーバーJSONLログ・ローテート・設定・テストを先に実装。
3. UI側ログ収集とログ表示・診断ZIP機能を実装。
4. WebMCP/標準MCPとBlender/FFmpegを統合。
5. 実際のWindows/Linux環境で障害注入・容量上限・復元を確認。
6. 合格後にGitコミットと実装版タグ。検証未完了ならリリース済みとしない。
