# Issue #63 — 一つのシーンと時計で制作するための接続設計

2026-10-22。Ownerの指摘：カメラ関連6画面の似たプレビュー、キャラクター・ステージ・曲・ダンス・カメラ・エフェクトの分断。関連Issueは [#63](https://github.com/baisound/BAI_CREATER_STUDIO/issues/63)。本書は現行の実装境界と段階的な接続契約を記録する。各段階の実装・実測が終わるまで「一つの制作フローが完成」と表示しない。

## 現行のデータと動作

| 操作 | 現行の正本 | 現在の画面と制限 |

| 曲、ダンス、各開始・頭出しフレーム | `music_dance_project.json`。`music_dance_project.py`、`/api/music-dance/project` | SCR-10の独立した保存・AudioContext時計・3Dプレビュー。SCR-02とは素材参照・動作・時計を共有しない。 |
| カメラキー、フォーカス、ショット | `camera_project.json`。`camera.js`・`camera_3d.js` | PR #57のSCR-02が旧画面の実編集コードを保持。SCR-03/04/14/15/16は独立したサンプル画面とSCR-02へのリンクが残る。 |
| エフェクト配置・値 | 保存正本なし | SCR-26は構想・画面内サンプル。実シーンへの配置、パラメータ、再生、保存は未実装。 |

`project_state_bundle.py` は現在も複数ファイルの段階的な統合であり、音楽・ダンスまで含む原子的な保存契約を持たない。既存の正常な制作状態、素材原本、ウェイト、バックアップを保持する。

## 画面上の一本の手順

1. SCR-08で素材を登録する。対応形式と登録失敗をその場で示す。
2. SCR-06でステージとキャラクターを配置する。制作状態の保存対象と未保存状態を示す。
3. SCR-10で曲、ダンス、開始位置と頭出しを編集する。登録済みの同じキャラクター参照を初期候補として示し、異なるモデルを選ぶ場合は撮影対象との相違を明示する。
4. SCR-02で**SCR-06の配置とSCR-10の演奏・動作を同じ30fpsのフレームで描画**し、カメラ、ピント、ショット、レールを編集する。カメラ関連の旧URLは対応するSCR-02タブへ案内する。サイドバーに独立したサンプル撮影画面を並べない。
5. エフェクトはMMDエフェクト工程で、同じシーンの対象とタイムライン区間へ配置し、値・見た目・保存再読込を追加する。それまではSCR-26を未実装と明記し、編集できるように見せない。
6. 動画出力はPhase Fで同じシーン・時刻から作る。SCR-23のVMDモーション変換と混同させない。

## 実装契約と順序

### A. カメラの入口を集約する

SCR-02を唯一の撮影編集画面とする。サイドバーにはSCR-02だけを置き、SCR-03/04/14/15/16の直接URLとSCR-02内の補助診断リンクは**補助診断・旧リンクとして保持**する。この5画面にある実APIの診断結果を消さず、重複したサンプル3Dプレビューとサンプル時間軸だけを出さず、SCR-02の該当タブへ進む大きな導線を置く。SCR-03は`focus`、SCR-14は`rail`、SCR-04/15/16は`camera`へ案内する。ホームからの通常の撮影導線はSCR-02へそろえる。未実装のマルチカメラやVMD機能を「実装済み」と見せない。元の画面IDと要件IDは台帳に残す。後のPhase Eで診断をSCR-02内へ実移植した場合にだけ旧URLの転送を検討する。

### B. 制作コンテキストを一意にする

既存ファイルを無断移行・上書きしない。最初は**読み取りの合成**として、`workspace`（ステージ・キャラクター・照明・撮影フレーム）と`music_dance_project`（曲・ダンスと配置）を各正本から取得し、版を保持して一つの`ProductionContext`を組み立てる。画面側で同名の独立コピーを作らない。異なるキャラクターID、欠損素材、30fps以外の入力、版競合を明示する。片方の読込失敗を既定値で上書きしない。

`workspace.frame`と`music_dance_project.head_frame`は現行の保存済み値が食い違い得る。読み込み時にどちらかを黙って書き換えず、画面には現在の撮影フレームと曲・ダンスの頭出し位置を区別して示す。新たな再生位置変更から、アプリ内の共有フレームを唯一の表示時刻として通知する。保存契約を追加する段階で初期値の優先規則と二重保存の失敗時処理を定め、旧データの回帰テストを加える。

### C. 同じシーンを撮る

SCR-02の3D世界へ、SCR-06と同じモデルローダー・座標換算を使って`workspace.stage`と`workspace.character`を置く。SCR-10のモデル・モーション参照と開始/頭出しフレームを読み、既存プレビューと同じ互換判定・姿勢評価で現在フレームの動きを表示する。カメラ単独の素材選択と制作コンテキストの選択が異なるときは明示し、保存前に意図しない上書きをしない。編集用カメラと撮影用カメラは一つの世界を描く。GLB/VRM/PMX/FBX、VMD/GLB/FBXの対応差は既存の実装範囲とエラーをそのまま示す。

### D. 30fps時計と音声

SCR-10のAudioContext基準の再生時計をアプリ共有の再生サービスへ移し、SCR-02のカメラ・フォーカス・動作プレビューが同じフレームを受け取る。シーク・停止・画面移動で時計を二重起動しない。再生中に音声が未読込・許可待ちなら無音として黙って進めず、画面に理由を出す。フレーム移動だけで制作状態をdirtyにしない既存規則を維持する。カメラ、曲、ダンスの保存版を読み直した後も同じ時刻と素材を確認する。

### E. エフェクトと出力

エフェクトトラックは対象（シーン/モデル/カメラ）、開始/終了フレーム、パラメータ、順序を保存し、同じフレームでプレビューと書き出しを一致させる。既存のMMDエフェクト要件とPhase Fの動画出力要件に組み込み、先行するUIサンプルを実データと混ぜない。Phase E後の所定順序を変更する必要が出る場合はOwnerの判断を記録してから台帳を更新する。

## 段階ごとの合格条件

- A: サイドバーの撮影編集入口は一つ。旧URLでは実診断を維持しながら重複したサンプルプレビューを見せず、SCR-02の該当タブへ進める。ホーム・戻る・検索・モバイルで到達でき、カメラキーと未保存状態が保持される。旧カメラ単体画面も壊れない。
- B/C: 隔離データで1体とステージ、曲、VMDまたはFBX/GLBダンスを保存し、SCR-02で同じID・配置・姿勢・フレームが描画される。4キャラクター形式ごとの対応/非対応を正しく示す。壊れた既存ファイルは原本不変。
- D: 音声再生・シーク・停止・画面往復・保存再読込で、同一フレーム上の音声、動作、カメラキーが一致する。旧ファイルとの不一致時に黙った移行をしない。
- E: エフェクト素材の選択・時間範囲・値・見た目・保存再読込と、動画出力の結果まで確認する。着手前は明確に未実装と表示する。

実装各段階の自動試験は隔離`BAI_DATA_DIR`を使い、実`data/`と`exports/`のハッシュを前後で比較する。実GPU/Linux、利用者モデル、MCP経路、実Blender変換は自動試験と区別して記録する。
