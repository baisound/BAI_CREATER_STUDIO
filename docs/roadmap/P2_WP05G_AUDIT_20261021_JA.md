# P2-WP-05g 既存模式再生監査（2026-10-21）

## 対象

承認済み詳細設計 `P2_PORT_DETAILED_DESIGN_20261020_JA.md` §2.5(d) WP-05g の⑤-10・⑤-15のみを、SCR-05 の既存画面に移す。スキニング・ウェイトは操作しない。

| 旧画面 | 新UIの受け口 | 保持する規則 |
|---|---|---|
| `index.html` の `select`・`tick`（92〜113行） | `chain-view.js` に画面内だけのパターン時計、`chain-viewport.js` 中央に前・再生/一時停止・次・位置 | 選択時0秒、既定再生、尺は `patternDuration`、速度は `combination.playbackSpeed`。制作状態に時計を保存しない。 |
| `pose`・`fighter`・`draw`（95〜113行） | 中央の折りたたみ「従来の2D模式アニメーション」 | SVGをDOMノードで組み立てる。A/Bの動き、技名、HIT表示、時刻を旧式と照合する。 |
| `dummy`・`motionState`・`animateActor`・`frame`（229〜254、358行） | 既存 `three-host` のA/Bと状態行 | FBX未登録スロットは3D模式人形。登録FBXがあり対応クリップもあれば実FBX再生。連結再生とPMX/VMD再生を優先して上書きしない。 |

## 現状と境界

- `chain-view.js` の一覧は82行と選択・速度保存を持つ。中央 `chain-viewport.js` は登録FBX/PMXと連結/VMD再生を持つが、選択パターンの時計、2D SVG、ダミーはまだない。
- 旧3Dでは実FBXモデルを登録していても選択手順のクリップが見つからなければ模式人形には切り替えず、実FBXの動きがない状態を「未割当」と表示する。新UIでもこの区別を維持する。モデル自体がないときだけ3D模式人形を表示する。
- 旧 `motionState` は起き上がりのB動作を `frame` 側で補正する。`draw` の2Dでは接触時のB動作が異なる。両者を混同しない。
- 新 `three-host` は一つだけ使い、表示のために別のレンダラーを作らない。画面離脱時は時計とrAFを停止し、模式人形の資源を解放する。

## 検証

`pose`・2Dの動きと文言を旧式関数と照合するNodeテスト、隔離Chromeでパターン1の説明・SVG・3D A/B模式関節変化・登録FBXの優先・連結再生の排他・画面離脱を確認する。実利用者のFBXとGPU実機、先行WPの独立レビューは未確認として残す。

最終確認ではパターン時計に実経過秒を渡し、3Dアニメーションだけ1フレームの更新量を制限した。対象試験25件、型検査、P2 E2E（S1/S2/S5）が通過し、実 `data/` のハッシュは不変。共通P2 Nodeは216件通過・計画済み5件スキップ・ポート8794の衝突で1件失敗、同試験はポート8894で単独通過。Evidenceは127件通過・FBX置換の画面待機が1件タイムアウト、同試験は単独通過。Python共通ゲート370件＋23 subtestsは最終のJSのみの修正より前に通過した。実利用者FBX/GPU実機と先行WPの独立レビューは未確認。
