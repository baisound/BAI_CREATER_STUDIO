# 全キャラクター形式の配置契約（Issue #50、2026-10-21）

## Owner決定と対象

Ownerは「キャラクターを配置できる機能すべてで、PMXに限らず全キャラクターを配置できる」と直接指定した。対象形式は現行の登録・読込契約でキャラクターとなる GLB、VRM、PMX、FBX。VMDはモーションで、キャラクター素材ではない。原本・骨・weightsは変更しない。診断用の転写比較は未校正のGLB/VRMノード候補を検査する別機能であり、一般のキャラクター配置からは分けて扱う。

| 画面・操作 | 現在 | 変更後の受け入れ条件 |
|---|---|---|
| SCR-12「このモデルを制作に使う」 | 一覧・3Dプレビューは4形式、制作状態への選択はGLB/VRMのみ | 4形式を選択・保存。存在しない素材は理由を表示。 |
| SCR-06シーンのキャラクター | `workspace.asset` のGLB/VRM保存名だけを表示、操作欄なし | 4形式から選択し位置XYZ・回転XYZ・倍率を保存・再読込。ステージの配置と独立。 |
| SCR-13モーション画面 | 4形式を表示できるが制作への記録はGLB/VRMクリップのみ | 4形式のキャラクター選択を制作状態へ記録。形式に合わないモーションの適用は案内して拒否。 |
| SCR-05 A/B表示 | FBX modelA/BとPMX A/Bだけを選択 | 4形式をA/Bそれぞれで表示。82パターンの実FBX再生、PMX+VMDは対応素材だけで有効にする。 |
| 旧カメラとWP06カメラ | GLB/VRMのカタログ・表示のみ | 制作状態の4形式を表示し、カメラ操作と保存・再読込で維持。形式別の未対応モーションは明示。 |

## 保存形式と互換性

`workspace.asset` は既存の `filename.glb` / `filename.vrm` を引き続き受け付ける。新たに登録済み素材の `integrated:<filename>`、`mmd:A:<name>`、`mmd:B:<name>`、`fbx:<id>` も受け付ける。UIは統合GLB/VRMには既存の保存名を使い、PMX/FBXに識別子を使う。既存の `clip` はGLB/VRMのアニメーションクリップ索引だけであり、PMX/FBXへキャラクターを変更したときは `null` にする。

任意の `workspace.character` は `{position:[x,y,z],rotation:[x,y,z],scale}` とし、ステージと同じ位置[m]・回転[度]・倍率の範囲検査を使う。値が無い古い保存は `[0,0,0]`・`[0,0,0]`・`1` で表示する。旧カメラ等がこのキーを知らずに保存しても保持する。素材の単位換算は表示時だけに掛ける。読めないID・ファイルは元の保存値を保持し、画面で理由を出す。

## 検証と未確認

合成GLB/VRM/PMX/FBXで選択、表示、XYZ変換、保存・再読込、形式不一致の案内、旧データ復元を隔離ブラウザーとAPIで確認する。既存のステージ・ライト・音楽・ダンス・制作履歴のハッシュを保持する。実利用者モデルの見た目、GPU、Linux、Owner採用は別に記録する。661MiBのLAST CHASE全量ブラウザー試験は前回の端末停止歴があるため繰り返さない。
