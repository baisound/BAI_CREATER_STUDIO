## 0. 前提

### 0.1 所有者の主な用途（この仕様の軸）
所有者の最多の使い方は、MMD を使った**歌ってみた動画**の制作。配布されているダンス VMD を自分の PMX／VRM モデルに当てると、体格・骨格の違いから次のズレが出る。

- 手が体（胸・腹・太もも）や顔に**めり込む**。
- 足が床の上で**滑る**、床に**沈む・浮く**。
- 腕・肘の向きがおかしい、頭の向きがずれる。

本書の目的は、これを**元のモーションを壊さずに、必要なフレームだけ手直し**し、MMD で使える VMD として書き出せるようにすること。カメラは、表示している画面を見ながら構図を決め、そのままキーにできるようにすること。

## 1. 所有者に響く価値

**使う側（所有者・MMD で歌ってみたを作る人）**
- 配布ダンスを自分のモデルで踊らせたときの「手のめり込み」「足滑り」を、**ズレているフレームだけ**、手先・足先をつかんで直せる。全部打ち直さなくてよい。
- 元の VMD は一切書き換えない。直しは別の層に残るので、**いつでも元に戻せる・効き具合（重み）を後から弱められる**。
- 直した結果は **MMD でそのまま読める VMD** として書き出せる。MMD 本体で IK を1本ずつ直す往復が要らない。
- カメラは「今見えている画面がそのまま撮影カメラ」。構図を目で決めて手を離せば、そのフレームにキーが入る。

**売る側（BAI Creator Studio を紹介・販売する立場）**
- 「配布モーション × 自分のモデル」で必ず起きるズレ直しは、MMD 制作で一番手間のかかる作業の1つ。そこを**ブラウザで、原本を壊さずに**片付けられる、という分かりやすい売り。
- 操作は Unreal Engine の Control Rig／Sequencer と同じ考え方（ハンドル、FK/IK、加算レイヤー、オートキー、パイロット）。UE や Blender を触ったことのある人がすぐ使える。
- 同じ操作を AI（WebMCP・標準 MCP）からも呼べる。AI なしでも全部手で操作できる。

## 2. モーション（MOTION-010）

### 2.1 範囲
- **含む**：操作ハンドルでのポーズ付け、部位ごとの FK/IK 切り替え、任意フレームのキー記録と補間、修正レイヤー（加算）と重み、焼き込みと VMD 書き出し、PMX／VRM の違いの扱い、非破壊。
- **含まない（別IDまたは範囲外）**：
  - ボーン対応の作成・修正そのもの → `MOTION-005`（本書はその結果を使う）。
  - 自動の接地・床貫通修正 → `MOTION-011`。足跡・接地時刻の指定 → `MOTION-012`（§2.6）。
  - 比較表示そのもの → `MOTION-014`（§2.7）。
  - 表情・口パクのモーフ → リップシンク・表情段階（LIP）。
  - 物理（髪・スカート）の焼き込み、めり込みの**自動検出・自動回避**（既存IDに無い。本書では作らず、候補にも挙げない）。

### 2.2 操作ハンドル（コントロール）
1. **標準のハンドル一式**（モデルの種類によらず同じ名前で出す）：

   | ハンドル | 既定の解き方 | 動かせるもの | PMX での主な対応ボーン | VRM での主な対応（humanoid） |
   |---|---|---|---|---|
   | 腰（体の中心） | FK | 位置・回転 | センター（＋グルーブ）、下半身 | hips |
   | 胸 | FK | 回転 | 上半身・上半身2 | spine・chest・upperChest |
   | 頭 | FK | 回転 | 首・頭 | neck・head |
   | 左手先／右手先 | FK（IK へ切替可） | 位置・回転 | 腕・ひじ・手首（IK 時はツール内で解く） | upperArm・lowerArm・hand |
   | 左肘／右肘（ポール） | IK 時のみ表示 | 位置 | — | — |
   | 左足先／右足先 | IK（FK へ切替可） | 位置・回転 | 左足ＩＫ・右足ＩＫ | upperLeg・lowerLeg・foot（ツール内で解く） |
   | 左膝／右膝（ポール） | IK 時のみ表示 | 位置 | （足ＩＫの解に従う） | — |
   | 左つま先／右つま先 | IK 時のみ | 位置 | 左つま先ＩＫ・右つま先ＩＫ | toes |

   - どのボーンにどう対応させるかは、`MOTION-005` のモデル別ボーン対応プロファイルを使う。対応が無いハンドルは**灰色で出し、つかめない理由を表示**する（例：「このモデルには『左つま先ＩＫ』がありません」）。
   - 一覧（アウトライン）から**任意のボーンを直接選んで FK で回す**こともできる（指、捩りボーンなど標準ハンドルに無いもの）。
2. **表示**：Scene View にだけ出す（書き出し・Camera View に映さない。Phase E §2.12 と同じ考え方）。左右で色を分け、FK と IK で形を変える。選択中は強調。モデルに隠れても見えるよう前面に描く。
3. **操作**：ハンドルをクリックで選択 → 移動・回転のギズモでドラッグ。座標の基準（ワールド／ローカル）を切り替えられる。数値入力（位置・回転）もできる。
   - **選んでいない部位は動かさない**。IK で手先を動かしても、肩より上（胸・頭）は変えない。
   - ドラッグ中はプレビュー（保存データは変えない）、離して確定、`Esc` で取消（Phase E P3 と同じ「プレビュー → 確定」）。
4. **届かないとき**：IK で手先・足先が届かない位置へ動かした場合は、**届く範囲で最も近い位置**まで伸ばし、「目標まで届きません（○○ 不足）」と表示する。黙って成功扱いにしない。
5. **関節の制限**：PMX の IK ボーンに角度制限があればそれを守る。VRM の制限値の出所は未決（O-12）。

### 2.3 部位ごとの FK/IK 切り替え
1. 切り替えの単位は**左腕・右腕・左脚・右脚**の4つ。腰・胸・頭は FK のみ。
2. **切り替えても見た目の姿勢を変えない**（スナップ）。FK → IK では手先（足先）ハンドルを今の手先位置に、ポールを今の肘（膝）の向きに置く。IK → FK では今の見た目からボーンの回転を求める。
3. 切り替えは**編集のしかたの設定**であり、それだけではキーを書かない。書き出しの結果（ボーンの回転・位置）にも影響しない。
4. 時間区間ごとに FK と IK を混ぜる（IK/FK ブレンドのキー化）は本書では作らない（O-11）。

### 2.4 キーの記録と補間
1. **任意のフレームにキー**を記録できる。キーは「ハンドル（またはボーン）× 位置／回転」のチャネル単位で持つ。
2. **キー記録の規則はカメラと同じ**（§3.4）：
   - オートキー ON：操作の確定（ドラッグを離す・数値入力の確定）で現在フレームにキーを書く。そのフレームに既にキーがあれば、**変更したチャネルだけ**上書きし、他のチャネルと補間の設定は保つ（カメラの `mergeKey` と同じ意味）。
   - オートキー OFF：プレビューのまま「未確定」と表示し、［キー化］で書く。
   - 変化が無い操作、`Esc` で取り消した操作はキーを書かない。
   - 1操作＝1 Undo。
3. **補間**：VMD と同じ**ベジェ曲線**（X・Y・Z 移動と回転の4本、制御点 0〜127）を基本にし、線形・保持（次のキーまで動かない）も選べる。補間の表示・編集は `DATA-003`（補間・ブレンドカーブ）の曲線部品で行う。カメラの曲線エディタ（CAM-003）と部品を共通にするかは O-13。
4. キーの操作：追加・更新・削除・フレーム移動。コピー・貼り付け・左右反転貼り付けは本書では決めない（O-10）。

### 2.5 修正レイヤー（加算）と重み
1. **重ね方（モーションスタック、`DATA-006` の具体化）**：

   ```
   元モーション（VMD 原本、読み取り専用）
     → 自動接地（MOTION-011、使う場合のみ）
     → 修正レイヤー 1 … N（加算、上から順に）
     → 画面表示・焼き込み
   ```
   順序を利用者が入れ替えられるようにするかは O-05。
2. **加算の意味**：
   - 回転：下の段の結果の回転に、レイヤーの差分回転を**重みで弱めて**掛ける（重み w のとき、差分を単位回転から w だけ球面補間した回転）。
   - 位置：下の段の結果に、差分 × w を足す。
   - 操作ハンドルで付けたポーズは、**そのフレームの下の段の結果との差分**としてレイヤーに保存する。利用者は差分を意識せず「見た目の姿勢」を付ける。
3. **重み**：レイヤーごとに 0〜100%（既定 100%）。0% で元と完全に同じ、100% で付けたとおり。重みの時間変化（キー）は O-03。
4. **効く区間となじませ**：レイヤーは**有効区間（開始・終了フレーム）**と、前後の**なじませフレーム数**を持つ。区間外では差分ゼロ（元のまま）、なじませの間は差分を 0 から滑らかに増減する。「この 20 フレームだけ手のめり込みを直す」がそのまま書けるようにするため。
5. **レイヤーの操作**：追加・名前変更・削除・順序変更・ミュート（一時的に無効）・ソロ（そのレイヤーだけ有効）。レイヤーはキーを持つチャネルだけに効く（部位の限定は `DATA-005` の考え方）。
6. 加算以外（上書きレイヤー）は本書では作らない（O-04）。
7. 既存の `motion_layers.js`（回転補正レイヤー）と保存データを二重にしない。既存の保存済みレイヤーは読めること（後方互換）。統合のしかたは詳細設計で決める。

### 2.6 MOTION-011（足IK・接地）、MOTION-012 との関係
- 自動接地（MOTION-011）は §2.5 の段の1つ。ON/OFF や設定を変えても、**手動の修正レイヤーのデータは変わらない**（効き方が変わるだけ）。
- 足滑りの手直しは、本書の範囲では「接地している区間の始まりと終わりに足先ハンドルのキーを打ち、同じ位置にする」で行える。**区間を選んで自動で足を固定する機能**は MOTION-011／MOTION-012 の範囲で、本書では作らない。
- 足先ハンドルは PMX の足ＩＫボーンと同じものを動かすので、MOTION-011 の結果（足ＩＫの位置）と矛盾しない。

### 2.7 MOTION-014（ゴースト比較）との関係
- 編集中に、**修正前の姿勢**（元モーション＋自動接地まで）を半透明のゴーストで重ねられる。手先・足先の**軌跡**も出せる。
- 表示部品は MOTION-014 のゴースト・軌跡を使い、重複して作らない。MOTION-014 の比較対象に「修正前」を加えることは MOTION-014 の詳細にも関わるので、詳細設計で両方を同時に決める（O-09）。
- ゴーストは表示だけで、キー・レイヤーを変えない。

### 2.8 PMX と VRM の違い
| 項目 | PMX（MMD） | VRM |
|---|---|---|
| 骨格 | モデルごとに自由。日本語のボーン名。センター・グルーブ・全ての親などの階層 | humanoid の決まった役割（hips〜toes、指） |
| IK | **足ＩＫ・つま先ＩＫなどの IK ボーンを持つ**。VMD は IK ボーンの位置・回転を記録し、MMD が再生時に解く | IK ボーンは無い。IK は本ツールの中で解き、結果をボーンの回転として持つ |
| 腕の IK | 通常は無い。本ツールの中で解き、腕・ひじ・手首の回転として書く | 同左 |
| 付与・捩り | 回転付与（腕捩・手捩など）がある。付与先ボーンは直接キーを書かない（付与元を書く） | 無し（VRM 1.0 の constraint は対象外） |
| VMD への書き出し | ボーン名のまま書く。足は §2.9-4 の規則 | `MOTION-005` のプロファイルで VMD のボーン名へ対応させて書く。**VRM に VMD を当てる経路そのものが未決**（P2 の O-⑤-8）なので、VRM の編集・書き出しはそれに依存する（O-02） |
| 編集の基準 | モデルの初期姿勢のローカル軸 | humanoid の正規化された姿勢（T ポーズ基準） |

- ハンドルの名前と操作は PMX／VRM で同じにし、違いは内部の対応表で吸収する（利用者に骨格の違いを意識させない）。

### 2.9 焼き込みと VMD 書き出し
1. **焼き込み**：§2.5 の重ねた結果を、MMD で再生できるボーンのキーに変換する。
2. **出力のしかた**（どちらも必須）：
   - **全フレーム**：対象範囲の毎フレームにキー。忠実だが大きい。
   - **修正区間だけ**：元 VMD のキーはそのまま残し、修正レイヤーの有効区間（なじませを含む）だけ毎フレームのキーで差し替える（`DATA-007` 部分差分転写と同じ考え方）。区間外のキーは元と1バイトも変えない。
   - 誤差の範囲でキーを間引く方式と、既定をどちらにするかは O-06。
3. **元の VMD にある他の内容**（モーフ・表示/IK の切り替え情報など、ボーン以外）は**そのまま写す**。
4. **PMX の足**：元 VMD が足ＩＫボーンを使っていれば、結果も足ＩＫボーンのキーとして書く（MMD 側で IK が効いたまま同じ姿勢になる）。元が IK を切って足の回転で書いていれば、そのやり方に合わせる。既定以外を選べるようにするかは O-07。
5. **書き出し先**：常に**新しいファイル**。元の VMD を上書きしない。同名があれば番号を付ける。
6. **書けないもの**：ボーン名が VMD の上限（Shift_JIS 15 バイト）に収まらない、対応ボーンが無い、などは書かずに一覧で報告する。黙って捨てない。
7. **往復検査**：書き出した VMD を読み戻し（`vmd_readback.py`）、焼き込み前の結果と全フレームで比べて、最大誤差（位置・角度）とその場所を報告する。
8. **権利の注意**：書き出した VMD の配布・再配布の可否は、元の VMD の配布規約に従う旨を書き出し画面に表示する（本ツールは判断しない）。

### 2.10 非破壊
- 元の VMD・PMX・VRM ファイルは**読むだけ**。編集・保存・焼き込み・書き出しのどの操作でも変えない。
- 修正はプロジェクト内の別データ（修正レイヤー）に保存する。元ファイルの指紋（ハッシュ）を記録し、元ファイルが変わっていたら「元のモーションが変更されています」と警告する（自動で合わせ直さない）。
- 既存の保存形式は、任意フィールドの追加だけで広げる。読み込み時に黙って書き換えない（Phase E P2 と同じ）。

## 3. カメラ（CAM-003・CAM-006・CAM-007）

### 3.1 承認済み設計との関係（重要）
- カメラの操作の正本は、承認済みの `docs/camera/BAI_CAMERA_INTERACTION_DESIGN_V1_JA.md`（操作設計 v1）と `PHASE_E_DETAILED_DESIGN_20261020_JA.md`（Phase E 設計 v4）。
- 承認済みの設計では、**Camera View での操作が撮影カメラを動かし**、**Scene View の移動は撮影キーを変えない**（操作設計 §2・§5-6、Phase E CAM-006 設計6）。キーの記録は「確定時に1キー、自動キー ON/OFF」（操作設計 §5、Phase E CAM-005 §2 の表）。
- 本書で**追加される要求**は次の2つ。どちらも Scene View 側の操作で撮影カメラを動かすので、承認済み設計の「Scene View は撮影キーを変えない」の**例外**になる。
  1. **パイロット**（§3.2）
  2. **Scene View で撮影カメラ（ギズモ）をつかんで動かしたときのオートキー**（§3.3）
- この2つは **Phase E の承認済み設計にはまだ組み込まれていない**。組み込むには Phase E 設計の改訂とレビューが要る（O-14）。それまでは Phase E の実装は承認済み設計のまま進め、本書の追加分は作らない。
- Scene View の普通の視点移動（見回し・フライト移動・オービット・フォーカス）は、パイロット中でない限り、今までどおり**撮影キーを変えない**。

### 3.2 パイロット（表示中の画面をそのままカメラとして動かす）
1. **意味**：Scene View の視点を撮影カメラに固定する。以後、Scene View の視点操作（右ドラッグの見回し、右ボタン＋W/A/S/D/E/Q の移動、ホイールなど）が、そのまま撮影カメラの姿勢を変える。構図を目で決めるための操作。
2. **開始**：撮影カメラを選んで［パイロット］を押す。開始時に Scene View の視点を撮影カメラの位置・向き・FOV・ロールへ移し、撮影の縦横比のマスクとセーフフレームを出す（Camera View と同じ構図が見える）。Scene View の元の視点は覚えておく。
3. **表示**：画面上部に「パイロット中：撮影カメラ ○○ ／ オートキー ON」の帯と［終了］ボタン。
4. **操作の変換**：パイロットは**新しい移動計算を持たない**。Scene View の操作を、CAM-006／CAM-007 の操作語（Phase E の `moveCamera` の操作名）に変換して使う。

   | Scene View の操作（パイロット中） | 撮影カメラへの操作 | ID |
   |---|---|---|
   | 右ドラッグ 横／縦 | `pan_yaw`／`tilt`（位置は変えず向きだけ） | CAM-006 |
   | 右ボタン＋W/S、ホイール | `dolly`（前後） | CAM-007 |
   | 右ボタン＋A/D | `truck`（左右） | CAM-007 |
   | 右ボタン＋E/Q | `pedestal`（上下） | CAM-007 |
   | R＋ドラッグ | `roll` | CAM-006 |
   | Z＋ドラッグ | `zoom`（FOV だけ。位置は変えない） | CAM-007 |

   - 向きを変えたときの注視点（`target`）は、位置との距離を保って視線の先に置く（Phase E のカメラ基底に従う）。
   - 速度・係数・符号は Phase E CAM-006 の表と同じ。パイロット中も**ドリー（位置）とズーム（画角）は独立**のまま（CAM-007）。
5. **1操作の区切り**：1回のドラッグ、またはキーを押してから離すまでを1操作とする。その確定で §3.4 の規則に従ってキーを書く（オートキー ON）。押しっぱなしで移動している間にキーを大量に作らない。
6. **終了**：［終了］で Scene View を元の視点に戻す。終了そのものはキーを書かない。`Esc` は「進行中の1操作の取消」に使う（パイロットの終了ショートカットは O-12）。
7. **書けないとき**：キー以外が姿勢を決めている間（シーケンスのショット区間内、カメラ VMD 追従中、ボーン追従・リグ駆動中）は、パイロットで動かしてもキーに書かない。「ショット／VMD／追従の表示中はキーを編集できません」を表示する（Phase E CAM-005 §2 の表の3行目と同じ）。
8. 再生しながらの連続記録（ライブ記録、操作設計 §5-4 で初期 OFF の別モード）は本書に含めない（O-13）。

### 3.3 3D 画面でカメラをつかむ（ギズモ）とオートキー
1. Scene View に、撮影カメラの本体と注視点の**ハンドル**を出す（既存の Scene View 専用表示、レイヤー1）。
   - **本体の移動**：位置と注視点を一緒に平行移動する（向きを保つ）。
   - **本体の移動＋修飾キー**：位置だけを動かす（注視点を固定するので向きが変わる）。修飾キーの割り当ては詳細設計で決める。
   - **注視点の移動**：注視点だけを動かす（位置は固定）。
   - **回転リング**：パン・ティルト・ロール。
2. ハンドルのドラッグは**撮影カメラの編集**として扱い、§3.4 の規則でキーを書く。ハンドル以外の場所でのドラッグは、今までどおり Scene View の視点移動（撮影キーを変えない）。
3. **オートキー**：
   - ON：ドラッグを離したとき、現在フレームにキーを書く（既存キーがあれば更新）。1操作＝1 Undo。
   - OFF：`previewPose` に入れて「未確定」と表示。［キー化］で書く。フレームを動かすとプレビューは捨てる（Phase E の現行どおり）。
   - 状態は、ビューの隅とタイムラインの両方に常に表示する（UE のオートキーと同じく、ON のときは目立つ色）。
   - 既定値（ON か OFF か）は O-11。
4. CAM-003 の数値入力・キー一覧からの編集、CAM-006 の Camera View 操作、パイロット、ギズモは、**すべて同じオートキーの切り替え**に従う（画面ごとに別の切り替えを持たない）。

### 3.4 キーを記録するときの規則（カメラとモーション共通の考え方）
1. **既存キーとの合成は Phase E の `mergeKey(existing, edit)` に合わせる**（Phase E §2.1）。
   - そのフレームに既存キーがあれば、**今回変えたフィールドだけ**上書きし、他のフィールド（`interpolation`・`customCurve`・`fStop`・`focusDistance` など）は保つ。
   - キーの補間設定は、オートキーでは変えない。
   - `KEY_FIELDS` 以外は書かない。
2. **新しいキー**は Phase E CAM-005 §2 の「新規キーの規則」に従う：`position`・`target`・`fov`（WP-06 以降は `roll` も）は有効姿勢＋今回の操作から書く。`fStop`・`focusDistance` は、今回の操作で変えたとき、または既存キー由来の値があるときだけ書く。
3. 操作ごとに書くフィールド：

   | 操作 | 変わるフィールド |
   |---|---|
   | `pan_yaw`・`tilt`、注視点の移動 | `target` |
   | `dolly`、本体の移動（位置だけ） | `position` |
   | `truck`・`pedestal`、本体の移動（向きを保つ） | `position`・`target` |
   | `roll` | `roll`（WP-06 以降） |
   | `zoom` | `fov` |

4. **書かないとき**：変化がない（誤差の範囲）、`Esc` で取消、キー以外が姿勢を決めている（§3.2-7）、操作中にフレームが変わった（操作設計 §5-5 のガードで確定か破棄を選ばせる。曖昧なまま別フレームに書かない）。
5. フレームは現在フレーム（整数）。
6. 外部（API・MCP）からの書き込みは revision 必須（Phase E §2.4）。競合時は上書きしない。
7. モーションのキー（§2.4）も同じ考え方（変更したチャネルだけ、補間は保つ、1操作＝1 Undo）で記録する。

### 3.5 各IDに足される要点
- **CAM-003**：キーの作り方にパイロット・ギズモからのオートキーが加わる。キーの合成は `mergeKey`。曲線エディタ・トラック別補間の設計（Phase E WP-05）は変えない。
- **CAM-006**：パイロット中の見回しが `pan_yaw`・`tilt`、R＋ドラッグとギズモの回転リングが `roll` になる。符号と係数は Phase E の表のまま。
- **CAM-007**：パイロット中の W/S/A/D/E/Q・ホイールが `dolly`・`truck`・`pedestal`、Z＋ドラッグが `zoom`。移動と画角の独立を保つ。スライダー・レールの設計（WP-07）は変えない。

## 4. 共通

### 4.1 手動 UI・WebMCP・標準 MCP
- **AI なしで全部手で操作できる**ことが前提。WebMCP・標準 MCP は、手動 UI と同じ共通 API を呼ぶ薄い橋渡し（Phase E P4）。
- 同じ入力から、4経路（手動 UI・共通 API・WebMCP・標準 MCP）で同じ保存結果になること。
- ドラッグ・パイロットは画面の操作なので、API では**数値で同じことをする操作**として用意する。

| 操作 | 手動 UI | 共通 API・MCP での相当（名前は仮。詳細設計で決める） | 標準 MCP の制限 |
|---|---|---|---|
| ハンドルを動かしてポーズ | ドラッグ・数値入力 | 「フレーム・ハンドル・位置/回転・座標の基準・確定するか」を渡す | IK の計算にモデルの骨格が要る。ブラウザ側でしか解けない場合は `transport:'browser'` とし、制限を一覧に書く（O-15） |
| FK/IK 切り替え | 部位ごとのスイッチ | 部位と FK/IK を渡す | 同上 |
| キーの追加・更新・削除 | タイムライン | フレームとチャネルを渡す（合成は §3.4） | なし（保存データの操作） |
| 修正レイヤー（追加・重み・区間・ミュート） | レイヤー一覧 | レイヤーの操作 | なし |
| 焼き込み・VMD 書き出し | ［VMD を書き出す］ | 書き出しの条件を渡し、報告（誤差・書けなかったボーン）を受け取る | 書き出し先はサーバーの決まった出力場所だけ（権限） |
| カメラの移動 | Camera View・パイロット・ギズモ | Phase E の `POST /api/camera/move`（`commit` 付き）と `bai_camera_move` | Phase E と同じ |
| パイロットの開始・終了 | ボタン | 画面の表示状態なので API は持たない。WebMCP で画面に対してだけ切り替え可（`transport:'browser'`） | 標準 MCP からは不可（制限として明記） |
| オートキーの切り替え | トグル | 設定の読み書き | なし |

### 4.2 保存と復元
- **保存するもの（プロジェクト）**：
  - モーション：元モーションへの参照（ファイルの場所と指紋）、修正レイヤー（名前・順序・重み・有効区間・なじませ・ミュート/ソロ・チャネルごとのキーと補間）、部位ごとの FK/IK の状態。
  - カメラ：キーは既存の `camera_project.json`（schema 1、任意フィールドの追加だけ。本書で新しいキーのフィールドは足さない）。
- **保存するもの（作業状態 workspace）**：オートキーの ON/OFF、ゴースト・軌跡の表示設定、ハンドルの表示設定、座標の基準。
- **復元しないもの**：パイロット中の状態（読み込み直後は必ずパイロット OFF。誤操作を防ぐ）、未確定のプレビュー。
- 保存 → 再起動 → 復元で、上の保存対象がすべて一致すること。統合保存（プロジェクトバンドル）への入れ方は Phase E WP-02d と P2 の決定に合わせて詳細設計で決める。

### 4.3 Undo
- **1操作＝1 Undo**：ハンドルの1ドラッグ、数値入力の1確定、パイロットの1操作、ギズモの1ドラッグ、キーの追加・削除・移動、レイヤーの追加・削除・順序変更・重み（スライダーは離したとき1件）・区間の変更、［キー化］。
- **Undo に積まないもの**：FK/IK の切り替え（キーを書かない設定）、パイロットの開始・終了、表示設定、ゴースト。
- **焼き込み・書き出し**は新しいファイルを作るだけでプロジェクトを変えないので Undo の対象外。代わりに書き出しの記録（日時・条件・報告）を残す。
- 外部（API・MCP）からの編集も、操作の単位で Undo に積む（操作設計 §5 のトランザクション）。
- 上限：カメラは現行の 80。モーションの上限は O-16。

### 4.5 受け入れ条件

- AC-M-12：編集・保存・焼き込み・書き出しの前後で、元の VMD・PMX・VRM ファイルの指紋が変わらない。書き出しは常に新しいファイル。

**カメラ（CAM-003・006・007）**

### 4.6 テストの方針
- **単体（計算）**：IK（届く・届かない・ポールの向き・関節制限）、FK/IK 切り替えのスナップ、加算と重み（0・50・100%）、区間となじませ、キーの合成規則（オートキー ON/OFF × キーの有無 × キー以外が姿勢を決めている、の6通り。Phase E の `lensEditAction` と同じ表形式）、ベジェ補間、焼き込み、ボーン名の長さ・対応なしの報告。
- **照合（parity）**：計算を JS と Python の両方に置く場合は、同じ入力に同じ出力を共通の照合データで確かめる（Phase E §2.2 と同じ方式）。カメラのパイロットは `moveCamera` の照合データに乗せる。
- **往復**：VMD 書き出し → 読み戻し → 比較（全フレーム）。「修正区間だけ」の区間外の同一性。保存 → 再読込で全フィールドが残る。
- **素材**：ライセンス上問題の無い小さなテスト用 PMX（足ＩＫ・つま先ＩＫ・捩りボーンを含む）、VRM、テスト VMD をリポジトリに置く。原本素材は Git に入れない（AGENTS.md）。
- **画面（Playwright、SwiftShader）**：ハンドルの1ドラッグで1キー・1 Undo、`Esc` 取消、FK/IK 切り替えで見た目不変、パイロットの開始・操作・終了、ギズモ、オートキー ON/OFF、ショット区間内での拒否、保存と復元。SwiftShader の合格を GPU 検証とは呼ばない。
- **通し確認**：主要シナリオの E2E に「VMD を当てる → 手先を1か所直す → 書き出す」と「パイロットで構図を決めてキーを1つ打つ」の手順を足す。
- **実データ**：所有者が使う配布 VMD と自分のモデルでの確認は、ロードマップ上の所有者確認の時期（Phase E は全実装後）に、5手順以内の「これを試して」形式で依頼する。それまでは未検証として記録する。

## 5. 実装までの手順
1. 本書（仕様）を台帳（`FEATURE_DETAIL_JA.md`・`FEATURE_REGISTER.json`／`.csv`）から参照できるようにする（本コミット）。
2. ロードマップの順番が来たら、モーション（MOTION-010）とカメラ（CAM-003/006/007 の追加分）の**詳細設計**を別々に作る。カメラは **Phase E 設計の改訂**として書く。
3. 詳細設計は**批評3回と最終判定**を通す。§4.7 の未決事項はこの中で決めるか、所有者への確認事項として残す。
4. 判定後に実装する。各コミットで台帳・進捗・テスト結果・未検証事項を更新する（AGENTS.md 規則6）。
5. 本書に無い機能（めり込みの自動検出、物理の焼き込みなど）は作らない。新しい NF 候補も作らない。
