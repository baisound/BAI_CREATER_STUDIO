# P2-WP-05f 既存実装監査（2026-10-21）

## 対象と位置

正本は `P2_PORT_DETAILED_DESIGN_20261020_JA.md` §2.5(d) WP-05f。SCR-13 の既存領域だけを使う。右「ボーンマップ」の末尾にQA、中央［比較］の帯にキー候補、右「足IK」に接地診断を置く。新しい画面やタブは作らない。Owner指定によりスキニング・ウェイト操作は実施しない。

| 機能 | 既存UI・API | 新UIの受け口 | 検証する制限 |
|---|---|---|---|
| ⑤-11 転写タイムライン・QA | `v01630_32_review.js`、`POST /api/retarget/review-bundle` | `retargetPanel` の末尾。選択は既存 `rt` を共有 | 共通座標系の確認前は呼ばない。出力は検証JSONだけ、VMD禁止。 |
| ⑤-12 キー候補・フレーム比較 | `v01633_35_scrub.js`、`v01636_40_playback.js`、`v01641_preview_guard.js`、`POST /api/retarget/keyframe-review` | `retargetViewport` の［比較］。対象 `rt.target` の登録済み GLB/VRM を読む | `blocked_for_production` と `vmd_export_allowed:false` の検査。150MB、ノード範囲、非ゼロ四元数、古い応答の破棄。別のレンダラーは増やさず `three-host` を使う。 |
| ⑤-14 足IK・接地 | `index.html` の `foot-qa`、`foot_qa_ui.js`、`POST /api/qa/{foot-contact,bvh-foot-world,dual-foot-preview}` | 右「足IK」の既存タブ | 診断結果のみ。BVHは2MBまで、strideは1〜1000。床高さは数値入力でスライダー外も指定できる。モデルへのIK適用はしない。 |

## データと表示

- ⑤-11 のリクエストは `{source,target,fps:30,coordinate_convention_confirmed:true}`。結果から品質・フレーム数・ボーン数・候補数・警告数と警告先頭15件を表示し、`BAI_retarget_review_unverified.json` をブラウザー内でダウンロードする。元・対象を変えたら候補を破棄する。
- ⑤-12 のリクエストも同じ選択と同意を使う。結果の `keys` を GLTFParser のノード数に対して検査する。対象の登録済みファイルを `/api/integrated-v02/asset/<filename>` から取得して2回解析し、高さ1.9、足Y=0、X=±1.1に置く。右のノード回転を各フレームで基準に戻して候補を適用する。同じノードに複数あれば最初の1件だけ使う。フレーム再生は5/10/15 FPSで表示専用。
- ⑤-14 の既定サンプルは旧画面の左4点と `foot_qa_ui.js` の右4点。3種類の結果はJSONをそのまま表示する。BVHはローカルファイルの本文だけを診断APIへ送り、素材登録やVMD保存はしない。

## 実装・検証の順序

1. ⑤-11 を既存 `retargetPanel` へ追加し、同意なしのHTTP 0回、結果、検証JSONのダウンロードをChromeで確認。
2. ⑤-12 を同じ `retargetViewport` と `three-host` に追加し、品質ゲート・不正キー・古い要求・対象変更・フレーム比較・破棄を確認。
3. ⑤-14 の専用featureを既存足IKタブへ結線し、3 API、入力上限、誤入力、モデル非変更を確認。
4. `screens.js` の実装済み表示とEvidence、マトリクスを同期し、型・全Node・Python・Evidence・E2Eを通す。

独立の高性能モデルによるWP05b/c/e/fレビューと、実利用者のモデル・GPU実機は別途未確認として残す。既存APIのGET→POST間の競合制限K12も変更しない。
