## 実装契約

1. SCR-10 の実操作としてモデル（登録 PMX）、ダンス（アニメーション入り GLB）、曲（登録 WAV/MP3）を選択する。SCR-08 の選択素材から SCR-10 へ渡す導線も置く。音源デコード後に実波形を描く。
2. 音楽・ダンスの配置を 30 fps の整数フレームで持つ。各ブロックに開始フレームと素材内の頭出しフレームを保存する。選択ブロックの開始位置を ±1F、再生ヘッドを ±1F で動かせる。元素材のデータは動かさない。
3. 一つの `AudioContext.currentTime` を再生時刻の正本とし、音声は `AudioBufferSourceNode` を指定時刻・頭出し位置で再生成する。3D 姿勢は同じ時刻から毎フレーム評価する。停止・シーク・配置変更時は古い音声ノードを止める。
4. GLB の元の基準姿勢とその時刻の世界回転差を、PMX の対応する骨の基準姿勢へ写す。上半身・頭・腕・脚など対応できる主要骨のみ。GLB の Hips 移動は PMX センターへ身長比で写す。顔・装飾の weights は変更しない。
5. `data/music_dance_project.json` に登録 ID・整数フレームの配置だけを原子的に保存する。`GET/POST /api/music-dance/project` は revision/If-Match で外部更新を検知する。破損 JSON は黙って初期化せずエラーを表示する。素材欠損時は配置を保持して明示する。
6. Owner が曲を指定し、実ファイルは教示パスの下の `15-3rdシングル LAST CHASE/` に見つかった。元WAVの hash を確認して既存の素材APIで登録済み。短い CC0 見本でも機能試験し、実曲の先頭・中間・末尾を追加確認する。GPU・Linux・標準 MCP は別の未検証項目として残す。

## 段階別の現状

- 保存契約・API: `music_dance_project.py` と `GET/POST /api/music-dance/project`。整数フレームの検証、revision/If-Match、前版バックアップ、破損時の拒否。`tests/test_music_dance_project.py` の2件が成功。
- SCR-10: PMX、アニメーション入り GLB、登録 WAV/MP3 を選び、実波形と2トラックを表示。同じ `AudioContext` 時刻から音声と3D姿勢を評価し、再生位置・各ブロック開始・素材頭出しを1F単位で調整する。SCR-08 の素材詳細から該当素材を渡せる。配置は保存・再読込で復元する。`tests/studio-music-dance-clock.test.mjs` 2件、`tests/studio-music-dance.test.cjs` 2件が成功。
- 実素材: 上記 PMX/GLB/WAV を隔離サーバーに読み込ませ、波形生成・骨59本の対応・剛体63個とジョイント99個の起動・10秒位置の実描画・切替時の解放を確認。実曲の先頭・約133秒・約273秒の音声位置表示と配置の保存再読込も確認した。元ファイル3点の SHA-256 は前後で一致。実曲は一時データ側へ登録し、制作データの配置は書き換えていない。WebGL は Chrome SwiftShader で、実 GPU/Linux は未検証。
- GLB にある頭・首・両手指・両足・つま先の回転トラックを対応するPMX骨へ写す。PMXの脚頂点を駆動する D/EX 骨も同期し、膝と靴が元の動きに追従する。GLBの非ルート位置トラックは全て定位置で、腰だけが移動する。骨長と形状が違うため、手先・足先の絶対位置は完全には一致しない。GLB に表情モーフのトラックが無く、顔の表情再生はこの素材からはできない。
- PMXに既存の衣装裾・髪・耳・尾・狐面紐/鈴の剛体があることを確認し、three.js r160 の `MMDPhysics`/Ammo でプレビュー時だけ計算する。縮小表示中の各ステップ後に世界行列を更新しないと衣装骨が約12.5倍の位置へ飛ぶ不良を実画像で発見・修正した。10秒位置の物理あり/なしを並べ、衣装が元の形を保ちながら変位することを確認。物理の動きがMMD本体と完全一致するか、貫通がないかは未検証。

## 受け入れの観測

- PMX/GLB の原本 hash は前後で同一。実3Dで異なる時点の姿勢が変わる。
- 曲と踊りの開始位置を別々に ±1F し、波形ブロック/ダンスブロックと出音/姿勢がそのフレームに追従する。
- 再生、停止、途中シーク、再開、画面再読込、保存復元、欠損素材、revision 競合を確認する。
- 自動試験は合成素材でフレーム写像と API を確かめ、Owner 実データで見た目と動作を確認する。実 GPU の確認と Owner 採用は別記録とする。
