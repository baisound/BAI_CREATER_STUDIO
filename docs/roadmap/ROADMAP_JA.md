# 推奨開発順序と依存関係

## あなたの用途からみた優先度

- MMD/PMXへの実用VMD変換とダンスMV制作を最優先する。
- Codexのクレジットが切れても手動で作業できる設計を最初に確立する。
- モーション変換→個別振付・フォーメーション→歌唱・カメラ→動画出力で早く成果を得る。
- クリティカルな品質検査は最終フェーズに集約せず各段階に導入する。

## 依存関係の注意

- 動画出力とJIZURAは早期に入出力形式を固め、3D表現統合は後続とする。
- カメラVMDのF値/焦点距離は標準VMDにそのまま保存できない。拡張JSON必須。
- Ray-MMD/MMEのFXはそのままブラウザで動かない。プレビュー近似とMMDへの設定出力を分ける。
- PMXリターゲット・IK・物理ベイクは別物。自動変換成功と動作の自然さを分離して検証。
- WebMCPと標準MCPを共通APIに収束させ、外部変更の競合・権限制御を必須化。

## 2026-10-18追加決定 — Phase E カメラ・フォーカス/被写界深度テスト

- 優先順位は **B残件を維持しつつ E → F → リップシンク/表情/MMDエフェクト → C → D → G → H** を継続。
- `E-FOCUS-01`: 被写体指定部位と焦点面の距離差、推定DOF近点・遠点、手前ボケ/厳密合焦近傍/許容範囲/奥ボケ/判定不能を色＋文字で提示。Scene Viewに焦点面ガイド、Camera Viewに対応プレビュー。モデルの時間同期が前提。
- `E-FOCUS-02`: 全フレーム/指定区間のフォーカス逸脱診断、タイムライン警告、CSV/JSON出力、UI・共通API・WebMCP・標準MCP対応。
- `F-DOF-01`: 実レンダラー接続後の被写界深度プレビューと深度/ボケ差分比較、出力画質確認。計算上のDOFと実映像の合焦を区別する。
- ドラッグ操作とテストモードの切替では撮影キーを書き換えない。「対象にピントを合わせる」はプレビュー→確定時の1キー更新とする。
- 詳細設計: [カメラ・フォーカス/被写界深度テストモード設計](../camera/BAI_CAMERA_FOCUS_DOF_TEST_MODE_DESIGN_V1_JA.md)
