# BAI Camera 操作設計 v1.0（承認済み・設計のみ）

決定日: 2026-10-18。適用対象: BAI Creator Studio / BAI Camera Phase E。実装状態: **未実装**（既存v0.16.47動作と混同しない）。

## 1. 確定した設計決定

- 自由視点（Scene View）: **Unreal Engine方式**を標準にする。
- キー登録: **操作確定時に登録**。明示的な「自動キー」切替を備える。
- 画面構成: **自由視点（Scene View）＋撮影画面（Camera View）2画面**。最大化・横幅変更可能。
- Phase Bの残課題を阻害要件とせず、EとFを優先。E/F完了後はリップシンク・表情・MMDエフェクトを前倒しし、C・D・G・Hへ。
- モデルを表示できない場合は「被写体未読み込み」と明示し、空の画面でカメラを操作させない。対象モデルのロード・描画経路を統合するまで実機完成とはしない。

## 2. ビューポート

| 要素 | 自由視点 Scene View | 撮影画面 Camera View |
|---|---|---|
| 表示 | 被写体の実メッシュ、骨、カメラギズモ、カメラ軌跡、注視点、床グリッド | 実際のレンズ/FOV、構図、セーフフレーム、被写体、DOFプレビュー |
| 操作対象 | 編集用ビュー。撮影キーを変更しない | 選択中の撮影カメラ |
| 同期 | 共通シーン時刻、被写体ポーズ、選択対象 | 同左。撮影キーによりレンダリング |
| 未読込時 | 原因と「モデルを読み込む」導線 | 原因と「被写体を選ぶ」導線 |

初期状態で両画面を表示。片側最大化を可能にする。FPS/フレーム数/現在フレームは共通タイムラインを正本にする。画面幅が狭いときは上下配置。固定ヘッダーと各ペイン内部スクロールにより右側パネルを押しつぶさない。

## 3. カメラ用語と軸（命名互換性）

- **Pan（パン）**: カメラ位置を変えず左右に回転（ヨー）。
- **Tilt（ティルト）**: カメラ位置を変えず上下に回転（ピッチ）。
- **Dolly（ドリー）**: カメラの向きに沿って前後に平行移動。焦点距離は変更しない。
- **Truck / Track（トラック）**: カメラローカル右方向に平行移動。
- **Crane / Pedestal（クレーン/ペデスタル）**: 上下方向にカメラを平行移動。クレーンリグの支点回転とは別。
- **Orbit（オービット）**: 指定ピボットを中心に周回。被写体注視はオプション（初期ON）。
- **Roll（ロール）**: 光軸周りに回転。
- **Zoom（ズーム）**: カメラ位置を変えず焦点距離を変更。
- **Focus（フォーカス）**: フォーカス対象／距離を変更。ズームとは独立。
- **Rail（レール）**: スプライン上の位置パラメータを編集。
- **Jib / Crane Arm（クレーンアーム）**: 支点・アーム長・角度を編集。

**互換性注意**: v0.16.44 の `pan` は「左右平行移動」の意味。旧 `pan` は保存データとAPI上、過去の挙動を維持し、新規APIでは `truck` と `pan_yaw` を区別。既存保存済みキーの位置/姿勢の数値は書き換えない。UIラベルの変更時には旧呼称を説明し、schema移行はversionedな明示変換で行う。

## 4. キーボード・マウス割当（初期値）

ポインタが該当ビューポート上にあり、入力フィールドへフォーカスがない場合だけ適用。

| モード | 操作 | 入力 | 備考 |
|---|---|---|---|
| Scene View | 見回し | 右ドラッグ | 撮影キー変更なし |
| Scene View | 前進/後退/左右移動 | 右ボタン保持 + W/S/A/D | 速度設定・Shift加速 |
| Scene View | 上昇/下降 | 右ボタン保持 + E/Q | UE系フライト移動 |
| Scene View | フォーカス | F | 選択被写体のバウンディングボックスを対象 |
| Scene View | オービット | Alt+左ドラッグ | 選択中心。撮影キー変更なし |
| Camera View | パン/ティルト | 左ドラッグ横/縦 | 撮影カメラ姿勢を変更 |
| Camera View | オービット | Alt+左ドラッグ | 注視ピボット中心 |
| Camera View | トラック/クレーン平行移動 | 中ドラッグ横/縦 | カメラローカル水平/シーン上方向。選択可 |
| Camera View | ドリー | ホイール上下 / W/S | 入力フォーカス時は無効 |
| Camera View | トラック | A/D | 撮影カメラ移動 |
| Camera View | クレーン上下 | E/Q | ワールド上方向 |
| Camera View | ロール | R+ドラッグ | キー修飾中のみ有効 |
| Camera View | ズーム | Z+ドラッグ | 焦点距離。ホイールドリーと区別 |
| Camera View | フォーカス | 対象を選択→フォーカスコマンド | クリック単独で既存キーを変更しない |
| Rail編集 | スプライン/ハンドルをドラッグ | UIギズモ | レール開始/終端・接線・速度を編集 |
| Craneリグ編集 | 支点/アームをドラッグ | UIギズモ | アーム長と角度を編集 |

ショートカットは設定UIで変更可能。カメラViewでドラッグ開始時は操作名をオンスクリーン表示、押している修飾キーと作用軸を明示。右クリックは視点操作で使用するため、コンテキストメニューは専用メニューボタンも用意。

## 5. 編集トランザクション・キー登録

1. `pointerdown`/ショートカット操作開始時にスナップショット取得（変更前カメラ値＋対象キー＋フレーム＋選択状態）。
2. 操作中はドラフト姿勢をプレビュー。自動キーOFFでは保存済みキーデータへ書き込まない。操作の累積量は1操作として計算する。
3. 正常な `pointerup`/入力確定で、編集された値がある場合だけ現在フレームへ**1キー**作成または同位置の既存キーを更新し、Undoを1件積む（デフォルト）。`Esc`でキャンセル。
4. 自動キーONでは編集状態を視覚表示するが、同じドラッグでフレームが進まない限りキーを大量作成しない。再生中のライブ記録は別モード（初期OFF）として扱い、サンプリング間隔と間引きを指定する。
5. 入力操作の途中でタイムラインフレームが移動した場合は、現在操作を確定/破棄するガードを設ける。曖昧な状態で別フレームへ書き込まない。
6. 表示モード切替、被写体選択、Scene View移動では撮影キーを作成しない。
7. 同じフレームを指定して追加する場合は「既存キーを更新」と明示する。隣接キーの誤選択を避けるためフレーム番号直接入力、ズーム、キー一覧からの数値編集を提供。

Undo/Redo は操作単位とし、MCPを含む編集のトランザクションID、version/etagを記録。外部更新との衝突時は古い書き込みで上書きしない。

## 6. セグメント補間・移動プリセット

**優先順位**: 隣接するキーフレーム間の **補間カーブ → カメラ移動プリセット**。曲線が未指定なら **Linear**。プリセットのデフォルト補間を明示的に適用する操作以外は、既存の補間指定を勝手に変更しない。

カーブ: Linear / Ease In / Ease Out / Ease In-Out / Bezier / Hold / Custom。位置、回転、焦点距離、F値、フォーカス距離の各トラックは独立制御。静的カットはHoldまたはCutを使用。Orbitは「中心点+半径+方位/仰角」、Railは「経路+経路パラメータ」、Crane Rigは「支点+長さ+姿勢」を時間に沿って補間し、単純なワールドXYZ線形補間による経路崩れを避ける。各区間の始点/終点フレーム、ease、およびプリセットIDを保持。

組み込みプリセット候補: 直進ドリー、ドリーアウト、左右トラック、上昇クレーン、半周/一周オービット、被写体追従、顔アップ、顔固定回転、レール追尾、弧状ジブ、スロープッシュイン、ウィップパン、静止ショット、ハンドヘルド揺れ（安全な強度上限）。カスタム操作は速度・軸・中心・パス・回転・補間・制限値を名前付き登録/編集/複製/削除可能。

## 7. 被写体、レンズ、DOF

被写体をモデル一覧から選択し、全身・胸・顔などのボーン/マーカー、またはメッシュの任意点を注視中心に指定できる。ボーン未解決時はバウンディングボックス中心へフォールバックし警告する。カメラ位置と狙い先は独立。追従は位置追従・回転追従を個別ON/OFF、滑らかさ設定あり。

焦点距離の例: 24/35/50/80/85/135mm。UIプリセットに構図ラベルを付与（広角・引き、標準、ポートレート、顔アップ）。F値の例: f/1.4, f/2, f/2.8, f/4, f/5.6, f/8, f/11。組合せプリセットも登録可能。センサー寸法、FOV計算、焦点距離、DOFの距離・強さは独立保存。VMDが標準保持できない追加のレンズ情報はsidecar JSONとして保持し、VMD往復で損失を検出する。

## 8. 共通データ/API/MCP設計（提案、未実装）

- 共通モデル案: `CameraRig`, `CameraPose`, `CameraLens`, `CameraTarget`, `CameraKey`, `CameraSegment`, `CameraPreset`, `ViewportState`, `EditTransaction`。
- プロジェクト保存時はschema versionと移行関数を明示。旧VMD/旧camera JSONは読み取り互換、元ファイルは不変。2画面のレイアウト設定は撮影モーション情報から分離保存。
- API案: `camera.get_state`, `camera.list_targets`, `camera.select_target`, `camera.set_operation_mode`, `camera.preview_operation`, `camera.commit_operation`, `camera.cancel_operation`, `camera.set_key`, `camera.set_segment_curve`, `camera.apply_preset`, `camera.manage_preset`, `camera.set_lens`, `camera.undo`, `camera.redo`。
- UI、WebMCP、標準MCPはいずれも同じアプリケーションサービス・バリデータへ接続。プレビュー操作と確定操作は分離し、プレビューを呼ぶだけでキー登録を行わない。安全な範囲・操作対象ID・現在フレーム・バージョンを必須チェック。
- ネイティブブラウザDOM以外の3Dエンジン、モデルローダーは既存資産と照合して採用。実モデル表示とポーズ同期の確認までは描画機能を完了扱いにしない。
