# BAI Creator Studio v0.5 UI全面刷新 — Git分岐・納品規約

## ブランチ系統
- `main`：元の統合ソース。UI全面刷新の試行で書き換えない。
- `feature/v05-workflow-integration`：第1段階の既存UI併存・導線追加（コミット `f0fbffe`）。変更禁止の基準点。
- `feature/v05-ui-overhaul-02`：第2段階以降のUI全面刷新専用ブランチ。本ブランチ上で作業し、完了単位ごとにコミット。
- 第3段階以降は `feature/v05-ui-overhaul-03` のように直前の枝番から派生させる。元の `main` を直接変更しない。

## 既存未コミット差分
元のアーカイブに多数の未コミット変更が含まれる。これらを削除・まとめてコミット・強制リセットしない。
各段階では変更対象だけ明示してステージし、変更を段階ごとにコミットする。

## 納品物
- 毎段階のZIPには `.git/` 全体、作業ツリー、検証記録を含める。
- ZIP内 `.git/HEAD`、`refs`、objects、config を残し、展開後 `git status` と `git log` が動作することを検証。
- 既存Git設定やoriginは含まれる可能性がある。プッシュはユーザーの明示指示なしに実行しない。
- 自動生成大容量の node_modules、キャッシュ、ビルド出力等は別途注記して除外可能だが、今回は原本作業ツリー内でそれらが存在する場合に原則維持する。

## 実装の完了基準
各作業単位で UI、API、標準MCP、WebMCP、ドキュメント、テストの対応を確認。未完了や未検証は完了と表記しない。
